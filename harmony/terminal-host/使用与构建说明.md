# 鸿蒙原生终端宿主源码

这是已安装调试应用 `com.codex.emulatorhnp` 的可维护源码。应用只声明 `ohos.permission.INTERNET`，通过官方 private HNP 安装并执行原样签名的 Codex ELF。本目录不含接口地址、密钥、证书私钥或编译产物。

当前调试契约固定 UID `20020059`、运行根 `/data/storage/el2/base/files/r`。它适用于本次已核验的鸿蒙 7 模拟器应用；重新安装到其他设备后，必须重新核验应用 UID 和目录归属，不能把此包当作通用真机安装包。

## 构建

需要 DevEco Studio 26.0.0 及其完整 SDK、Node、Hvigor、OHPM、HNP 工具和 Java。`--distribution` 指向已经签名的 `hnp-debug` Codex 发行目录，不能使用 HiShell 或 HDC 专用包。

```sh
# 在仓库根目录执行；按本机情况修改发行目录和 DevEco 安装位置。
python3 harmony/terminal-host/build_terminal_host.py \
  --distribution '/外置盘/releases/日期时间/鸿蒙Codex' \
  --deveco '/应用位置/DevEco-Studio.app' \
  --output '/外置盘/build/codex-terminal-新目录'
```

输出目录必须是新目录。脚本把源码、依赖缓存和所有编译产物放在那里，使用 SDK 自带工具和本地 NAPI 类型依赖，不运行 npm 安装脚本。

打包前会核对原发行目录的完整 SHA-256 清单、8 个 ELF 的原构建记录和包元数据；缺项、旧文件、被替换文件、符号链接或路径越界都会被拒绝。复制后再次按原摘要核对。该清单用于完整性检查，不能替代发行来源的真实性判断。

输出包括 `codex-harmony-terminal-debug.hap`、同名 `.sha256`、`build-manifest.json` 和构建日志。HAP 使用模拟器允许的普通未签名调试安装流程；其内 ELF 保留发行包原有签名。此过程没有申请系统应用身份，不等于获得商业真机发行证书。

HAP 版本、宿主源码逐文件摘要、Codex 版本、Rust 源码 SHA、HNP 版本及运行文件摘要分别记录在构建清单中。HNP 版本带 Rust 源码 SHA，避免同名安装目录缓存旧二进制。

## 配置和入口

配置通过应用私有目录单独导入，不放进 HAP。安装、导入和采集脱敏日志使用仓库内 [应用管理脚本](../../docs/鸿蒙电脑模拟器/manage-harmony-app.py)，操作说明见 [模拟器文档目录](../../docs/鸿蒙电脑模拟器)。

桌面名称是“Codex 鸿蒙原生终端”。点击“启动 Codex”才创建交互子进程；模型固定 `gpt-5.6-terra`，初始 `read-only`、`on-request`。关闭页面或点击停止会回收自身子进程。网页只加载包内 xterm 资源，禁止外部导航和网页文件访问，不读取配置内容，不把终端输出写进网页日志。

当前模拟器缺少 bubblewrap 所需的 user namespace 能力；原生终端和联网成功不代表受限工具已经可用。宿主不会自动切换完全权限。

## 本机验证

```sh
# 验证私有配置导入、原子替换、权限和链接拒绝；只用假密钥。
python3 harmony/terminal-host/test_secure_config.py

# 使用本机 Node 验证前端输入上限、输出背压和桥接边界。
node harmony/terminal-host/test_terminal_bridge.cjs

# 用临时假发行目录验证旧二进制、篡改、缺项和不安全路径会被拒绝。
python3 harmony/terminal-host/test_prepare_codex_hnp.py
```

`tools` 调试动作只在新建的应用私有工作区内测试 `rg` 和 `apply_patch`，使用独立空 HOME/CODEX_HOME；不读取真实配置。`verify-install` 只导出固定的公开安装文件供主机比对摘要，导出副本不会执行。
