## 项目目标

在商业鸿蒙 PC 的原生终端执行 `codex`，能够登录、访问本机项目、修改代码、执行本机开发命令、取消任务和恢复会话。客户端及工具运行在本机，模型请求仍访问模型服务。

实施方式为：适配 Codex CLI 源码与依赖，使用匹配的 Rust 目标及 SDK 交叉编译，签名并组成原生包，配置后由鸿蒙终端启动。首个候选架构为 ARM64，构建使用 SDK 6.1.1.125 / API 24；具体型号、系统与最低兼容 API 尚未验证。Linux 子系统、虚拟机、容器及远程执行替代方案均不在范围内。

已生成标记为“未真机验证”的原生候选包，具体版本、文件位置和摘要见[实施记录](实施进展与构建记录.md)。安装脚本已做 Mac 文件操作验证；用户启动截图是新增反馈，尚不能代替产物身份核对和完整真机验收。

## 建议阅读顺序

1. 先阅读“适配范围与源码清单”，确认首版功能及工作范围。
2. 按专题查看源码证据、拟议改动和验收条件。
3. 阅读“安装配置与运行指南”，检查最终用户体验是否符合目标。
4. 最后按“实施计划与任务拆分”开展实施。

## 没有鸿蒙 PC 时的推进方式

源码分支、依赖收敛、交叉编译、签名、ELF 检查和宿主侧定向验证已完成，产物统一标记为“候选构建，未真机验证”。这些工作不能证明商业系统的签名接受条件、PTY、沙箱或实际运行效果。

真机工作保留独立任务，待有授权测试设备或测试参与者时执行。无法真机验证时，项目可达到“候选构建完成”，不能把“原生适配通过”标记为完成；也不改用用户排除的运行路线。

## 全文使用的状态与约定

| 标记 | 含义 |
| --- | --- |
| 已有证据 | 当前源码或已核对的官方资料可以支持该判断 |
| 拟议适配 | 设计选择，尚未写入产品代码 |
| 待构建验证 | 需要实际目标编译、链接及产物检查 |
| 待真机验证 | 需要商业鸿蒙 PC 上的实际结果 |
| 首版暂缓 | 不进入首个功能交付，但相关编译依赖仍要处理 |

“阻断项”表示会阻止启动或核心编码任务；“必要项”表示交付前必须处理；“后续项”表示允许在能力清单中明确暂缓。专题中的源码入口是排查起点，不意味着每个文件都需要改动。

新增说明文件使用中文文件名和正文。代码文件统一使用英文文件名，包括 Shell、Python、Rust 及可执行脚本入口；中文文件名只用于文档。命令、协议字段、配置键、包布局及已有源码标识保留原名。示例是否实际执行，以实施记录及对应测试报告为准；示例路径必须在实施时替换并验证。
