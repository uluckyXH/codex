## 方案与字段

- 每个 Native worker 仍只执行一个查询。成功加载的库持有到进程结束，取消主动 dlclose，包括缺符号分支。查询前后的阶段为 `native-context-call`、`native-context-returned`；加载后的 JSON 说明 `library_lifetime=retained_until_worker_exit`。
- worker 显式检查已有写入错误、fflush 和 fclose。`worker-result-flushed errno=N`、`worker-result-closed errno=N` 是对应操作结束后的记录；错误导致非零退出。Native worker 在 `native-worker-_Exit code=N` 后显式收尾 stderr，再调用 `_Exit`，不进入普通退出析构。stdout 是 supervisor 为 worker 打开的 `/dev/null`，结果使用专用 FD 3。
- supervisor 的调用信号、超时、截断和原始等待状态保留；没有信号恢复、成功替换或失败根目录回退。
- 默认观察优先加入编译宏 `CODEX_OHOS_RUNTIME_BASE` 下的 `c{实际EUID:08x}/a` 和 `/s`，使用 `geteuid()`，不运行 id、不读环境中的同名变量、不写目录。缺宏时保留旧候选；显式 `--path` 仍完全替换默认候选，最多 12 条。超长或非法宏不会变成截断路径。
- 新增 `path_selection`：`mode`、`selected_count`、`limit`、`runtime_paths`。最后一项可能是 `selected`、`not_configured`、`explicit_paths_override`、`invalid_base` 或 `path_too_long`，属于候选采集信息，不授予运行根批准。
- `mountinfo.selection=covering_candidate_path`、`complete_mount_table=false` 明确这是覆盖候选路径的筛选视图；`entry_limit=8`、`input_byte_limit=1048576` 和原 `truncated` 字段保留限额。未截断也不等于完整挂载表。完整表诊断由另一会话处理。

## 接口依据与验证计划

[`_Exit` / `_exit` 文档](https://man7.org/linux/man-pages/man2/_exit.2.html)说明此类退出不执行 atexit 且不自动刷新 stdio，因此需要显式收尾结果流。[dlopen/dlclose 文档](https://man7.org/linux/man-pages/man3/dlopen.3.html)说明卸载可能运行析构。这些接口资料不证明商业鸿蒙库的实际故障位置；Mac 危险析构和 atexit 夹具也只验证本次退出流程。

用真实动态库分别设置危险 destructor 和 atexit：独立控制加载器必须先真实触发信号，证明夹具有作用；生产 worker 应完整采集并跳过钩子。再验证原调用信号、超时、输出失败和截断保持失败；编译契约 EUID 路径只读且有边界；筛选挂载视图不冒充全表；其余目录安全与清理回归保留。
