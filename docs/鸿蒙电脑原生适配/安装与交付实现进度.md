## 集成接口约束

新默认数据布局目标为经过验证的平台 `filesDir/codex/{state,r,tmp,logs}`；项目目录保持调用者 cwd 或 `--cd`。安装器只安装程序并生成 PATH 环境入口，不读取/写入用户认证配置、不建立固定应用 UID、不替 CLI 选择未验证的数据根。

编译参数、运行目录来源、初始化与只读诊断命令以目录会话的新实现契约为准。未形成契约的步骤标明“待集成”；旧包说明保留其历史版本边界，不将新设计标为已通过。

分发接口改为：`--runtime-profile platform` 为默认，不传 `--runtime-base`，移除 `--runtime-uid` 和 `hnp-debug`；保留显式 `strict`、`hdc-debug` 诊断构建。为 HNP 制作完整包时加独立 `--with-hnp-alias`，只允许与 `platform` 配合，不绑定应用 UID。同一签名原生包可由终端会话用于两个实际身份的 HAP。主会话的构建命令和终端打包验证需据此更新。

通用包独立 C 探针定义 `CODEX_OHOS_PLATFORM_DATA`，不再定义旧 `CODEX_OHOS_RUNTIME_BASE`，避免继续把 `base/cUID/{a,s}` 报为新布局；它仍是另一个进程的只读候选与 Context 观察，不是 CLI 初始化或目录批准。CLI 提供离线 `codex doctor --initialize-data-directories [--json]`，明确初始化并打印成功路径；新文档从 `state=…`、`logs=…` 获取位置，不以 `--version` 或能力诊断代替初始化。

首次实际 CLI 启动负责初始化；安装器不执行 CLI。文档会区分安装文件前缀、受保护数据根和项目 cwd，且不要求 HiShell 用户手建或猜测应用私有目录。初始平台 files 为 0777 或缺少可信根时应保留失败，不通过安装器 chmod 整个 HOME 或父目录。
