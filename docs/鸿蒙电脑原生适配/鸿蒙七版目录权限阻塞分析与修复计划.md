## 三、官方资料支持的范围

1. 华为说明应用私有文件与用户文件属于不同范围，应用路径是权限与挂载隔离后的视图，应通过 Context 获取。它支持“优先考察应用私有目录”的设计，但没有保证 HiShell 启动的独立 Rust ELF 具有应用上下文，也没有给出本机 HOME 的 UID 规则。[应用沙箱目录（官方 V5 文档）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/app-sandbox-directory-V5)
2. 当前安装的 Native SDK `6.1.1.125 / API 24` 中，`AbilityKit/ability_runtime/application_context.h` 提供 `OH_AbilityRuntime_ApplicationContextGetCacheDir`（API 13）、`GetFilesDir` 和 `GetTempDir`（API 16）。`ability_runtime_common.h` 定义 `CONTEXT_NOT_EXIST = 16000011`。这是已核对的本地 SDK 声明，不代表独立 CLI 调用已经成功；网页接口页抓取失败，不据搜索摘要补写运行保证。
3. `OH_Environment_GetUserDownloadDir` 等 Native 接口返回公共文件目录，不能拿它们替代私有运行根。[华为 oh_environment.h](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/api/capi-oh-environment-h)
4. 华为明确终端不能修改 `/storage/Users/currentUser/appdata` 内的应用数据和权限；该路径不能作为默认可写修复目录，也不安排 `chown` 整个 HOME。[终端无法修改应用文件权限或应用内数据](https://consumer.huawei.com/cn/support/content/zh-cn16051022/)
5. 华为对 HarmonyOS 7.0/6.1/6.0 的终端说明明确提示 `/dev/shm` 为多用户共享目录。其存在不能证明私密或可执行；命令手册也不能替代实际设备的命令可用性检查。[鸿蒙电脑终端命令合集](https://consumer.huawei.com/cn/support/content/zh-cn16083991/)
6. 上游 Codex 的 Linux 沙箱还依赖内核隔离能力，包内 bwrap 的版本输出不能证明这些能力通过。此资料描述官方支持平台，不能作为商业鸿蒙内核支持性的承诺。[OpenAI 沙箱说明](https://learn.chatgpt.com/docs/sandboxing)

以上均在本轮查阅。V5 应用目录文档及 API 声明用于设计线索，商业鸿蒙 PC 7.0 的行为仍以本机探针和隔离复测为准；不使用 Linux 子系统、OpenHarmony 模拟器或社区其他机器的结果替代验收。

## 四、拟采用的受保护目录方案

### 4.1 先确定目录来源，再改变生产路径

首选平台提供的应用私有文件目录。通过 Native API 查询并验证；不能仅因函数存在就认为调用成功。API 没有上下文、库不可用或返回路径不符合安全要求时，记录实际原因，不自动回落到公共 HOME。

| 候选来源 | 用途与接受条件 | 本轮状态 |
| --- | --- | --- |
| 平台应用 `filesDir` | 优先用于稳定运行根；必须确认独立 Codex 和相关子进程能访问同一目录，且目录归属、祖先、挂载与生命周期可信 | API 已核对，设备调用及权限未验证 |
| 平台应用 `cacheDir` / `tempDir` | 仅考虑可重建的运行数据；必须验证清理时机、活跃 socket/锁/aliases 的生命周期，不能存放认证或唯一会话数据 | 候选，不能按名字推定安全 |
| HiShell 可见的应用沙箱路径，如 `/data/storage/el2/base/files`、`/data/storage/el2/base/cache` | 仅列入有界探针的候选；与平台来源、命名空间及实际元数据交叉验证，不能把示例路径直接写成保证可用的常量 | 待探测，不是安装命令 |
| `/dev/shm` 中的专用运行子目录 | 仅作为后备研究：父目录确实为受信任所有者且具备有效 sticky 保护，叶目录归当前有效 UID、严格 0700，并通过跨主体访问与沙箱隔离验证；不放配置、密钥或项目内容 | 官方说明为共享区，默认不启用此方案 |
| 公共 HOME、`.codex`、HOME 下普通 `tmp`、`appdata` | 保留用户现有数据和配置；不以它们作为已证明安全的控制 socket/别名根 | 已知 HOME/.codex 不满足当前安全条件 |

`HOME`、`TMPDIR`、`CODEX_HOME`、`XDG_*` 可以作为诊断信息，但受限命令传来的变量不得决定 privileged socket 根。环境中给出一个可写路径，也不能替代验证。

如果探针证明所有原生 CLI 候选均不满足要求，明确保留阻塞，再评估受支持的原生应用宿主向 CLI 提供私有目录的方案。该分支涉及启动方式和交付形式变化，应另行形成设计，不能凭空声称改两行路径即可完成。

### 4.2 目录结构与跨进程一致性

统一安全目录校验接口，区分 aliases、普通临时数据和控制 socket 的访问规则；它们不必使用同一个物理父目录。**aliases 必须能被允许的工具读取、执行；控制 socket、启动锁和定位元数据必须对受限工具隐藏。** 若共用父根，使用独立子目录，不能为恢复 aliases 而把整个运行根重新开放，也不能把它们一概屏蔽后令 aliases 再次失效。

同一可信应用/用户命名空间中的 CLI、app-server、sandbox 及文件 helper 必须解析到一致的受保护根，不随项目、`CODEX_HOME`、工具环境或启动先后变化。不能用每次随机选择不同父根代替共享 socket 设计；会话 aliases 可以在固定根内使用随机叶目录。

在改动前写出并测试：根如何可信发现、无应用上下文的 helper 如何获得同一身份、环境变更是否能造成不同遮蔽范围。若采用继承目录描述符，需要可信的启动链、显式描述符清单和身份复核，并在执行模型控制的命令前关闭这些特权描述符；单纯传一个路径字符串不构成可信交接。

候选探测可以检查多个位置，生产 socket 根不能由各进程分别执行“files → cache → 共享临时目录”的回退链。Context 暂时失败或根被系统清理时，不得自动建立第二个 socket 根；主进程有上下文而 helper 没有时，应使用经过验证的同一根或拒绝。相同路径字符串也不足以证明同一对象，mount ID 只在相应命名空间内解释，不能跨命名空间直接比较为全局身份。

同机不同版本、不同安装位置和不同 `CODEX_HOME` 的 daemon 也要纳入；新旧 socket 根和公开定位入口不能留在沙箱可见范围。优先迁移到单一确定的根；过渡期若保留多个根，必须有一致的完整遮蔽集合。还要反向验证旧沙箱是否能访问新 daemon：只改新版遮蔽集合无法修复已经运行的旧沙箱。不能证明双向隔离时，升级说明必须要求退出旧实例及其受限子进程，明确不支持新旧并行；只停止旧 daemon 不够，不自动杀掉用户进程。

### 4.3 安全条件保留并补齐

- 目录路径、每级祖先、符号链接、真实目录身份及可见挂载别名都要验证。公共可写父目录下的 0700 子目录不能单靠叶权限过关；若依赖平台的额外隔离，必须有平台契约和对应设备负向证据。
- 使用受信任父目录描述符配合 `openat`、`mkdirat`、`O_NOFOLLOW`、`fstat` 等完成创建与复核，避免检查后再跟随可替换路径。返回并持有目录 guard/描述符，而不是校验后只返回一个没有生命周期约束的字符串。
- 叶目录要求当前有效 UID 和严格 0700；socket 为 0600。只允许规范化本次新建且已核对身份的对象，不能递归修改、接管或删除已有的 HOME、`.codex`、平台目录和陌生文件。
- setgid 继承、默认 ACL、强制访问控制、只读挂载、`noexec`、路径过长分别诊断；`mkdir(0700)` 成功后还要复核实际结果，不能假设存储层一定按请求保存所有者和权限。
- 共享 socket 根必须满足 `sockaddr_un.sun_path` 的实际字节预算。当前 basename 为 64 位十六进制摘要，还要计算分隔符和终止符；不能为解决过长路径直接截断摘要或放宽验证。
- 若后备方案涉及 `/dev/shm`，覆盖 bwrap 重建 `/dev`、重新绑定 `/dev/shm` 及其祖先后的效果；aliases 必须仍按最小范围可用，任何重新绑定都不能撤销 socket 屏蔽。
- 保留 bwrap 的可信摘要与已打开文件执行机制；aliases 指向安装包程序的安全性也要核对。签名、权限位和目录隔离是不同的检查。
- 找不到安全目录时给出候选来源、拒绝阶段、实际 UID/mode 和错误码，保持受限执行拒绝；不静默改成全盘权限、无沙箱、root 或 legacy 弱化模式。

本轮迁移的是运行设施。用户的 API/登录配置沿用，禁止自动搬运或重新生成凭据；同时不能把运行根修复宣传成已经审计了公共 `.codex` 中所有数据的保密性。

## 五、不依赖 id 的原生探针与专项日志

先扩展独立的 [harmony_probe.rs](../../scripts/harmony_probe.rs) 或等价的最小 Native 探针，再接入 [诊断.sh](../../scripts/harmony/诊断.sh)。独立探针不能依赖先成功初始化 arg0、daemon 或完整用户配置，否则会在采集前遇到同一阻塞。默认直接输出到 stdout，不以 HOME 下先建日志目录为前提；同时限制候选数量、单项耗时及总输出长度。现有探针只验证启动，以下能力均为待实现。

| 采集项 | 方法与边界 |
| --- | --- |
| 当前进程身份 | 直接调用 `getuid/geteuid/getgid/getegid/getgroups`；可选读取 `/proc/self/status` 中 UID/GID/Groups、NoNewPrivs、Seccomp 等限定字段；不执行 `id`、`whoami` 或完整 `env` |
| 目录状态 | 对有限候选及必要祖先执行 `lstat/openat/fstat/fstatfs/readlink`，输出类型、数值 UID/GID、完整八进制 mode、设备/inode、来源和错误码；不遍历用户目录内容 |
| 平台 API | 检查库/符号和返回码，区分路径不存在、接口不可用、无上下文及权限拒绝；不把这些全并成“不能写 HOME” |
| 创建与清理 | 默认只读；显式写入探测只在已通过基础验证的候选中创建随机测试目录/文件，写固定无敏感内容并读回；只清理本次持有的对象，不跟随链接、不 chmod/chown 原目录 |
| 存储和挂载 | 记录候选对应的 mountinfo/fdinfo 条目；不可读时保留未知状态。核对命名空间、目录映射及原生 socket bind 的真实结果 |
| 退出与阶段 | 每一步先标记阶段；可能被系统禁止的调用由独立子进程执行并设超时，父进程保留 exit code、signal、raw wait status、errno 和 stderr，避免一个探测失败抹掉全部证据 |

新增字段示意为 `runtime.source`、`runtime.candidate`、`runtime.stage`、`identity.euid`、`directory.uid`、`directory.mode`、`directory.dev/ino`。只记录路径元数据和错误，不记录 API Key、认证文件、配置正文、提示词或完整环境。诊断脚本的目录可写仅表示能保存报告，不代表它适合做受保护运行根。

文件 helper 的完整工具错误也要保留；有些失败只出现在工具结果里，不能只收集 `codex-tui.log`。每个 helper 记录自己的身份，不能假设父子进程 UID、命名空间和可见路径天然相同。

## 七、每项修复都必须覆盖的测试

| 层级 | 正向测试 | 必须保持拒绝的场景 |

Mac 模式/UID 夹具只是策略测试，不等于已做跨 UID 的真实对抗测试。真实权限、namespace/mount/seccomp、socket 隔离和 HiShell 行为只能在受支持的设备环境验收。所有测试使用无敏感固定数据，不做登录、凭据读写或模型请求测试。

目录恢复后若仍退出 159，按新增原始状态确认是显式退出还是信号，再定位具体阶段和 syscall；若文件写入失败，保留 helper 的独立错误链。不得因 alias 警告消失就一起关闭 HM-03。

## 八、新包交付要求

- 继续固定当前上游源码基线，不恢复官方更新检查、提醒或自动更新。
