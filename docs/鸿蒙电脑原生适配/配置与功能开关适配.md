# 配置与功能开关适配

状态：设计稿。覆盖适配23—24、适配31。目标是让简单的 `codex` 命令使用正确默认行为，同时保留上游配置兼容性。

## 配置来源

[配置加载说明](../../codex-rs/config/src/loader/README.md)定义用户、项目、命令行、管理和云端配置层；[配置结构](../../codex-rs/config/src/config_toml.rs)与[约束](../../codex-rs/config/src/config_requirements.rs)决定最终行为。

拟议保持现有层级和约束语义，不另建一套“鸿蒙专用配置格式”。默认用户文件仍为 `~/.codex/config.toml`；自定义 CODEX_HOME、项目配置和管理约束应按既有逻辑处理。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)

如果目标系统没有某个系统级配置路径，应定义一致的缺失或拒绝行为，不能绕过原有强制策略，也不能要求用户修改受保护的系统目录。

## 开关、构建和资源必须一致

| 层次 | 必须完成的适配 |
| --- | --- |
| Cargo 依赖 | 可选功能未支持时，不引入无法构建的目标依赖 |
| 功能注册 | 不向模型或用户提供无法执行的工具 |
| 配置默认值 | 默认只启用目标已经验证的能力 |
| 资源打包 | 所有启用能力都找到正确的辅助程序或资源 |
| 请求处理 | 用户显式启用不支持能力时提前报告原因 |
| 能力说明 | CLI 帮助、诊断与安装指南描述一致 |

例如设置 `code_mode = false` 不会自动让 V8 从依赖图中消失，也不会改变打包器是否构建宿主。文件凭据开关同样不会自动移除 Secret Service 条件依赖。

## 首版候选配置

以下键已存在于当前[配置 schema](../../codex-rs/core/config.schema.json)或[功能表](../../codex-rs/features/src/lib.rs)。这是首版裁剪方案的示例，实施时需结合最终依赖和模型能力确认。

```toml
cli_auth_credentials_store = "file"
mcp_oauth_credentials_store = "file"
approval_policy = "untrusted"
sandbox_mode = "read-only"
check_for_update_on_startup = false

[features]
code_mode = false
code_mode_only = false
code_mode_host = false
code_mode_prewarm = false
shell_zsh_fork = false
```

只读配置用于通过隔离验证后的首次检查，不代表当前鸿蒙后端已实现只读隔离。工作区写入策略也必须通过验收后才可用于真实编码任务。

配置不预置 API Key、个人目录或固定模型名称。模型按账户和所选服务实际支持情况选择。暂缓特性如果被当前上游的启动流程或模型要求强制依赖，需要解决依赖再形成可交付配置。

## 防止误更新

用户端应用更新机制后续设计，但现有更新入口的兼容性现在就需要处理。

- [TUI 更新行为](../../codex-rs/tui/src/update_action.rs)会根据安装方式选用包管理器或独立安装脚本。
- [安装上下文](../../codex-rs/install-context/src/lib.rs)的 Unix 分类不足以单独证明下载产物适合 OHOS。
- [daemon 更新循环](../../codex-rs/app-server-daemon/src/update_loop.rs)和[手动更新](../../codex-rs/app-server-daemon/src/manual_update.rs)需要独立审核。

拟议处理：明确识别鸿蒙适配产物，不调用不匹配的上游安装器；未设计鸿蒙更新渠道前，相关入口应返回清晰说明。`check_for_update_on_startup = false` 只关闭启动检查，不代替手动更新、后台服务及其他更新入口的源码适配。

这项工作只保证当前包不会被错误替换，不提前决定自动下载、版本切换或回退产品方案。

## 诊断与验收

配置错误应显示键名、来源和原因，避免将“不支持某平台能力”误报成 TOML 格式问题。诊断不得输出凭据。

验证用户配置、命令行覆盖、项目配置和管理约束的合成结果；用户显式打开不支持的能力时有确定行为。旧配置中的未知或变更字段沿用上游兼容规则，不能静默吞掉权限字段。

验证启动检查关闭后，手动更新和 daemon 路径同样不会安装错误目标。最后在不传额外参数的情况下执行 `codex`，确认它能按已经配置好的能力正常启动。
