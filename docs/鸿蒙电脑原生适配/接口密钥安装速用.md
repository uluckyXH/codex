# 鸿蒙 PC 接口密钥安装速用

适用：ARM64 鸿蒙 PC 原生终端（zsh）。这是**未真机验证的候选包**；每段执行成功后再继续，报签名、缺库或沙箱错误时先停止。已安装本包的读者直接从配置步骤开始。

## 1. 准备文件

Mac 已整理好的目录：`/Volumes/MacSSD/Repositories/codex/.harmony-build/交付/鸿蒙Codex安装`。

把整个“鸿蒙Codex安装”文件夹复制到鸿蒙用户主目录，最终路径是 `$HOME/鸿蒙Codex安装`，包含：

- `鸿蒙Codex-0.0.0-harmony.bc1a10fa191c-未真机验证.tar.gz`：完整程序包，里面已有签名后的 codex、rg、bwrap 和安装器。
- `安装包校验.sha256`：压缩包校验文件。
- `账号登录安装速用.md`、`接口密钥安装速用.md`：任选对应教程。

鸿蒙端准备 `sh`、`zsh`、`tar`、基本文件命令及 `sha256sum` 或 `shasum`；Codex 本身无需 Rust、SDK、Java 或 Node.js。项目需要的原生 Git、Python、Node.js 等另行安装。按[华为说明](https://consumer.huawei.com/cn/support/content/zh-cn16079826/)开启“设置 → 隐私和安全 → 高级 → 运行外部来源的扩展程序”。

## 2. 安装并配置命令路径

```zsh
: '先让 zsh 识别后续粘贴命令中的中文 # 注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 在独立 Shell 中安装，任一步失败立即停止
(
set -eu
# 进入传来的安装资料目录
cd "$HOME/鸿蒙Codex安装"
# 校验压缩包是否完整；按设备现有工具自动选择
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 新建解压目录；已存在就停止，避免覆盖旧内容
mkdir 解压
# 解压完整目录包，保留辅助程序和签名
tar -xzf "鸿蒙Codex-0.0.0-harmony.bc1a10fa191c-未真机验证.tar.gz" -C 解压
# 安装到用户目录；安装器会再次校验文件，已有安装不覆盖
sh 解压/鸿蒙Codex/安装.sh --prefix "$HOME/应用工具/鸿蒙Codex"
)
```

```sh
# 让当前终端能够找到本次安装的 codex
. "$HOME/应用工具/鸿蒙Codex/环境.sh"
# 只追加一次启动配置；新开 zsh 终端也能直接输入 codex
grep -Fqx '. "$HOME/应用工具/鸿蒙Codex/环境.sh"' "$HOME/.zshrc" 2>/dev/null ||
    printf '%s\n' '. "$HOME/应用工具/鸿蒙Codex/环境.sh"' >> "$HOME/.zshrc"
# 查看命令位置，应该指向上面的安装目录
command -v codex
```

```sh
# 在鸿蒙 PC 检查实际加载；失败时先停止，不继续登录
"$HOME/应用工具/鸿蒙Codex/bin/codex" --version
```

## 3. 选择一种 API 接入方式

**A、B 二选一，不要连续执行两套配置。** 配置文件已存在时会停止，请合并已有内容。Key 只在输入提示出现后粘贴，不填进教程、配置或命令参数。

### A. OpenAI 官方 API Key

```sh
# 新建用户配置；已存在时停止，绝不覆盖
(
set -euC
# 新文件仅当前用户可读写
umask 077
# 沿用已有 CODEX_HOME，否则使用默认用户目录
harmony_config_dir="${CODEX_HOME:-$HOME/.codex}"
# 准备配置目录
mkdir -p "$harmony_config_dir"
# 写入下面带中文说明的配置
cat > "$harmony_config_dir/config.toml" <<'TOML'
# 凭据保存到本机用户文件，不使用未实现的系统密钥库
cli_auth_credentials_store = "file"
mcp_oauth_credentials_store = "file"
# 限制写入工作区，非受信命令需审批；不关闭沙箱
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
# 避免下载不适用的上游 Linux 更新包
check_for_update_on_startup = false
TOML
)
```

```zsh
# 在独立终端作用域隐藏输入 Key，退出后临时变量消失
(
set -eu
# 读取 Key；输入内容不显示，也不作为命令写入历史
read -rs 'harmony_api_key?粘贴 OpenAI API Key 后回车：'
# 结束隐藏输入后的提示行
printf '\n'
# 从标准输入交给官方登录入口，保存到上面配置的本机凭据文件
printf '%s' "$harmony_api_key" | codex login --with-api-key
)
```

成功后直接执行第 5 步；后续通常只需 `codex`。该方式使用 OpenAI API 额度，和 ChatGPT 订阅额度分开。[官方 API Key 说明](https://learn.chatgpt.com/docs/auth)

### B. 自定义 API 服务

先把下面的 `填写模型ID` 和 `https://你的服务地址/v1` 换成服务方提供的值。服务必须支持 **Responses API 及所需工具调用**；只支持 Chat Completions 的服务不能直接套用本例。这里使用独立的服务 Key，不执行上面的官方 Key 登录。[提供方配置说明](https://learn.chatgpt.com/docs/config-file/config-advanced)

```sh
# 新建用户配置；已存在时停止，绝不覆盖
(
set -euC
# 新文件仅当前用户可读写
umask 077
# 沿用已有 CODEX_HOME，否则使用默认用户目录
harmony_config_dir="${CODEX_HOME:-$HOME/.codex}"
# 准备配置目录
mkdir -p "$harmony_config_dir"
# 写入下面带中文说明的配置
cat > "$harmony_config_dir/config.toml" <<'TOML'
# 使用服务方提供的实际模型 ID 和独立提供方名称
model = "填写模型ID"
model_provider = "harmony_api"
# 首次先关闭尚未确认由服务提供的联网搜索
web_search = "disabled"
# 凭据保存到本机用户文件，不使用未实现的系统密钥库
cli_auth_credentials_store = "file"
mcp_oauth_credentials_store = "file"
# 限制写入工作区，非受信命令需审批；不关闭沙箱
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
# 避免下载不适用的上游 Linux 更新包
check_for_update_on_startup = false

[model_providers.harmony_api]
# 自定义服务的显示名称
name = "鸿蒙接口服务"
# 填完整 API 基址；程序会继续拼接 /responses
base_url = "https://你的服务地址/v1"
# 使用当前代码支持的协议
wire_api = "responses"
# 从本机环境变量取得服务 Key
env_key = "HARMONY_CODEX_API_KEY"
# 使用服务自身的 Key，不要求 OpenAI 账号登录
requires_openai_auth = false
TOML
)
```

## 4. 自定义服务输入 Key（仅 B）

```zsh
# 在当前终端隐藏输入服务 Key，不把真实密钥写进命令历史
read -rs 'HARMONY_CODEX_API_KEY?粘贴服务 API Key 后回车：'
# 结束输入提示行
printf '\n'
# 让此终端启动的 Codex 能读取该 Key
export HARMONY_CODEX_API_KEY
```

B 的 Key 只保存在当前终端环境中，**每次新开终端先重做第 4 步**；配置文件不需要重建。`codex login status` 不验证自定义服务的 Key。

## 5. 进入项目运行

```zsh
# 输入本机项目的实际路径，不需要把示例路径写死
read -r 'harmony_project?请输入项目的绝对路径：'
# 进入项目并启动；路径无效时不会启动
cd -- "$harmony_project" && codex
```

首次先查看文件；运行项目命令需要原生工具链和设备隔离能力。受限执行报错时保留错误信息，不切到无沙箱模式。之后在项目目录执行 `codex` 即可；B 方式每次新终端先执行第 4 步。
