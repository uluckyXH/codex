# 鸿蒙 PC 接口密钥安装速用

本轮已有安装的用户优先按[挂载修复候选安装与复测](挂载修复候选安装与复测.md)完成一次离线复测；下文日期-时间指本次实际交付目录。

已有 API 配置、只需升级并收集故障日志：使用[升级与专项日志速用](升级与专项日志速用.md)，无需重新填写 Key。

适用：ARM64 鸿蒙 PC 7.0 原生终端（zsh）。这是**七版挂载修复候选包，尚待新版真机验收**。已有账号/API 配置继续保留，升级后不用重建配置或重新填写 Key；已安装新版可直接跳到运行步骤。

## 1. 准备文件

Mac 交付目录：`/Volumes/MacSSD/Repositories/codex/releases/日期-时间-鸿蒙Codex-挂载修复候选/鸿蒙Codex安装`。

把整个“鸿蒙Codex安装”文件夹复制到鸿蒙用户主目录，另命名为“鸿蒙Codex安装-挂载修复”，最终路径是 `$HOME/鸿蒙Codex安装-挂载修复`，包含：

- 一个 `鸿蒙Codex-*-未真机验证.tar.gz`：完整签名程序包，含 codex、rg、bwrap、独立目录探针、安装器、终端配置器和诊断脚本。
- `安装包校验.sha256`：本次压缩包校验文件。
- 两份安装速用文档、[升级与专项日志速用](升级与专项日志速用.md)及[七版修复包安装与复测](七版修复包安装与复测.md)。

鸿蒙端准备 `sh`、`zsh`、`tar`、基本文件命令及 `sha256sum` 或 `shasum`；运行 Codex 无需 Rust、SDK、Java 或 Node.js。项目需要的原生 Git、Python、Node.js 等另行安装。按[华为说明](https://consumer.huawei.com/cn/support/content/zh-cn16079826/)开启“设置 → 隐私和安全 → 高级 → 运行外部来源的扩展程序”。

## 2. 安装并配置命令路径

升级前退出旧 Codex、daemon 及其受限子进程；本轮不支持新旧版本并行运行。不要修改整个 HOME 的权限。

```zsh
: '先让 zsh 识别后续粘贴命令中的中文 # 注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 在独立 Shell 中安装，任一步失败立即停止
(
set -eu
# 进入传来的安装资料目录
cd "$HOME/鸿蒙Codex安装-挂载修复"
# 校验压缩包是否完整；按设备现有工具自动选择
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 此目录必须只有一个本次候选包，防止误装旧包
set -- 鸿蒙Codex-*-未真机验证.tar.gz
if [ "$#" -ne 1 ] || [ ! -f "$1" ]; then
    printf '%s\n' '目录内必须恰好有一个候选压缩包，请核对文件。' >&2
    exit 1
fi
# 新建解压目录；已存在就停止，避免覆盖旧内容
mkdir 挂载修复解压
# 解压完整包，保留辅助程序和签名
tar -xzf "$1" -C 挂载修复解压
# 安装到独立目录；保留旧安装和原来的账号/API 配置
sh 挂载修复解压/鸿蒙Codex/安装.sh --prefix "$HOME/应用工具/鸿蒙Codex-挂载修复候选"
# 备份并更新 zsh 的 Codex 启动块，让以后新开终端也使用新版
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/启用终端.sh"
)
```

```sh
# 让当前终端立即找到新版；新终端会从启动配置自动加载
. "$HOME/应用工具/鸿蒙Codex-挂载修复候选/环境.sh"
# 查看当前程序路径，应该指向鸿蒙Codex-挂载修复候选
command -v codex
# 检查真实加载及源码身份；报错时先停止
codex --version
```

新版默认加载 `/etc/ssl/certs/cacert.pem`，无需为这台 PC 额外设置 CA 或 TMPDIR。已有 `CODEX_CA_CERTIFICATE`、`SSL_CERT_FILE` 覆盖仍优先生效；公司自定义证书设置应保留。CLI 和界面版本为 `0.160.0-dev`，`--version` 另显示 HarmonyOS 构建 SHA。它是主线开发快照的适配版，不等同于官方 0.160.0 稳定版；详见[版本来源](https://github.com/uluckyXH/codex/blob/codex/harmony-native/docs/鸿蒙电脑原生适配/上游同步与版本维护.md)。

## 3. 选择一种 API 接入方式

**A、B 二选一，不要连续执行两套配置。** 配置文件已存在时会停止，请合并已有内容。A 在提示中输入 Key；B 把 Key 保存到本机用户配置。真实 Key 不写进仓库教程或要粘贴执行的 Shell 命令。

### A. OpenAI 官方 API Key

```sh
# 新建用户配置；已存在时停止，绝不覆盖
(
set -euC
# 请求新文件使用最小权限；实际权限取决于鸿蒙存储机制
umask 077
# 沿用已有 CODEX_HOME，否则使用默认用户目录
harmony_config_dir="${CODEX_HOME:-$HOME/.codex}"
# 准备配置目录
mkdir -p "$harmony_config_dir"
# 写入下面带中文说明的配置
cat > "$harmony_config_dir/config.toml" <<'TOML'
# 凭据保存到本机用户文件，不使用未实现的系统密钥库
cli_auth_credentials_store = "file"
mcp_oauth_credentials_store = "file"
# 限制写入工作区，非受信命令需审批；不关闭沙箱
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
# 避免下载不适用的上游 Linux 更新包
check_for_update_on_startup = false
TOML
)
```

```zsh
# 在独立终端作用域隐藏输入 Key，退出后临时变量消失
(
set -eu
# 读取 Key；输入内容不显示，也不作为命令写入历史
read -rs 'harmony_api_key?粘贴 OpenAI API Key 后回车：'
# 结束隐藏输入后的提示行
printf '\n'
# 从标准输入交给官方登录入口，保存到上面配置的本机凭据文件
printf '%s' "$harmony_api_key" | codex login --with-api-key
)
```

成功后直接执行第 5 步；后续通常只需 `codex`。该方式使用 OpenAI API 额度，和 ChatGPT 订阅额度分开。[官方 API Key 说明](https://learn.chatgpt.com/docs/auth)

### B. 自定义 API 服务（Key 保存在配置中）

先原样执行下面的模板，再按第 4 步填写地址与 Key。默认模型采用你指定的 `gpt-5.6-terra`；服务必须提供这个模型或对应别名，并支持 **Responses API、工具调用和所选推理强度**。`web_search = "live"` 还需要服务支持联网搜索，不支持时改为 `"disabled"`。本方式无需执行 `codex login`。[提供方配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)

```sh
# 新建用户配置；已存在时停止，绝不覆盖
(
set -euC
# 请求新文件使用最小权限；实际权限取决于鸿蒙存储机制
umask 077
# 沿用已有 CODEX_HOME，否则使用默认用户目录
harmony_config_dir="${CODEX_HOME:-$HOME/.codex}"
# 准备配置目录
mkdir -p "$harmony_config_dir"
# 写入下面带中文说明的配置
cat > "$harmony_config_dir/config.toml" <<'TOML'
# 将需要审批的请求交给用户确认
approvals_reviewer = "user"
# 服务必须支持此模型 ID；有别名时改成服务方提供的实际值
model = "gpt-5.6-terra"
# 选择下方定义的 proxy 提供方
model_provider = "proxy"
# 使用默认服务等级
service_tier = "default"
# 启用实时联网搜索；服务不支持时改为 disabled
web_search = "live"
# 普通任务使用 max 推理强度，需服务和模型支持
model_reasoning_effort = "max"
# 保留原示例；当前版本已弃用此项，不再据此选择风格
personality = "pragmatic"
# 计划模式使用 xhigh 推理强度
plan_mode_reasoning_effort = "xhigh"
# 凭据保存到本机用户文件，不使用未实现的系统密钥库
cli_auth_credentials_store = "file"
mcp_oauth_credentials_store = "file"
# 限制写入工作区，非受信命令需审批；不关闭沙箱
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
# 避免下载不适用的上游 Linux 更新包
check_for_update_on_startup = false

[model_providers.proxy]
# 第 4 步填写完整 API 基址；程序会继续拼接 /responses
base_url = "你获得的那个地址"
# 使用服务自身的 Key，不要求 OpenAI 账号登录
requires_openai_auth = false
# 按你的示例命名；当前源码也用这个名称识别 OpenAI 提供方
name = "OpenAI"
# 使用当前代码支持的协议
wire_api = "responses"
# 第 4 步在本机配置中填写 Key，作为 Bearer token 发送
experimental_bearer_token = "这里填写你的API Key"
TOML
)
```

`name = "OpenAI"` 可以按本例保留；`proxy` 必须与 `[model_providers.proxy]` 对应，连接地址由 `base_url` 决定。当前源码还用 `OpenAI` 这个名称判断部分提供方行为，因此它并非只影响显示，也不保证服务完整兼容。

## 4. 填写接口地址与 Key（仅 B）

```sh
# 显示需要用本机文本编辑器打开的用户配置路径
printf '%s\n' "${CODEX_HOME:-$HOME/.codex}/config.toml"
```

打开上面输出的文件，将 `你获得的那个地址` 替换为服务方给出的完整 API 基址（通常类似 `https://服务域名/v1`，不要额外加 `/responses`），将 `这里填写你的API Key` 替换为真实 Key，保留两侧引号并保存。模型名称有别名时同时修改 `model`。

配置是 **TOML**，不要把它逐行当作 Shell 命令执行。Key 会明文保存在这个仅当前用户可读写的配置文件里，不要分享或提交该文件。保存后新开终端也无需重输 Key；`codex login status` 不验证此方式的 Key。

## 5. 进入项目运行

```zsh
# 输入本机项目的实际路径，不需要把示例路径写死
read -r 'harmony_project?请输入项目的绝对路径：'
# 进入项目并启动；路径无效时不会启动
cd -- "$harmony_project" && codex
```

首次先查看文件；运行项目命令需要原生工具链和设备隔离能力。受限执行报错时保留错误信息，不切到无沙箱模式。之后在项目目录执行 `codex` 即可。

本轮仅核对命令、配置格式和安装流程，未执行真实或模拟认证、凭据读写测试或模型请求。
