# 沙箱与权限适配

状态：设计稿。覆盖适配09—10，并约束文件、Shell、辅助程序及 MCP 的本地执行。

## 必须区分的职责

| 机制 | 它解决的问题 | 不能由它推导出的结论 |
| --- | --- | --- |
| 二进制签名 | 程序能否被目标系统接受和加载 | 程序获得所有权限、Codex 已有沙箱 |
| 鸿蒙用户或应用授权 | 当前身份能访问哪些系统资源 | 每个 Codex 子任务已经相互隔离 |
| Codex 审批 | 用户是否允许一次操作 | 未获允许的操作一定被操作系统阻止 |
| 执行隔离 | 实际限制文件和网络访问 | 仅写入一个配置值就自动具备该能力 |

首版要求功能描述与实际强制执行一致。不支持所请求的隔离时，执行前返回明确错误；不得静默改为无隔离执行。

## 适配决策流程

1. 用 SDK 和公开接口确定候选机制及参数，不假设 Linux 内核特性全部存在。
2. 源码中分离 OHOS 能力选择，保留策略层公共逻辑。
3. 在普通终端身份下探测候选机制的可用性；系统存在某接口不代表该身份获准调用。
4. 如果既有机制的强制语义完整可用，复用其实现并保留回归用例。
5. 如果不完整，评估鸿蒙提供的等价隔离方式和原生权限边界，再设计后端；没有依据时不虚构系统接口。
6. 所需策略不能实现时，记录阻断项；源码和交叉构建工作仍可继续，但受影响的编码能力不得标记为已完成。

首轮网络、配置和 TUI 验证可以使用禁用本地工具注册的开发验证构建。它需要后续实现且明确标记，不是现有 `--sandbox read-only` 的替代含义，也不满足最终编码闭环。

## 文件策略

读取、写入、补丁、Shell 和文件辅助进程应共享最终解析后的授权范围。至少覆盖：工作区、额外授权根目录、程序资源、凭据、临时目录和会话数据。

先规范化路径，再在最终文件访问或执行边界强制约束。需要防止软链接越界、目录替换及路径检查与实际打开之间的竞态；单纯比较路径字符串前缀不足以实现隔离。

只读策略仍可能需要 Codex 自己写入会话状态，其范围应按既有架构独立授权，并与被执行工具的可写范围区分。不得为保存会话而放开任意子进程对整个主目录的写权限。

## 网络策略

Codex 主进程访问模型服务与子进程是否能联网是两种策略。要求子进程禁止联网时，应测试直连 TCP、UDP/DNS、回环地址、Unix 套接字、代理环境和后代进程。

仅设置 `HTTP_PROXY` 等变量无法限制不遵循代理的程序；如果网络策略依赖代理，则需要可验证的系统限制协作。无能力时应报告无法实施该策略，不显示已经隔离。

## 审批和配置

复用既有审批模式及组织管理约束。某个请求需要额外目录或联网权限时，审批结果应转换成可执行的权限配置，且只作用于对应请求。

本方案不以默认开启 `danger-full-access`、绕过审批或要求 root 作为“适配成功”的条件。若后续产品需要支持已有的完全访问模式，应独立说明其行为，不把它用作受限模式的隐式回退。

## 必须通过的行为测试

| 场景 | 预期 |
| --- | --- |
| 只读任务尝试写入项目 | 被实际阻止，并提供可理解的原因 |
| 工作区写入与工作区外写入 | 允许范围内成功，范围外被阻止 |
| 软链接或目录替换指向范围外 | 不扩大授权 |
| 父进程再创建子进程 | 限制继续生效 |
| 禁止联网时使用直连或另设代理 | 不绕开网络限制 |
| 增加一次性授权后再次执行无授权任务 | 权限不残留 |
| 策略创建失败或辅助程序缺失 | 子进程没有以较宽权限偷偷启动 |

没有设备时可检查策略转换、错误传播和目标编译；操作系统强制效果必须真机验证。详见[验证记录](验证方案与兼容性记录.md)。
