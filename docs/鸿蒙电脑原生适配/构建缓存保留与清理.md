# 构建缓存保留与清理

从 2026-10-04 起，按用户要求只保留一份当前构建缓存，避免每次测试或每个会话都累积整套 Rust 产物。

## 保留规则

- 编译前关闭当前模拟器并确认已退出，再开始构建；编译完成后才启动模拟器调试。若调试后不需再次编译，保持模拟器运行，不作例行关闭。多会话统一遵守此顺序；关闭不删除实例、镜像或应用数据。
- 编译统一使用主仓库 `.harmony-build/current`，Cargo 产物位于其 `target` 子目录。Mac 与 OHOS 目标可放在同一 `target` 下，由 Cargo 分开管理。
- HAP 的 Hvigor 要求输出真实路径使用英文字符，本机 `current` 的目标含中文，宿主固定用 `.harmony-build/terminal-host-current` 和第二身份验收目录 `.harmony-build/terminal-host-second-current`。这不是第二份 Rust 缓存；失败尝试只留日志，清理重复解包。
- 多会话的编译、包装器生成及依赖这些产物的测试统一排队串行执行；不再通过 `cp -cR`、`cp -R` 或其他复制方式为每轮测试保存完整缓存。
- 必须临时隔离时，测试结束、报告留档且相关进程退出后立即删除临时缓存。长期保留当前发布构建所需的缓存；不再使用的 debug 和增量产物可清理。
- 源码、Git 工作副本、私有配置、签名材料、测试报告和必要日志保留。Rust 工具链、Cargo 下载缓存、SDK、模拟器镜像不属于此次清理对象。
- `releases/` 保留已交付的安装包、SHA256 和说明。旧批次的重复解包、安装夹具、HAP 中间目录和测试可执行文件在证据保存后清理。
- 历史报告记录的构建路径是当时的产物位置，不保证该缓存永久存在；复现依据源码 SHA、构建参数、工具链版本和报告中的证据。

## 统一构建目录

在主仓库根目录执行；使用其他工作副本时，仍指向这个主仓库目录。

```sh
# 指定唯一的编译缓存根目录；不会发起编译。
harmony_cache_root="/Volumes/MacSSD/Repositories/codex/.harmony-build/current"

# 鸿蒙构建命令使用：--output-dir "$harmony_cache_root"
# 完整签名打包使用：--build-dir "$harmony_cache_root"
# Mac Cargo 测试使用：CARGO_TARGET_DIR="$harmony_cache_root/target"
```

本机 `current` 是指向最近完整构建目录的符号链接，复用原有路径；不是又复制了一份缓存。主仓库 `.harmony-build/target` 也指向同一份产物，兼容默认构建入口。新机器可直接建立真实的 `current` 目录，构建与测试仍统一使用上面的显式参数。

清理前先解析 `current` 的实际目标并排除该目录，不能按日期直接删除它所在的旧批次。此次清理结果见[清理与保留验证报告](测试报告/2026-10-04-构建缓存清理/测试报告.md)。

## 查看空间

```sh
# 查看外置盘可用空间；APFS 的实际容器用量可在“磁盘工具”中核对。
df -h /Volumes/MacSSD

# 查看构建目录的累计统计，便于找出大目录。
du -sh .harmony-build
```

APFS 的写时复制文件可以共享底层数据块，因此 `du` 对多个副本的累计值不能直接当作独占物理空间。清理释放量应以清理前后的磁盘实际用量变化为准，不能把删除目录的累计大小相加当作释放量。
