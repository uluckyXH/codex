# 鸿蒙 PC 升级与专项日志速用

本轮已有安装的用户优先按[挂载修复候选安装与复测](https://github.com/uluckyXH/codex/blob/e11ea5e65308bc00ebb5c3ab238b73213ac362c0/docs/%E9%B8%BF%E8%92%99%E7%94%B5%E8%84%91%E5%8E%9F%E7%94%9F%E9%80%82%E9%85%8D/%E6%8C%82%E8%BD%BD%E4%BF%AE%E5%A4%8D%E5%80%99%E9%80%89%E5%AE%89%E8%A3%85%E4%B8%8E%E5%A4%8D%E6%B5%8B.md)完成一次离线复测；下文日期-时间指本次实际交付目录。

适用：已有账号/API 配置的鸿蒙 PC 7.0、ARM64、HiShell/zsh。新版显示 `0.160.0-dev`，不检查、不提醒、不安装官方更新；以后手动安装本项目的鸿蒙包。**本轮改进挂载身份识别、同一进程诊断及独立探针收尾；文件写入失败和终端 159 仍需复测。**

本候选包在编译时固定尝试 `/data/storage/el2/base/files`，逐级检查目录归属、权限和身份。不使用公共 HOME 回退，不修改 HOME/.codex 权限。上一版报告中 a/s 归属和权限已通过，受限执行仍停在挂载校验。本轮继续逐项验证，不保证已解除后续阻塞。

## 1. 复制与升级

Mac 上把 `releases/日期-时间-鸿蒙Codex-挂载修复候选/鸿蒙Codex安装` 整个文件夹复制到鸿蒙主目录，命名为 **`鸿蒙Codex更新-挂载修复`**。目录内应有一个完整压缩包、`安装包校验.sha256` 和本说明；不要混入旧压缩包。

先退出旧 Codex、daemon 及其受限子进程，再在终端复制。本轮不支持新旧版本同时运行：旧沙箱并不知道新控制目录，不能仅靠新版修复保证并行隔离。安装器不会自动杀进程。

```zsh
: '让 zsh 接受后续命令中的中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 在独立 Shell 中升级，任一步失败就停止；不会修改 API 或账号配置
(
set -eu
# 进入刚传来的新版资料目录
cd "$HOME/鸿蒙Codex更新-挂载修复"
# 校验压缩包，自动选择设备已有的校验工具
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 只接受一个候选包，避免误选旧包
set -- 鸿蒙Codex-*-未真机验证.tar.gz
if [ "$#" -ne 1 ] || [ ! -f "$1" ]; then
    printf '%s\n' '目录内必须恰好有一个候选压缩包，请核对文件。' >&2
    exit 1
fi
# 建全新的解压目录，已有目录时停止，不覆盖旧内容
mkdir 挂载修复解压
# 解压整个目录包，保留主程序、辅助程序与签名
tar -xzf "$1" -C 挂载修复解压
# 安装到新版独立目录，保留旧安装及原账号/API 配置
sh 挂载修复解压/鸿蒙Codex/安装.sh --prefix "$HOME/应用工具/鸿蒙Codex-挂载修复候选"
# 备份并更新 zsh 启动配置，让新终端使用新版
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/启用终端.sh"
)
```

```sh
# 当前终端立即加载新版命令路径
. "$HOME/应用工具/鸿蒙Codex-挂载修复候选/环境.sh"
# 确认命令来自新版目录
command -v codex
# 确认显示 0.160.0-dev，以及 HarmonyOS 构建 SHA
codex --version
```

已有配置继续使用，不要重跑首次 API 配置或登录。若安装提示新版目标目录已存在，先停下核对；不要删除旧目录或覆盖它。

## 2. 先收集沙箱专项日志（不调用模型）

```sh
# 独立采集身份和目录信息，直接显示；无需 id，也不先创建 HOME 日志目录
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --paths-only
# 检查普通 pwd、受限 pwd、包内资源与真实退出状态；失败也会保留日志
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --sandbox
```

第二条命令最后会显示本次目录：`$HOME/Codex诊断/时间-进程号/`。提供这五份文件；如果连报告目录也无法创建，先复制第一条的终端输出：

- `检查摘要.txt`：每项检查的退出码。
- `目录与身份.txt`：真实 UID/GID、目录所有者及权限、Native API 返回值和探测阶段。
- `挂载诊断.txt`：Rust 进程同一 FD 的挂载身份、拒绝原因及有界挂载表。
- `受限终端.txt`：新增的 `stage`、`raw_wait_status`、`signal`、`errno` 和沙箱错误。
- `构建与能力.txt`：确认实际使用的程序、版本及资源。

目录探针退出 0 只代表采集完成，候选目录不存在或拒绝信息仍可能在 JSON 中；不代表已找到安全运行根。默认只读，不创建测试目录，不读取账号配置。

`159` 只是表面退出码；这些字段用来区分程序主动退出、信号终止、子进程加载及沙箱准备失败。无输出的字段不要自行补值。

## 3. 再收集文件写入与终端工具日志

下面的命令保留交互界面，只把 stderr 写到独立文件；按原来的服务配置调用模型。

```sh
# 保存本次日志路径，退出 Codex 后仍可在当前终端查看
harmony_trace_dir="$HOME/Codex诊断/工具专项-$(date +%Y%m%d-%H%M%S)-$$"
# 建目录、切目录或终端检查失败时，立即停止，不会在原目录启动
(
set -eu
# TERM 未设置或为 dumb 时，请换到正常的 HiShell 交互终端
case "${TERM-}" in
    ''|dumb) printf '%s\n' '请在正常的 HiShell 交互终端运行。' >&2; exit 1 ;;
esac
# 请求新日志使用最小权限；实际权限以设备目录探针为准
umask 077
# 创建日志父目录；本次子目录必须是全新的
mkdir -p "$HOME/Codex诊断"
mkdir "$harmony_trace_dir"
# 创建空白测试项目与交互日志目录
mkdir "$harmony_trace_dir/空白项目" "$harmony_trace_dir/交互日志"
# 只在这个空白项目中复现，失败就停止
cd "$harmony_trace_dir/空白项目"
# 开启阶段诊断，stderr 单独保存；模型仍使用原服务配置
if CODEX_HARMONY_PROCESS_DIAGNOSTICS=1 \
   RUST_LOG=warn,codex_exec_server::fs_sandbox=debug,codex_linux_sandbox=debug \
   codex -c "log_dir=\"$harmony_trace_dir/交互日志\"" \
       2>"$harmony_trace_dir/进程专项.txt"; then
    harmony_codex_exit=0
else
    harmony_codex_exit=$?
fi
# 退出后保留主程序退出码及本次日志目录
printf 'Codex 退出码：%s\n' "$harmony_codex_exit" > "$harmony_trace_dir/启动结果.txt"
printf '日志目录：%s\n' "$harmony_trace_dir"
exit "$harmony_codex_exit"
)
```

默认本地模式下，父进程等待状态通常进入 `进程专项.txt`；子进程阶段和文件 helper 失败可能只出现在工具结果中。因此必须同时保留完整工具错误，不能只依赖文件摘要。

进入后依次发送：①“用终端工具执行 pwd”；②“用文件编辑工具创建 问候.txt，内容为 鸿蒙验证”。保留失败工具的**完整错误文字**，不要仅记录退出码。按正常受限权限运行，不开启全盘权限来绕过失败。

退出后，在同一个终端复制：

```sh
# 提取阶段及错误前后 4 行；区分日志缺失、没有匹配和读取失败
(
for harmony_log_file in "$harmony_trace_dir/进程专项.txt" "$harmony_trace_dir/交互日志/codex-tui.log"; do
    printf '\n文件：%s\n' "$harmony_log_file"
    if [ ! -r "$harmony_log_file" ]; then
        printf '%s\n' '此日志不存在或不可读，请一并反馈。'
        continue
    fi
    if grep -n -E -C 4 'runtime-dir|alias-root|codex-mount|codex-process|raw_wait_status|signal=|errno=|sandbox.*stage=|fs[.]sandbox_(request|prepare|execute)|fs sandbox helper|bubblewrap|Permission denied|Operation not permitted|Read-only file system|os error' "$harmony_log_file"; then
        :
    else
        harmony_grep_exit=$?
        if [ "$harmony_grep_exit" -eq 1 ]; then
            printf '%s\n' '日志存在，但未匹配到专项字段。'
        else
            printf '提取失败，退出码：%s\n' "$harmony_grep_exit"
        fi
    fi
done
) > "$harmony_trace_dir/专项摘要.txt"
# 显示摘要，便于复制错误片段
cat "$harmony_trace_dir/专项摘要.txt"
```

发回第 2 步的五份文件、第 3 步的 `专项摘要.txt` 和失败工具的完整错误文字即可。分享前检查路径和内容；**不用发 API Key、`config.toml` 或 `auth.json`**。若日志缺失或没有匹配，也请如实说明，不表示故障已经解决。原始日志先保留本机，不直接整份发送。
