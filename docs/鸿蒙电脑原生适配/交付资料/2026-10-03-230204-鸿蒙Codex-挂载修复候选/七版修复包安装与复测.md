# 七版修复包安装与复测

本轮已有安装的用户优先按[挂载修复候选安装与复测](https://github.com/uluckyXH/codex/blob/e11ea5e65308bc00ebb5c3ab238b73213ac362c0/docs/%E9%B8%BF%E8%92%99%E7%94%B5%E8%84%91%E5%8E%9F%E7%94%9F%E9%80%82%E9%85%8D/%E6%8C%82%E8%BD%BD%E4%BF%AE%E5%A4%8D%E5%80%99%E9%80%89%E5%AE%89%E8%A3%85%E4%B8%8E%E5%A4%8D%E6%B5%8B.md)完成一次离线复测；下文日期-时间指本次实际交付目录。

已有安装并要排查退出 159 / 文件写入失败时，直接按[升级与专项日志速用](https://github.com/uluckyXH/codex/blob/e11ea5e65308bc00ebb5c3ab238b73213ac362c0/docs/%E9%B8%BF%E8%92%99%E7%94%B5%E8%84%91%E5%8E%9F%E7%94%9F%E9%80%82%E9%85%8D/%E5%8D%87%E7%BA%A7%E4%B8%8E%E4%B8%93%E9%A1%B9%E6%97%A5%E5%BF%97%E9%80%9F%E7%94%A8.md)执行，包含保留配置升级及本轮专项日志命令。

目标设备：商业鸿蒙 PC 7.0、ARM64、HiShell/zsh。修复源码和 Mac 测试已分别留档；新版的内核隔离与完整编码闭环仍待这台设备复测。[修复计划](https://github.com/uluckyXH/codex/blob/codex/harmony-native/docs/鸿蒙电脑原生适配/鸿蒙电脑七版故障修复计划.md)记录各项状态，不能把“构建成功”当成“沙箱已通过”。

## 安装或升级

Mac 上将 `releases/日期-时间-鸿蒙Codex-挂载修复候选/鸿蒙Codex安装` 整个目录复制到鸿蒙的 `$HOME/鸿蒙Codex安装-挂载修复`，按[接口密钥安装速用](https://github.com/uluckyXH/codex/blob/e11ea5e65308bc00ebb5c3ab238b73213ac362c0/docs/%E9%B8%BF%E8%92%99%E7%94%B5%E8%84%91%E5%8E%9F%E7%94%9F%E9%80%82%E9%85%8D/%E6%8E%A5%E5%8F%A3%E5%AF%86%E9%92%A5%E5%AE%89%E8%A3%85%E9%80%9F%E7%94%A8.md)或[账号登录安装速用](https://github.com/uluckyXH/codex/blob/e11ea5e65308bc00ebb5c3ab238b73213ac362c0/docs/%E9%B8%BF%E8%92%99%E7%94%B5%E8%84%91%E5%8E%9F%E7%94%9F%E9%80%82%E9%85%8D/%E8%B4%A6%E5%8F%B7%E7%99%BB%E5%BD%95%E5%AE%89%E8%A3%85%E9%80%9F%E7%94%A8.md)的第 1、2 步安装。不要只复制一个 codex 文件。

先退出旧 Codex、daemon 和它们的受限子进程；新旧版本暂不支持并行运行。本包固定尝试 `/data/storage/el2/base/files` 私有目录候选，所有检查仍须通过；上一版已观察到其 a/s 归属和权限通过，但完整隔离仍未通过，不要求修改 HOME/.codex 的权限。

已有 `config.toml` 和账号/API 配置直接沿用，不必重跑首次配置。新安装目录是 `$HOME/应用工具/鸿蒙Codex-挂载修复候选`；安装器不覆盖旧目录，终端配置器会备份 `.zshrc` 并更新自己管理的启动块。

## 先运行一次本机诊断

```zsh
: '允许在终端粘贴下面的中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 加载新版命令路径；不改变 HOME、TMPDIR 或账号配置
. "$HOME/应用工具/鸿蒙Codex-挂载修复候选/环境.sh"
# 输出新包的源码身份，确认没有误用旧版本
codex --version
# 独立目录探针直接显示身份和候选信息；即使 HOME 日志不可写也可执行
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --paths-only
# 检查文件、资源、普通 pwd 和受限 pwd；不请求模型、不执行登录
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --sandbox
```

结果在终端最后输出的 `$HOME/Codex诊断/时间-进程号/` 中。失败时也会保留报告，重点提供 `检查摘要.txt`、`目录与身份.txt`、`受限终端.txt`、`挂载诊断.txt`、`构建与能力.txt`。若报告目录创建失败，保留 `--paths-only` 的终端输出。目录探针退出 0 仅代表采集完成，不能据此判定候选安全。目录错误、签名/加载失败和信号状态会分别显示；不用发送 `config.toml`、`auth.json` 或 Key。

旧配置若启用了 `use_legacy_landlock`，受限模式会明确拒绝；在本机配置编辑器撤销这个实验开关，再用默认沙箱复测。不要把 `sandbox_mode` 改成全盘权限来掩盖故障。

## 再验证真实工具闭环

诊断中的受限终端通过后，在新建的空白测试项目中启动。模型会按现有服务配置处理测试请求，可能产生正常 API 费用。

```sh
# 新建独立测试目录，不触碰现有项目文件
mkdir -p "$HOME/Codex七版验证"
# 进入这个空白项目，后续只在这里验证文件操作
cd "$HOME/Codex七版验证"
# 启用阶段日志并启动；只对本次进程生效
CODEX_HARMONY_PROCESS_DIAGNOSTICS=1 codex
```

依次让 Codex 做下面三件事，并保存每步的工具结果：

1. 执行 `pwd`，应该得到当前测试目录，退出码为 0。
2. 用文件编辑工具创建 `问候.sh`，内容为 `printf '鸿蒙验证成功\n'`，再读取文件核对。
3. 执行 `sh 问候.sh`，应该输出“鸿蒙验证成功”，退出码为 0。

这三项通过只能证明允许操作的编码闭环；还需按[沙箱验收表](https://github.com/uluckyXH/codex/blob/codex/harmony-native/docs/鸿蒙电脑原生适配/沙箱与权限适配.md)验证禁止访问的路径与 daemon socket 仍被隔离。若仍出现 159，请提供原始 `signal`、`raw_wait_status` 和最后一个 `stage`，不能仅凭 159 判定 SIGSYS 或 seccomp。

## 日志与回退

交互日志默认是 `${CODEX_HOME:-$HOME/.codex}/log/codex-tui.log`；自定义 `log_dir` 时以该设置为准。阶段输出也可能显示在终端 stderr。只摘录本次错误附近的内容，分享前检查路径、请求内容和服务地址，不附带认证文件。

```sh
# 撤销新版脚本管理的终端启动块；原配置备份与旧安装均保留
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/启用终端.sh" --remove
# 临时使用本次故障报告中的旧安装路径；有其他路径时按实际修改
. "$HOME/codex-hm/环境.sh"
```

回退仅用于对比；旧包的沙箱和 TLS 已知问题不会因此消失。`releases/` 是本机产物目录，源码、方案与测试报告仍由 Git 管理；本流程不会创建或上传 GitHub Release。
