# 鸿蒙 PC 七版挂载修复候选安装资料

将本目录整体复制到鸿蒙主目录，命名为“鸿蒙Codex安装-挂载修复”，先按《挂载修复候选安装与复测.md》操作。已有账号/API 配置继续保留，无须重新填写 Key。新包安装到独立目录，不覆盖旧包；退出旧 Codex、daemon 及其受限子进程后再安装，本轮不支持新旧实例并行。

CLI 版本：`0.160.0-dev`。官方更新检查、提醒和执行继续禁用，没有跟进上游新版本源码。

包版本：`0.160.0-dev.harmony.ge11ea5e65308`。

完整源码 SHA：`e11ea5e65308bc00ebb5c3ab238b73213ac362c0`。

本轮采用同一个目录 FD 的 statx 明确设备号，并与 inode/权限/UID/GID、fdinfo mount ID、命名空间及挂载表严格核对。失败会指出具体 reason；没有按 hmfs 名称放行或关闭目录保护。Native 一次性查询不主动卸载库，显式完成输出后退出；实际故障是否消失仍需真机反馈。

先只运行诊断脚本的受限 pwd，回传检查摘要、目录与身份、受限终端、挂载诊断、构建与能力五个文件。本包保留原始错误和等待状态，不调用模型。受限 pwd 通过后，再安排文件写入和隔离负向验收。

已完成 Mac 交叉构建、SDK 自签名、独立解包、SHA256 与文件安装检查；没有在 Mac 执行鸿蒙 ELF。原 159、文件写入和真实隔离尚未关闭。当前证据不能认定 PC7 不支持所需沙箱，也不能认定已经支持全部能力。

包内四个 ELF 均为已签名文件：codex、rg、bwrap、harmony-runtime-probe。本轮重编 CLI 和探针；rg/bwrap 复用记录中的已验证签名资源，构建记录保存来源和摘要。不要传“未签名”中间文件，也不要只替换主程序。

本机 releases 目录被 Git 忽略。源码、计划、测试报告和交付文字进入仓库，不上传二进制或创建 GitHub Release。只需传本资料目录，无须 Rust、SDK、Java 或编译缓存。
