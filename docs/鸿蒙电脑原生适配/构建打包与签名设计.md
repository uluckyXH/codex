## 当前候选包布局

```text
鸿蒙Codex/
├── bin/
│   └── codex
├── codex-path/
│   └── rg
├── codex-resources/bwrap
├── codex-package.json
├── 安装说明.md
├── 构建与签名记录.json
├── 文件校验清单.sha256
├── 安装.sh
└── 许可原文/
```

以上布局已由实际打包流水线生成并检查。`环境.sh` 由安装器在新的安装目录创建。既有协议文件 `codex-package.json` 和资源目录名保持原名；新增说明使用中文。清单由打包器生成并遵循现有读取方式，不让用户手写伪造元数据。

如保留代码模式宿主，将 `codex-code-mode-host` 放入 `bin`；原生动态库、沙箱或定制 Shell 按最终实现加入资源目录。包中只包含实际需要且已适配的文件，但不能省略启用能力依赖的资源。

## 构建、签名与归档顺序

```mermaid
flowchart LR
    源码[固定源码与依赖] --> 辅助[构建与签名 rg 和 bwrap]
    辅助 --> 摘要[将已签名 bwrap 摘要编入 CLI]
    摘要 --> 编译[构建 CLI]
    编译 --> 检查[检查 ELF 并裁剪符号]
    检查 --> 签名[签名 CLI]
    签名 --> 装配[原样装配完整包]
    装配 --> 校验[记录最终摘要并归档]
    校验 --> 验收[解包与真机验收]
```

签名后不再修改二进制内容。按文件类型识别 ELF 和动态库，不只依据扩展名，也不对文档等所有文件盲目签名。符号文件可独立保留用于调试。

最终清单至少记录：源码提交、上游版本、适配版本、Rust/SDK/工具版本、目标、功能组合、每个原生产物的摘要、签名方式和验证状态。许可与再分发条件按各实际依赖检查，保留上游要求的许可文本。

## 签名工具如何获取

华为官方二进制工具文档列出三条路径：[二进制签名工具](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/binary-sign-tool)。

| 签名环境 | 工具来源 |
| --- | --- |
| 鸿蒙 PC | 应用商店安装 DevBox 后，在终端使用 `binary-sign-tool` |
| Linux 构建机 | Command Line Tools 的 SDK `openHarmony/toolchains/lib` 中的原生工具 |
| 兼容 Java 环境 | API 24 及以上工具包内的 `binary-sign-tool.jar`，要求 JDK 8 及以上 |

可在构建机签名后传输，也可在鸿蒙 PC 本机签名。DevBox 在此用于提供签名工具，Codex 的目标仍为原生程序。签名位置不改变编译目标。

## 开发自签名

工具支持不先提供官方证书的自签名方式。本次已在 Mac 使用 SDK 的 Java 工具完成自签名。下方原生工具命令用于后续设备操作参考，实际执行命令与工具输出见[构建记录](实施进展与构建记录.md)。

```sh
binary-sign-tool -help
mkdir -p "产物/已签名"
binary-sign-tool sign \
  -inFile "产物/未签名/codex" \
  -outFile "产物/已签名/codex" \
  -selfSign 1
binary-sign-tool display-sign -inFile "产物/已签名/codex"
```

`display-sign` 是查看签名信息，不是商业设备加载验收。华为支持页另有自签名工具链后传入鸿蒙 PC 执行的示例。[官方部署示例](https://consumer.huawei.com/cn/support/content/zh-cn16078461/)

## 官方二进制证书

若采用官方证书路线，当前申请页面要求企业开发者身份、受限开放，并限制每个账号最多三个二进制证书。需要先通过工单开通，再准备 CSR，在 AppGallery Connect 的证书管理中申请二进制证书，下载后使用匹配的私钥和密钥库签名。[官方申请说明](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/agc-help-binary-cert-0000002408063605)

工具支持自签名与证书签名，但官方证书页对程序运行条件的概括，与自签名部署示例的适用范围没有被完整解释。本项目不能据此保证所有商业系统都接受自签名，也不能认定每次本机开发都要申请企业证书。首台设备记录具体系统、设置、签名方式与实际加载结果。

二进制证书与 HAP 应用签名按不同交付形态处理。当前优先原生 CLI 开发验证；正式分发渠道和应用更新机制后续设计。每次重新构建均重新签名；证书申请不必与每次构建绑定，但使用的证书必须有效且与密钥匹配。

## 传输和安装前检查

按目标系统要求开启外部扩展运行设置；调试传输可以使用 hdc，也可验证文件传输方式。调试身份能执行不等于普通终端用户能执行。[华为外部扩展说明](https://consumer.huawei.com/cn/support/content/zh-cn16079826/)

```sh
hdc file send "产物/已签名/鸿蒙Codex" "/设备上已确认的可写目录/鸿蒙Codex"
```

传输后核对内容摘要、文件权限和包布局。没有 hdc 时，不把调试连接作为日常运行前提。最终操作见[安装指南](安装配置与运行指南.md)。

无设备阶段可产出带签名信息的候选包及清单；只有设备加载、辅助程序和完整编码用例通过后，才能标记为针对该设备基线的可交付包。
