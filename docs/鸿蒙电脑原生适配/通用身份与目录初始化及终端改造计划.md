## 本轮执行约定

1. **编译与模拟器不同时运行。** 代码准备好、即将编译时，先正常关闭当前模拟器并确认已退出，再进行编译；编译完成后才打开模拟器安装和调试。再次需要编译时重复这一顺序。包含会触发编译的 Cargo 检查/测试、原生依赖和宿主应用构建；多会话由主会话协调，不能一边调试一边编译。
2. **无需编译时保持模拟器。** 调试结束后若没有下一次编译，不关闭模拟器，留给用户继续使用。仅编辑代码、文档或查看日志不构成关闭理由；关闭实例不等于卸载应用、重置数据或删除镜像。
3. **开发期间以最新目录为准。** 不实现旧数据迁移、旧布局自动发现、迁移恢复或版本回退代码，也不把旧会话、数据库和项目迁移列为本轮验收。必要时由执行者手动将现有 `config.toml` 放入新 `codex/state/`，不新增迁移脚本；模型保持 `gpt-5.6-terra`。普通配置读写和显式 `CODEX_HOME` 能力继续保留。
4. **真机由用户验收。** 我们负责源码、Mac 检查、模拟器调试、分项报告、完整签名候选包及简洁验收命令；用户负责商业鸿蒙 PC/HiShell 的安装与实测。收到真机结果前保留“待用户真机验收”，不阻止先交付候选包。
5. **代码文件全部英文命名。** 安装、环境、终端启用、诊断、构建、测试脚本以及包内生成代码均用英文文件名；文档文件名和内容用中文。同步源码路径、打包清单、测试、脚本用法和文档命令，不能只重命名单个文件。
6. **两个协作会话，保持已有设置。** 用户要求降低并发负载，只保留目录适配、终端改造两个协作会话；第三个安装交付会话停止，已完成的修改交给主会话继续。派发任务不传模型或思考覆盖参数，保持用户指定的 `gpt-6.1-sol`、`max` 设置。主会话负责安装交付、协调与最终验收。
7. **交付新的安装说明。** 新增中文《新版安装与运行说明》，写明上机文件、前置条件、校验解压、英文安装命令、PATH、账号与 API 两种配置、指定项目启动、版本核对和日志查看；每段复制命令加中文用途注释。以最终包的实际入口、版本和测试结果定稿，同份说明放入对应 release。

## 一、正式目标与模拟器入口

- 正式版提供鸿蒙原生 CLI。用户在鸿蒙自带终端进入有权访问的项目目录后输入 `codex`，不要求打开本项目制作的 GUI。
- 同一个构建适配实际运行身份；不得绑定某台模拟器的 UID，不要求用户查询或填写 UID，也不按机器重新编译。
- Codex 启动时自行完成必要数据目录和运行目录的初始化，或通过随包的命令行启动入口完成；不能依赖事先打开测试 GUI。
- 在验证可用的平台数据目录下单独创建 `codex/`，默认将持久状态、运行资源、临时文件和日志集中管理。当前应用示例为 `/data/storage/el2/base/files/codex/`；签名程序按平台安装要求存放，项目路径独立。
- 当前模拟器没有 HiShell，保留 GUI 作为调试终端。增加可独立使用的空白 Shell，支持 `pwd`、`cd` 和手动运行 `codex`；同时支持指定目录直接启动 Codex。
- 配置、会话、日志、内部运行目录与项目目录独立。`workspace` 只是默认测试位置，不能成为正式版唯一支持的项目目录。
- “通用”必须按系统版本、运行入口和授权条件说明支持范围；尚未验证的其他机器不能写成已经全部兼容。GUI 内普通应用 Shell 与真机 HiShell 分别验收。
- 模型仍限定为 `gpt-5.6-terra`，保留已有配置；不将密钥写入 GUI 包、源码、日志或报告。

## 三、UID 与私有目录的处理原则

UID 是进程身份的一项信息。改为 `getuid/geteuid/getgid/getegid` 等接口获取，不依赖外部 `id` 命令，不假设 UID 与 GID 数字相同。不同账号、不同安装身份的目录分别验证。

**自动获取 UID 只能解决错误的固定身份限制，不能创造系统权限或应用上下文。** 创建目录必须在当前身份已有权限且满足保护要求的父目录内进行；对已有安全目录的使用和对缺失子目录的创建分别处理。

### 应用环境

从实际 ApplicationContext 查询应用私有文件目录，或通过经过验证的原生入口获得同一上下文结果；不能根据 UID 拼接并猜测目录。验证目录来源、实际归属、必要访问能力及保护条件后，创建自身子目录。

`files` 本身就是供应用保存数据的空间。当前 ApplicationContext 返回 `/data/storage/el2/base/files`；相同路径字符串在不同应用中可映射为各自的数据。在正常应用运行环境中，应能按同一套逻辑使用自己的 `files`，不需要用户填写 UID 或逐台重新编译。读取 UID 只是在查询已存在的进程身份，不是申请权限、切换身份或建立应用目录视图。[官方应用沙箱目录说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/file-management/app-sandbox-directory.md)

当前本机 SDK 的 `AbilityKit/ability_runtime/application_context.h` 提供 `OH_AbilityRuntime_ApplicationContextGetFilesDir`，并明确可能返回 `ABILITY_RUNTIME_ERROR_CODE_CONTEXT_NOT_EXIST`。接口存在不代表 HiShell 启动的独立 ELF 一定拥有上下文。

### 独立 CLI 环境

必须用实际终端启动身份验证目录和系统行为。若该进程没有应用上下文，需要查明此入口可使用的受保护目录与官方安装机制；不能借用测试 GUI 的私有目录，也不能把公共 HOME、临时目录或任意可写路径直接视为安全运行根。

HiShell 启动的 Codex 是否可访问其运行环境中的 `/data/storage/el2/base/files` 尚未验证，不能写成已经确认不存在或不可用。Context API 不可用，也不能单独证明文件系统中没有合适目录；需结合实际目录视图、归属、访问结果与保护条件判断。官方允许签名后的外部二进制在开启相应设置后运行，但这不证明每个独立 ELF 都会被分配单独的应用数据空间。[外部扩展程序说明](https://consumer.huawei.com/cn/support/content/zh-cn16079826/)

应用环境与 CLI 环境可以有不同的可信目录来源，但初始化、归属检查和错误处理应共用实现。找不到合法目录时给出可理解的原因与诊断信息，不能靠全局改权限、root 或取消安全检查宣称适配成功。

### 独立 codex 数据根与配置准备

默认布局为平台数据根下的 `codex/state`、`codex/r`、`codex/tmp` 和 `codex/logs`；可选测试项目为 `codex/workspace`，GUI 辅助数据为 `codex/host`。按[目录说明](目录布局与维护说明.md)创建和维护，不再让新默认数据分散在系统 `files` 顶层。

内部 socket 不能只机械增加路径前缀。当前 SDK 的 `sun_path` 为 108 字节；拟议使用 `files/codex/r/s/<64字节名称>`，当前完整示例含 NUL 为 104 字节。取消冗余 UID 路径层的前提是保留实际身份校验和私有根隔离，仍须测试跨身份、路径替换、锁、对端身份和地址长度；长目录不能靠摘要截断或公共目录回退解决。

本轮直接使用新默认布局，不读取旧目录来自动搬运数据，也不编写迁移或回退代码。必要时手动将现有配置放入新 `codex/state/`；旧会话、数据库、日志和项目不要求搬入新根。已有显式 `CODEX_HOME`、`log_dir` 和项目路径仍是用户可选择的配置，不因此增加旧布局兼容层。新目录的读写、导入导出及安装说明同步更新。

### 启动顺序

1. 获取实际运行身份与平台目录来源。
2. 打开并验证可信父目录，防止链接跳转、目录替换和错误所有者。
3. 在已验证的父目录下安全创建或复用 `codex/` 及必要子目录；重复启动可复用，失败或并发不会覆盖新目录中已经准备好的配置。
4. 初始化配置、日志、内部入口与通信目录，再启动 TUI、`exec` 等功能。相关子进程必须使用一致且可信的目录选择，不能由模型工具通过普通环境变量任意改选受保护控制目录。
5. 在用户指定或当前的项目目录工作。项目目录不会因初始化而自动迁移到应用数据目录。

新建自身私有目录可设置所需的保护模式；不修改整个 HOME、桌面项目或其他应用目录的权限。CLI 配置目录、内部运行根和用户项目的验证目的不同，不能一律要求项目目录属于应用 UID 且模式为 0700。

### 桌面项目与系统授权

从 HiShell 启动时，以该运行环境的实际身份、目录视图和权限为基础，不为 Codex 编造新的应用身份。“同一终端的普通命令能读写项目”是应与 Codex 对照的基线；用户在文件管理器能编辑，不直接证明终端或 Codex 已有同等权限。无额外沙箱限制且执行环境一致时，Codex 应能完成同类读写，这是正式入口的验收要求，尚未以真机结果确认。

完全访问模式仍受系统权限约束；源码中存在托管网络要求时还可能选择平台隔离，不能仅凭界面显示 Full Access 推断所有隔离已经关闭。诊断需记录有效配置、实际沙箱选择和系统调用结果。内部 socket/alias 安全目录的校验失败，与项目文件的读写权限分别判断。

鸿蒙 PC 的“设置 → 隐私和安全 → 文件和文件夹”包含桌面、文档和下载目录的权限；也可以从应用权限页面管理已配置或申请的权限。适配需要确认权限应授予哪个实际承载应用，并验证其启动的 Codex 与工具是否获得相应访问能力。应用入口也可评估官方文件夹选择授权，不能将拿到路径或 URI 当作原生工具读写已通过。[华为应用权限管理说明](https://consumer.huawei.com/cn/support/content/zh-cn16046673/)

这类用户文件授权不等于开放其他应用私有数据。华为明确说明终端不能修改 `/storage/Users/currentUser/appdata` 中的应用数据及权限，因此不能把修改该目录作为通用修复办法。[终端访问应用数据限制](https://consumer.huawei.com/cn/support/content/zh-cn16051022/)

## 四、GUI 终端改造

### 空白终端与目录切换

- 新增“空白终端”入口，启动鸿蒙可用的原生交互 Shell，使用真实 PTY。
- 自动配置必要的 `PATH`，能找到安装的 `codex`、`rg` 和随包工具；不要求用户记程序的版本目录。
- 用户可以输入 `cd` 切换目录，然后执行 `codex`；正常退出 Codex 后返回 Shell 提示符。
- 另提供“在此目录启动 Codex”，以结构化参数传递工作目录，正确处理中文、空格和引号；不把路径拼入可执行的 Shell 文本。
- Shell 和 Codex 会话各有明确会话身份、工作目录和状态，停止一个会话不能停止另一个。具体 UI 可使用两个独立页签。
- 输入路径或文件选择器结果仍需权限校验。外部目录授权、路径/URI 访问和原生子工具读写必须一起验证；仅取得路径字符串不算成功。
- 空白终端继承这个 GUI 应用的系统权限，不能冒充 HiShell 或管理员终端；它能用于测试通用 CLI 代码，但不能替代真实终端入口的最终验收。

### 停止、退出与重新启动

将用户操作明确区分为中断当前前台任务、退出 Codex、关闭整段终端会话。控制字符、信号和进程组的具体实现根据实际 Shell 的作业控制能力验证。

先复现用户报告，再核对 PID、会话标识、进程组、前台作业、发信号返回值、`errno` 和 `waitpid` 结果。现有源码的反馈缺口已经确认，但尚不能据此断定用户现象的唯一原因。

界面依据实际退出状态更新。停止失败显示原因，超时按已说明的策略升级；只处理本应用拥有的目标会话，防止旧会话回调或 PID 重用误伤。停止 Codex、停止其工具、关闭 Shell 的范围须清晰，并实际检查子进程退出和 PTY 释放。

## 六、完成标准

本计划完成后，应能由同一套 CLI 在已支持的鸿蒙运行环境下自动识别身份、准备合法数据目录，并在有访问权限的项目目录中工作；用户不填写 UID，不为自己的机器重新编译，也不需要逐个手动建立内部目录。
