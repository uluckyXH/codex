上游基线中存在明确的源码条件缺口：`posix_child.rs` 中 `addchdir` 的定义只覆盖 GNU Linux、musl 和 macOS，后续却有调用。OHOS 不满足这些定义条件。

已核对本机 SDK 6.1.1.125 的 `spawn.h` 和 ARM64 `libc.so` 导出符号：均没有 `posix_spawn_file_actions_addchdir_np`。当前补丁为 OHOS 使用运行时符号查询；缺少扩展时返回既有兼容启动后端，不强制链接一个不存在的符号。`cargo check` 已通过。兼容后端仍在鸿蒙本机调用进程接口，不涉及 Linux 子系统；其工作目录、信号、描述符和权限行为仍需真机验证。

## 子进程创建怎么改

先核查选定 SDK 的 `posix_spawn` 系列声明与符号，包括工作目录扩展、创建新会话、进程组、文件描述符操作和信号设置。

- 如果 OHOS 提供所需扩展且 ABI 已确认，为它增加独立条件分支，复用公共逻辑。
- 如果缺少某个扩展，评估既有兼容后端能否实现相同语义；只有完整保持工作目录、环境、描述符和隔离要求时才允许选用。
- 如果必须新增后端，将差异限制在底层启动模块。多线程进程中的 fork/pre-exec 路径不能随意调用会分配内存或获取锁的逻辑，避免引入死锁。
- 不支持的设置在创建子进程前报错，避免启动后才发现权限或工作目录不符合要求。

不能直接把 OHOS 加到 musl 条件里作为最终修复；目标 ABI、扩展函数和运行权限仍需验证。

## 每次执行必须保持的约定

| 约定 | 适配要求 | 验收例子 |
| --- | --- | --- |
| 参数 | 保留参数边界和 argv[0]，避免二次 Shell 解析 | 中文、空格、引号、空参数 |
| 环境 | 使用最终批准的环境与 PATH，不意外继承密钥 | 有无 PATH、环境覆盖、最小环境 |
| 工作目录 | 子进程在请求目录执行，不修改整个父进程 cwd | 两个并发任务使用不同目录 |
| 输入输出 | 正确处理管道、EOF、背压和关闭顺序 | 大量 stdout/stderr、提前关闭 stdin |
| 退出 | 正确区分退出码、信号终止和启动失败 | 退出 0、非零、程序不存在 |
| 取消 | 终止该任务的进程组及应受管理的后代，并回收 | 长任务及其子进程一起取消 |
| 描述符 | 不泄漏不应继承的文件、套接字或终端句柄 | 子进程无法读取其他任务资源 |
| 生命周期 | 超时、客户端断开、任务丢弃均有明确回收行为 | 反复执行和取消，无僵尸进程累积 |

## PTY 与信号

需要验证普通终端用户可用的 PTY 接口、设备节点、控制终端设置、`termios`、窗口尺寸及 `SIGWINCH`、`SIGINT`、`SIGTERM`、`SIGCHLD` 行为。不预设节点路径或要求 root。

先实现并验证管道执行，再验证 PTY；两者均需进入相同权限处理。PTY 不可用时，非交互命令可以在产品明确支持的管道模式运行，交互命令应明确拒绝或报告限制，不能伪造终端。

Ctrl+C 要区分用户取消当前任务、终止前台命令和退出 CLI。终端异常退出后应恢复原始输入模式和光标状态，进程回收不依赖 TUI 仍在运行。

## Shell 与环境

华为官方环境说明使用 zsh 和用户 `~/.zshrc`；具体 Shell 路径及非交互启动行为仍应由设备确认。[鸿蒙终端环境说明](https://consumer.huawei.com/cn/support/content/zh-cn16089085/)

拟议发现顺序：验证已有配置或环境中指定的 Shell、检查实际 PATH，再使用经设备基线确认的候选路径。保留上游已有语义，避免添加静默选择错误 Shell 的特殊规则。

测试交互、非交互与登录 Shell 分别加载哪些配置；用户 PATH 需传给命令执行路径。Shell 快照捕获不得把欢迎文字当成变量，也不得把敏感环境写入普通诊断日志。

系统 zsh 与 Codex 定制的 zsh fork 分开处理。首版暂缓定制 fork 时，必须关闭对应注册和依赖，并确认普通执行路径仍可用；不得把系统 zsh 文件冒充定制版本。详见[辅助工具](辅助工具与扩展能力适配.md)。

## 自身与项目构建产物

主程序的再次执行、内部补丁入口、执行辅助入口均受签名和路径规则约束。项目命令若生成新的 ELF，也需要遵循系统的签名规则；应在项目开发工具链中安排构建后的签名步骤，不让 Codex 对任意发现的文件自动签名。

## 验收与依赖

无设备阶段可完成：条件分支修改、SDK 符号核对、目标编译，以及公共参数、环境和取消逻辑的宿主回归。后者不能证明鸿蒙信号和 PTY 行为。

真机阶段按上述约定逐项测试，再从 Codex 中实际执行原生开发命令。依赖[平台](平台识别与系统接口适配.md)、[沙箱](沙箱与权限适配.md)和[签名](构建打包与签名设计.md)，不能只以某个独立 Shell 命令成功判定整个执行路径完成。
