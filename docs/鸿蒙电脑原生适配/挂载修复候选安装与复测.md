# 挂载修复候选安装与复测

适用：已有配置的鸿蒙 PC 7.0、ARM64、HiShell。先退出旧 Codex 及其子进程。本轮先做离线复测；不重新登录，不填写 Key，不修改 HOME 权限。

## 准备文件

从本次 `releases/日期-时间-鸿蒙Codex-挂载修复候选/` 复制整个 **鸿蒙Codex安装** 文件夹到鸿蒙主目录，命名为 **鸿蒙Codex安装-挂载修复**。其中必须有：

- 唯一的 `鸿蒙Codex-版本-未真机验证.tar.gz`：完整签名目录包。
- `安装包校验.sha256`：上述压缩包校验值。
- `交付摘要.json` 和本说明：版本、源码 SHA、复测方法。

## 安装新版

```zsh
: '让 HiShell/zsh 允许后续命令中的中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 任一步失败即停止；旧安装、原账号/API 配置均保留
(
set -eu
# 进入本次收到的安装资料
cd "$HOME/鸿蒙Codex安装-挂载修复"
# 校验压缩包是否完整
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 必须只有一个候选压缩包，避免误装旧版
set -- 鸿蒙Codex-*-未真机验证.tar.gz
[ "$#" -eq 1 ] && [ -f "$1" ] || exit 1
# 使用全新的解压目录，已有目录则停止
mkdir 挂载修复解压
# 完整解压，不单独替换 bin/codex
tar -xzf "$1" -C 挂载修复解压
# 安装到新目录，安装器会再次核对全部文件
sh 挂载修复解压/鸿蒙Codex/安装.sh --prefix "$HOME/应用工具/鸿蒙Codex-挂载修复候选"
# 备份 zsh 配置并更新 Codex 启动路径
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/启用终端.sh"
)
```

```sh
# 当前终端加载新版命令路径
. "$HOME/应用工具/鸿蒙Codex-挂载修复候选/环境.sh"
# 确认路径和版本，源码 SHA 应与交付摘要一致
command -v codex
codex --version
```

## 只运行一次离线复测

```sh
# 自动采集目录身份、Native 查询、资源校验及普通/受限 pwd；不调用模型
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --sandbox
```

即使退出非零，报告仍保留在最后显示的 `$HOME/Codex诊断/时间-进程号/`。回传这五份文件：

| 文件 | 用途 |
| --- | --- |
| 检查摘要.txt | 各项原始退出码 |
| 目录与身份.txt | 独立探针、实际 EUID 的 a/s 目录、Native 收尾阶段 |
| 受限终端.txt | 完整受限执行错误及信号/等待状态 |
| 挂载诊断.txt | Rust 进程自身的挂载身份和挂载表；与探针结果分开 |
| 构建与能力.txt | 证明正在使用哪一版程序和资源 |

挂载诊断可能较长，保留原文件；不要只截末尾几行。记录可能包含本机目录名，分享前检查，不用附带 `config.toml`、`auth.json` 或 API Key。没有挂载记录也要回传受限终端，不代表检查通过。

若报告目录创建失败：

```sh
# 直接显示独立探针信息，不创建 HOME 日志目录，也不依赖 id 命令
sh "$HOME/应用工具/鸿蒙Codex-挂载修复候选/诊断.sh" --paths-only
```

只有受限 pwd 通过后，再按《升级与专项日志速用.md》第 3 节做文件编辑复测并保留完整工具错误。受限 pwd、文件编辑与隔离负向检查是不同验收项；本包编译签名成功不代表这些真机项目已通过。
