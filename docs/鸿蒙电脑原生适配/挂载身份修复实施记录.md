## 身份来源取舍

OHOS 使用同一目录 FD 的 statx 明确主次设备号；必须提供类型、模式、UID、GID、inode、mount ID，前五项与 Rust metadata 一致，mount ID 与 fdinfo 一致且非零，命名空间前后保持一致。缺字段、调用失败或关联冲突均明确拒绝。之后要求完整 mountinfo 中唯一 ID 的 device 精确匹配，继续原有路径、覆盖、绑定别名和嵌套检查。其他 Linux 平台保留原有 dev 解码及 Btrfs 例外。

SDK 与 Rust 的 major/minor 规则相同，因此不替换宏、不根据 hmfs 名称放行、不使用报告中的固定 dev 或 mount ID。statx 设备字段没有单独有效位；采用 Linux ABI 的设备字段语义，同时严格检查上述有效位与交叉来源。实际 OHOS 内核行为仍待新日志确认；缺少证据不能标记为真机修复成功。

## 日志约定

显式 `CODEX_HARMONY_PROCESS_DIAGNOSTICS=1` 启用 `[codex-mount] pid=… purpose=aliases|control-sockets stage=…`。包括编译身份、路径、同 FD 的 metadata dev/ino/owner/mode、解码值、fdinfo、statx 请求/返回mask/明确device/mount ID、fstatfs、命名空间、选中条目与拒绝原因。完整 mountinfo 使用字节转义、开始/结束标记、字节偏移和截断标识；超过安全读取上限拒绝，不能用前缀完成判断。关闭诊断时仍返回具体 reason。

不读取配置正文、完整环境、认证数据；不执行认证、登录、模型或 OHOS 目标程序。
