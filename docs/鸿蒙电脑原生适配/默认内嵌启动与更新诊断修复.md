# 默认内嵌启动与更新诊断修复

本批解决只读审查发现的两项问题：鸿蒙首次启动仍依赖不支持的 daemon 包准备，以及 doctor 仍查询上游版本并推荐不兼容更新方式。改动基于终端工作分支 28a548691a051703db4c2c75ddd0441020b3b343，供主会话集成到当前适配分支。

## 行为与文件

| 文件 | 修复 |
| --- | --- |
| [功能默认值](../../codex-rs/features/src/lib.rs) | OHOS 的 daemon_auto_start 默认关闭，其他平台维持开启；保留配置字段与覆盖机制 |
| [daemon 启动选择](../../codex-rs/tui/src/daemon_startup.rs) | OHOS 排除隐式本地 daemon，避免默认启动探测并复用已有后台进程；--no-daemon 保留原优先级 |
| [平台策略](../../codex-rs/tui/src/daemon_startup/platform.rs) | 默认本机会话可继续使用内嵌 app-server；显式要求本地 agents 概览或启用 daemon_auto_start 时返回 Unsupported，并给出本地内嵌方式的操作提示 |
| [启动编排](../../codex-rs/tui/src/startup_orchestration.rs) | 打开终端前校验本地 agents 请求；解析最终配置后、自动启动 daemon 前检查显式启用请求 |
| [doctor 更新](../../codex-rs/cli/src/doctor/updates.rs) | OHOS 在安装来源识别、版本缓存读取和 HTTP 客户端创建之前返回 Warning：更新渠道不可用，上游版本探测已跳过；没有 npm/Linux 安装建议和“发现新版本”字段 |
| [功能测试](../../codex-rs/features/src/tests.rs)、[启动选择测试](../../codex-rs/tui/src/daemon_startup_tests.rs) | 补充实际功能默认值及 OHOS 隐式 daemon 排除测试；其他平台保留原回归 |

默认模式是本机内嵌 app-server，不引入 Linux 子系统、虚拟机或远程替代。已有显式远程选择沿用原行为，没有新增远程推荐或自动切换。用户显式 --no-daemon 优先于配置中的 daemon_auto_start=true；未使用该覆盖时，会提示关闭对应配置键。

没有修改根 Cargo 清单/锁文件、认证模块、提供方配置、CLI run_update_action 或 daemon 生命周期实现。主会话新增的手动/后台更新保护仍负责底层命令入口；本批修复其与 TUI 默认启动的衔接。
