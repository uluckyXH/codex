本次将 OHOS 的显式描述符清理改为失败即返回错误：close_range(CLOSE_RANGE_CLOEXEC) 失败后，必须完整完成 procfs 枚举与 fcntl 清理，才允许执行目标。打开或读取目录、读取或设置标记失败均返回原始 errno；异常目录记录返回 EIO。普通 Linux 保留原有尽力清理行为。

直接创建子进程与重新执行后的设置辅助入口都传递清理错误。已经进入显式 PTY 路径的 OHOS 请求在辅助入口不可用时继续走可报告错误的清理路径，包括空保留列表。标准流、明确保留的描述符及 exec 前的错误报告通道保持可用；清理只添加 CLOEXEC，不直接关闭通道。

## 测试选择与覆盖

本次修改进程创建和 OHOS 系统调用错误处理，因此选择相关宿主回归、OHOS 包检查、目标测试链接和 ELF 检查。没有重跑完整 CLI、认证、网络、TUI 或沙箱模块。

新增 7 项 Unix 宿主测试覆盖无序及重复的保留列表、标准流和清理区间；部分区间成功后的完整后备清理；后备 errno 原样返回；真实 Unix 描述符 CLOEXEC 标记及保留通道；异常目录记录 EIO；fcntl 严格与尽力清理模式；清理失败后父进程收到 EBADF 且目标未产生标记文件。

区间返回值与 Linux 目录记录是注入数据，不能当作 OHOS 系统调用结果。真实 fcntl 和父子错误通道只在 macOS 执行。

新增 OHOS 条件测试通过子进程 seccomp 同时拒绝 close_range 和 getdents64 或 fcntl，断言显式命令创建返回 EPERM 且目标未运行。本批只编译链接，并确认 ELF 内有该用例符号。普通 Linux 原有“清理失败仍允许启动”用例保留，但本批未在普通 Linux 运行。
