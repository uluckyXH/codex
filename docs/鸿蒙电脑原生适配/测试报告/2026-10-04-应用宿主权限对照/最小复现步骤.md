# 最小复现步骤

这里只复现公开域名和无密钥夹具。不要复制真实 `config.toml`，不要发模型请求。

## 准备工程

在 DevEco Studio 26.0.0 新建 Native C++ 的 2in1 项目，包名用 `com.codex.emulatorhost`，SDK26.0.0。保留模板的 `AppScope/resources/base/media/app_icon` 图标资源。

将 `source/common` 的文本工程文件覆盖到新项目，再选择一个版本覆盖：

- `source/native_child`：官方普通 `.so` 子进程测试，推荐先复现这个；不需要独立 ELF。
- `source/napi_host`：NAPI/系统 Shell/独立自签名 ELF 对照。额外准备下面的 `network-probe` rawfile。

这两个版本是独立测试入口，不要叠加源码。`source` 保存实测所用业务源码和配置；图标、编译器、缓存、签名文件和编译产物不入库。使用 IDE 完成项目同步，构建 `entry` 的 debug HAP。普通原型只声明 `INTERNET`；不要增加受限权限。

## 独立 ELF 对照的附加步骤

仅运行 `napi_host` 版本时需要。以下从仓库根目录执行；每次选新的输出目录。

```sh
# 指定 DevEco Studio 安装目录。
STUDIO="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents"
# 指定报告源码目录。
REPORT="$PWD/docs/鸿蒙电脑原生适配/测试报告/2026-10-04-应用宿主权限对照"
# 指定本次新建的忽略输出目录。
OUT="$PWD/.harmony-build/host-probe-repro"
# 创建本次探针构建目录。
mkdir -p "$OUT"
# 使用官方 SDK 编译普通 OHOS 可执行文件。
"$STUDIO/sdk/default/openharmony/native/llvm/bin/clang" --target=aarch64-linux-ohos --sysroot="$STUDIO/sdk/default/openharmony/native/sysroot" -O2 "$REPORT/source/network_probe.c" -o "$OUT/network-probe-unsigned"
# 使用仓库已有工具调用 SDK 官方自签名，不修改 ELF 格式。
python3 scripts/sign_harmony.py --sdk "$STUDIO/sdk/default/openharmony/native" --java "$STUDIO/jbr/Contents/Home/bin/java" --input "$OUT/network-probe-unsigned" --output "$OUT/network-probe" --record "$OUT/signature.json"
```

将新生成的 `network-probe` 作为原样资源复制到新项目 `entry/src/main/resources/rawfile/network-probe`，再构建。不要给它重命名为 `.so`，不要修改权限段或系统策略。不同工具版本或编译参数会产生不同摘要，应记录自己的 SHA256；报告中的摘要是当次实测值。

## 安装与读取

下面在新建的测试工程根目录执行。只针对指定模拟器和本测试包；unsigned 包仅用于本轮模拟器调试，不代表商业真机签名方式。

```sh
# 指定官方 HDC 工具。
HDC="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc"
# 安装刚构建的测试 HAP。
"$HDC" -t 127.0.0.1:5555 install entry/build/default/outputs/default/entry-default-unsigned.hap
# 停止本测试应用的旧进程。
"$HDC" -t 127.0.0.1:5555 shell aa force-stop com.codex.emulatorhost
# 启动本测试应用。
"$HDC" -t 127.0.0.1:5555 shell aa start -a EntryAbility -b com.codex.emulatorhost
# 读取父进程探针结果，不读取用户配置。
"$HDC" -t 127.0.0.1:5555 shell -b com.codex.emulatorhost 'cat ./data/storage/el2/base/haps/entry/files/host-probe.txt'
# 读取官方子进程结果，仅 native_child 版本会生成此文件。
"$HDC" -t 127.0.0.1:5555 shell -b com.codex.emulatorhost 'cat ./data/storage/el2/base/haps/entry/files/native-child-probe.txt'
```

原生网络探测有超时，完成后会出现 `native_child_complete=yes`；只看到启动返回0不能代替子进程结果。普通主进程版本检查 `probe_complete=yes`、`standalone_posix_spawn_result` 和 `spawn_exit`。

## 仅假配置的投递验证

`native_child` 第一次运行会创建应用自身0700目录；没有输入夹具时报告 `handoff_source_errno=2`，这是正常待投递状态。

```sh
# 在本机创建不含地址和密钥的固定测试夹具。
python3 - <<'PY'
from pathlib import Path
p = Path('handoff-probe.toml')
p.write_text('probe_only = true\nmodel = "gpt-5.6-terra"\n')
p.chmod(0o600)
PY
# 通过官方调试应用通道投递到应用已创建的0700目录。
"$HDC" -t 127.0.0.1:5555 file send -m -b com.codex.emulatorhost handoff-probe.toml ./data/storage/el2/base/haps/entry/files/handoff-private/incoming-probe.toml
# 停止本测试应用，以触发下一次导入验证。
"$HDC" -t 127.0.0.1:5555 shell aa force-stop com.codex.emulatorhost
# 重新运行本测试应用。
"$HDC" -t 127.0.0.1:5555 shell aa start -a EntryAbility -b com.codex.emulatorhost
# 读取原生fstat与匹配结果；不会输出夹具内容。
"$HDC" -t 127.0.0.1:5555 shell -b com.codex.emulatorhost 'cat ./data/storage/el2/base/haps/entry/files/native-child-probe.txt'
```

预期源文件0660，私有目录0700，最终文件0600，所有者均是应用UID。为了避免覆盖未知内容，探针使用 `O_EXCL`；重复导入时出现 `handoff_output_errno=17` 表示目标已存在。不要以这份仅接受固定假夹具的代码导入真实配置。
