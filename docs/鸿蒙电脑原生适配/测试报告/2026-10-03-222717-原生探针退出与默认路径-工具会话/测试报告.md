## 问题与实现

原汇总中三个目录 API 返回 `return_code=16000011`、`write_length=-1`、`status=context_not_exist`，最后记录 `native-dlclose`，随后信号 11。该标记只把问题定位在收尾阶段附近，没有 dlclose 返回后的标记，不能独断 dlclose 内是唯一根因。无应用上下文也不等于 files/cache/temp 路径不可访问。

一次性 Native worker 现在保留 dlopen 库引用，不主动 dlclose，包括符号缺失分支。查询返回后记录 `native-context-returned`，保留 API 原始码与无上下文状态；结果流已有写入错误、fflush 和 fclose 均检查并记录。结果流关闭后的 `worker-result-closed errno=N` 可与调用阶段区分。随后记录 `native-worker-_Exit code=N`、显式刷新关闭 stderr，再由该专用 worker 调用 `_Exit`；最终标记表示准备退出，不能替代 supervisor 的真实等待结果。其他 worker 与 supervisor 不改用该退出入口。

实际调用信号、超时及捕获上限保持原判断。结果写入/关闭或 stderr 失败不会报告采集成功；没有注册恢复信号处理器，也没有将崩溃改写为无上下文成功。库生命周期字段为 `library_lifetime=retained_until_worker_exit`。

默认观察在原有候选前加入编译契约 `CODEX_OHOS_RUNTIME_BASE` 下 `c{geteuid():08x}/a`、`/s`，与 Rust 目录命名一致。只使用实际 EUID，不依赖 id、shell 或同名环境变量，不创建目录。无宏时保留旧默认候选；最多 12 条显式路径仍完整替换默认项。非法基址或拼接后超长会记录原因，绝不提交截断路径给观察程序。

`path_selection` 记录选择方式、数量、上限和运行目录选择结果。`mountinfo.selection=covering_candidate_path`、`complete_mount_table=false` 明确是覆盖候选路径的筛选视图，原 `truncated` 只描述有上限的读取；即使未截断也不能据此声称拿到了完整挂载表。未增加 namespace 主动系统调用探针，未改 Rust 挂载策略。

危险 destructor 控制加载器真实执行 dlclose，并必须以 SIGSEGV 终止且输出钩子标记；危险 atexit 控制加载器走普通进程退出，必须以 SIGABRT 终止且输出标记。对应生产探针均采集成功，未输出危险标记，结果刷新/关闭和 `_Exit` 阶段按序出现。前者覆盖无上下文与缺符号分支，后者覆盖三次无上下文查询。这两个信号是预先约定的负向对照，不是把实际构建失败标成通过。

原调用信号 SIGSYS 保留为 `signal` 与原始等待状态，且其他路径继续采集；超时仍被判 incomplete、SIGKILL，未出现“调用已返回”的阶段。关闭结果 FD 的固定夹具产生写入/关闭错误和非零退出；关闭 stderr 的夹具亦为 incomplete；超量输出继续截断并失败。默认 EUID 路径的只读、宏缺失、环境覆盖无效、非法/超长基址、12 条显式覆盖均有实际断言。挂载表夹具明确是合成输入，验证筛选范围及 8 条上限，不是商业设备表重放。

原有 0711、2771、符号链接、打开前后 inode 变化、排他创建、文件/socket 往返与按对象身份清理回归继续通过。Mac 0711 用例仍是当前用户所有；不能作为 OHOS O_PATH 或跨用户 root-owned 0711 的实测。
