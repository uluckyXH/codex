## 改动与测试选择

鸿蒙 SDK 声明 `ioctl(int, int, ...)`，锁定的 libc 也使用对应类型；nix 0.28 原实现把 OHOS 当普通 Linux 选择 `c_ulong`。本次只为 OHOS 选择 `c_int`，由根 Cargo 清单引用带补丁的原发布源包。详见[第三方适配说明](../../../../third_party/rust/nix-0.28.0/鸿蒙适配说明.md)。没有升级所有依赖或修改 Cargo 注册表缓存。

验证选择交叉01和受影响的宿主01。单独检查没有调用宏的 nix 库不足以证明修复，因此对依赖 Starlark/rustyline 的 `codex-execpolicy` 做目标检查，并执行其 Mac 库回归。未运行登录或认证测试。

## 警告与剩余问题

本地路径形式的旧 nix 0.28 源包会显示原上游的自定义 cfg、弃用类型和生命周期等警告；OHOS 完整检查记录 580 条、Mac 回归记录 553 条。警告未被屏蔽，没有因此宣称全仓无警告；补丁没有额外改写这些上游代码。

交付时完整暂存差异检查返回 2，发现原 nix 发布源包已有的尾随空白与末尾空行。为保持上游文件逐字节可对照，保留这些原内容；本项目新增文件及 ioctl 修改文件单独检查，不把全源包空白检查写成通过。

完整检查的新错误来自 TUI 的 Linux D-Bus 依赖。另一会话正在为 OHOS 隔离该桌面后端；合入后建立新批次重新检查完整 CLI，不覆盖本失败报告。完整链接、SDK 动态依赖和商业设备行为仍需后续验证。
