# HDC 终端输入与窗口尺寸回归

日期：2026-10-04。执行会话：运行目录会话。设备：已连接的 HarmonyOS 7 PC 模拟器，目标 `127.0.0.1:5555`，普通 HDC Shell UID 2000。测试使用自签名 ARM64 原生探针，不涉及 API Key、登录或模型请求。

## 结论与修复

发现两个独立的终端兼容问题，并完成最小修复：

1. HDC 继承的标准输入通过 `isatty`，但修改其终端模式返回 `EACCES(13)`。在同一交互 Shell 重新打开 `/dev/tty` 后，现有 crossterm 默认后端可进入原始模式、读取按键并完整恢复模式。因此只修改模拟器 `start-codex.sh` 的输入重定向，不改 crossterm feature，也不修改通用 HiShell 入口。
2. HDC 交互终端的窗口查询成功却返回 `0×0`，会令 TUI 绘制空界面。Mac Expect 入口读取实际行列数并以 `LINES/COLUMNS` 数字前缀传入。新增 OHOS 尺寸策略，在任一原生维度为零时才采用提示；没有合法提示时使用 `80×24` 并每进程告警一次。

这些测试确认终端输入和尺寸策略，不代表完整模型对话、受限执行或文件工具已经通过。完整 Codex TUI、信任页面、恢复会话及最终包由主会话继续验收；网络 `EACCES` 属于另一条问题链。

## 对照证据

| 测试 | 结果 | 结论 |
| --- | --- | --- |
| C 探针：继承 stdin 的 `tcgetattr` | 成功 | 输入确实是终端 |
| C 探针：继承 stdin 的 `tcsetattr` | `EACCES(13)` | TTY 检测成功不保证可改变模式 |
| C 探针：新开 `/dev/tty` 的 `tcsetattr` | 原始模式与恢复均成功 | 可用当前控制终端的重新打开句柄 |
| Rust 默认 crossterm，继承 stdin | 退出 1，`enable_raw_mode` 返回 13 | 复现 Codex 启动问题 |
| Rust 改为 crossterm libc feature，继承 stdin | 同样返回 13 | 只切换后端不解决问题 |
| 默认 crossterm，重开 stdin | 三次进入和恢复均成功，退出 0 | 无需改变依赖 feature |
| libc feature，重开 stdin | 同样成功 | 修复关键在输入句柄 |
| C `poll/read` 输入及模式比较 | 收到 `K`，恢复后完全一致，退出 0 | 没有因重开而丢失输入或遗留原始模式 |
| Rust 默认 crossterm `poll/read` | 收到 `Key(Char('K'))`，恢复后完全一致，退出 0 | 实际事件库输入路径可用 |

C 探针直接调用 `TCGETS2` 返回 13，不能据此推断整个 rustix 后端不可用；上述完整 crossterm 对照证明默认后端在重开输入后正常。未修改 libc、rustix 或 crossterm 源码。

窗口尺寸对照：

| 条件 | Mac Expect slave | 设备 stdin / stdout / 新开 `/dev/tty` |
| --- | --- | --- |
| spawn 前设置 `stty_init` | `36×120` 行列 | 三个 FD 的 `TIOCGWINSZ` 均返回 `0×0` |
| spawn 后设置 slave 尺寸 | `36×120` 行列 | 三个 FD 同样返回 `0×0` |
| 向三个 FD 写回相同窗口尺寸 | 无改动 | `TIOCSWINSZ` 均返回 `EACCES(13)` |

因此不是仅靠调整 Expect 的初始化时序就可恢复远端尺寸。没有修改设备策略，也没有为设置窗口尺寸提升设备身份。

## 尺寸策略及接入位置

新策略文件：[terminal_size.rs](../../../../codex-rs/tui/src/terminal_size.rs)。行为如下：

- 非 OHOS 平台原样返回原生尺寸，包括原有的零值行为。
- OHOS 原生宽高均大于零时优先使用原生值，不受环境提示限制。
- 原生宽或高为零时，只有 `LINES/COLUMNS` 都为十进制正整数、各不超过 1000 且面积不超过 100000 才采用提示；缺失、空值、负数、非数字、溢出或过大时使用 `80×24`。
- 策略接入 `custom_terminal.rs` 的两个构造入口及 `size()`、`screen_size.rs` 的 Resize 分支，以及 history 的直接 crossterm 尺寸查询。
- 已检查后台尺寸监听：它只在 tmux 路线启用，且本来就过滤零尺寸，保持原实现。

Mac 入口只把验证后的数字加入 Shell 命令。模型仍固定为 `gpt-5.6-terra`，没有改沙箱权限或认证配置。当前 HDC 路线不承诺动态窗口调整；改变 Mac 窗口后退出并重新运行入口，获取新尺寸。

## 已完成验证

1. 独立编译生产 `terminal_size.rs` 的单元测试：**5/5 通过**。覆盖有效原生值优先、空尺寸恢复、两项提示必需、非法/超限/面积上界、非 OHOS 行为不变。
2. 签名 Rust 探针直接包含同一生产文件，在设备实际 `0×0` 终端上验证：提示 `120×36` 时得到 `120×36`；空提示时得到 `80×24`。两次默认 crossterm 输入事件、模式恢复、退出状态均通过。
3. Mac 真实 PTY 的假 HDC 对照：本地尺寸 `36×120`，远端命令确实带 `LINES=36 COLUMNS=120`；假远端退出 7，启动器也退出 7。
4. `start-codex.sh` 的 `sh -n` 和改动的 `git diff --check` 通过。

测试没有执行完整 Mac TUI 测试树，避免把独立策略测试等同于完整界面验收。完整交叉构建和设备 TUI 结果需引用主会话的最终报告。

## 可复现材料与边界

本目录保留英文文件名的 C/Rust/Expect 探针源码及 [探针输出](探针输出.txt)、[源码摘要](源码摘要.txt)。原始日志、签名 ELF、签名记录和离线构建缓存位于 Git 忽略的 `.harmony-build/terminal-backend-probe/`。探针使用与主工程相同的 crossterm 提交 `efa177859fd9623d57b9fe7ae9bf491ae1ac6ec4`，并确认 libc `0.2.186`、rustix `1.1.4` 与主工程对应依赖一致。

`terminal_probe.c` 保留初始 ioctl 对照；`terminal_io_probe.c` 使用初始化后的 termios 结构验证真正的模式恢复。首版比较曾因未初始化的结构尾字节出现假阴性，修正探针后两轮均恢复一致；不能把首版比较失败当作设备模式恢复故障。

```sh
# 在仓库根目录运行：仅编译并执行跨平台的纯尺寸策略单元测试。
rustc --edition 2024 --test codex-rs/tui/src/terminal_size.rs -o .harmony-build/terminal-size-tests
.harmony-build/terminal-size-tests
```

`Cargo.toml` 提供探针依赖与两种 Rust 入口；交叉链接、SDK 自签名和传入 HDC 的绝对路径沿用现有构建工具。两个 `run_*.exp` 是测试工具，只应传入可信的固定探针命令；它们不用于执行用户配置内容。C/Rust 探针部署后只对新探针文件设置 `0700`，不改变父目录、系统权限或设备安全配置。
