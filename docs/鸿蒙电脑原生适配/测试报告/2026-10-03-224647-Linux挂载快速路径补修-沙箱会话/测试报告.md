## 修复原因与最终行为

[初版报告](../2026-10-03-223259-挂载身份与定向诊断-沙箱会话/测试报告.md)记录了 statx 身份选择、SDK 依据及 61 项测试结果。主会话审查发现初版在普通 Linux 上无条件新增 statx 调用；旧路径在 fdinfo 有有效 ID 时不调用它，额外系统调用可能触发已有容器 seccomp 策略。忽略调用错误不能消除这项风险，故另行补修。

最终行为如下：

| 场景 | statx | 请求字段 | 命名空间采集 |
| --- | --- | --- | --- |
| OHOS | 必须调用 | BASIC_STATS 与普通 MNT_ID | 必须读取并核对前后相同 |
| 普通 Linux，诊断开启 | 调用以补齐证据 | BASIC_STATS 与普通 MNT_ID | 读取以供诊断 |
| 普通 Linux，诊断关闭，有有效 fdinfo ID | 不调用 | 不请求 | 不额外读取 |
| 普通 Linux，诊断关闭，fdinfo ID 不可用 | 沿用原回退调用 | 仅 MNT_ID | 不额外读取 |

statx 采样结果区分 `ok`、`error` 和内部未请求状态，不把未查询或失败字段当成零。OHOS 的字段有效位、同 FD metadata、fdinfo mount ID、命名空间和完整挂载表设备号关联规则未放宽。传统 Linux 的设备解码和 Btrfs 例外仍保留。挂载表有严格读取上限、明确截断拒绝以及解析/重复 ID/设备冲突/覆盖/别名/嵌套拒绝原因；格式与限制见[实施记录](../../挂载身份修复实施记录.md)。
