## 改动与验证选择

只在 OHOS 将 inspect_chain 的 `/` 和逐级 openat 改为 SDK 定义的 `O_PATH | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`。可信 root-owned 0711 祖先允许其他用户搜索但不允许读取目录项，O_RDONLY 会额外引入读取权限要求。owner、mode、链接与打开前后对象身份检查全部保留；没有失败回退。create-test 新建目录、文件等仍使用普通可用 FD。

选择整个短时探针宿主回归，因为默认路径、Native API 返回路径和显式创建检查都经过同一祖先函数；新增覆盖 0711 所有者元数据/子目录身份，以及 fstatat 后打开了替换对象时禁止创建。原策略夹具补充 root 0711 与当前 euid 0111 的模式判断。宿主 0711 用例属于当前用户所有，当前用户仍有读取权限，不是 root-owned 0711 的跨用户重现。

macOS 27.0.1 arm64、Python 3.14.7、Apple Clang 版本见提交后复核。OHOS SDK 6.1.1.125 / API 24、Clang 15.0.4、目标 `aarch64-linux-ohos`；C11、`-Wall -Wextra -Werror`、链接 `-ldl`。类型/IR 使用 O0，实际可执行文件使用 O2/PIE。无 Cargo feature 或锁文件变更，不适用 Rust 测试。
