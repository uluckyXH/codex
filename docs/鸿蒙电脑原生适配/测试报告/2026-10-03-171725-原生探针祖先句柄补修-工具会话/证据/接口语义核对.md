# 祖先句柄的接口语义核对

本表区分 Linux 接口约定、实际 OHOS SDK 编译证据与设备运行证据，不把它们合并成真机支持结论。

| 操作 | 代码用途与核对结果 | 证据边界 |
| --- | --- | --- |
| `open` / `openat` + `O_PATH` | 引用目录而不要求列目录读取权限，路径前缀仍需要搜索权限；保留 DIRECTORY、NOFOLLOW、CLOEXEC | SDK 定义和实际目标 IR 已验证；Mac 没有执行 OHOS O_PATH |
| `fstat` | 比较已打开对象的身份、目录类型、owner/mode | Linux 文档支持 O_PATH，实际 SDK 的函数声明和链接存在；OHOS 商业系统待实测 |
| `fstatat` / `readlinkat` | 相对已持有目录检查下一分量和读取链接目标，仍不跟随链接 | Linux 文档允许 O_PATH 作为 *at 的 dirfd；代码仍保留原有 no-follow 及身份检查 |
| `fstatfs` | 记录当前路径句柄所指文件系统 | Linux 文档支持该用法，SDK 编译链接通过；失败仍写 errno，不重开为 O_RDONLY |
| `mkdirat` / `unlinkat` / `openat` | 显式 create-test 相对父目录 FD 创建和清理自己的对象 | 父句柄仅定位，不授予额外创建/删除权限；系统拒绝继续如实报告 |
| 新建目录 FD、文件 FD | 新目录仍以 O_RDONLY 打开，文件仍 O_RDWR / O_EXCL；fchdir 绑定 socket 使用新目录的普通 FD | 实际 SDK IR 和宿主读写/绑定/清理回归验证，未改为 O_PATH |

Linux 语义依据：[Linux man-pages 项目 open(2) 的 O_PATH 与 openat 说明](https://man7.org/linux/man-pages/man2/open.2.html)。该文档列出 fstat、fstatfs、目录 FD 相对调用及它们的约束；属于 Linux 接口约定，不能单独证明商业鸿蒙实现或安全策略允许。

实际 SDK 为 DevEco 6.1.1.125 / API 24，`sysroot/usr/include/aarch64-linux-ohos/bits/fcntl.h` 定义 O_PATH，`fcntl.h`、`sys/stat.h`、`sys/statfs.h` 提供实际函数声明。没有手写平台结构体布局，也没有把 O_PATH 数值写死到产品代码。[目标打开方式](目标打开方式.json)中的数值由该 SDK 编译得出。

本轮没有放宽 root/当前 euid 所有者、祖先模式、符号链接、dev/ino 身份等判断；运行根批准仍恒为 false。O_PATH 不受支持或后续调用失败时保留错误，不改权限、不变更所有者、不回退到另一候选根或另一种权限判断。
