# 默认命令入口快照修复测试报告

日期：2026-10-04。执行环境：Mac ARM64、Rust 1.95.0。本报告记录源码修改及宿主定向回归；新的完整鸿蒙构建和设备验收由主会话另行记录。

## 问题与证据

主会话在同一个 HarmonyOS 7 应用会话中完成四格对照：默认 shell 和显式请求 `/bin/bash` 均为 `login=true` 退出 127、`login=false` 正常，失败输出均为 `sh: sh: inaccessible or not found`。后续检查确认实际解释器仍是 `/system/bin/sh`、MIRBSD KSH R59；不能把请求 `/bin/bash` 成功解释为设备上确实运行了 Bash。

当次会话已成功创建旧版 shell 快照，功能配置未启用 `shell_snapshot_v2`。旧版包装在外层恢复快照后会再 `exec sh -c …`。同一应用会话可以通过原生进程启动接口启动第一层 sh，但对 `/system/bin/sh` 执行跟随链接的 `stat` 返回 Permission denied；这与 mksh 在执行前查找可执行文件时失败相符。早期只有 `lstat` 失败的记录不足以证明 `stat` 也失败，本次已补齐两者的区分。

原始四格脱敏证据由主会话保存于 `.harmony-build/emulator-install/validation/shell-fix-20261004-start/rollout-matrix-redacted.jsonl`。本报告没有访问真实配置、密钥或设备，也没有发起模型请求。

## 修复范围

生产修改位于 `codex-rs/core/src/tools/runtimes/mod.rs`，仅在以下条件全部满足时复用已恢复快照的外层 shell：

1. 编译目标是 OHOS；平台参数在生产入口由 `cfg!(target_env = "ohos")` 决定。
2. 会话 shell 类型确实是 `ShellType::Sh`。
3. 命令入口路径与会话 shell 路径逐字相同。
4. 原有快照存在、参数长度和登录标志检查均通过。

复用分支保留尾部 argv，使 `$0`、`$1` 和 `$@` 仍从命令参数取得。快照载入、显式环境覆盖、运行时 PATH 前缀、代理变量、凭据替换及私有变量清理沿用原实现。没有修改 shell 发现、默认 `login`、审批或沙箱策略，也没有修改 V2 执行路径。

非 OHOS 和不同 shell 的执行方式保持原样。既有 brokered Bash/Zsh 复用条件保持原样。

语义差异需要明确：复用后，快照中非导出的函数、别名和 shell 选项会保留给原命令。旧实现中，后续 `exec` 会丢掉部分本地状态。本次实际执行测试包含函数、别名和 `set -e`，以确认快照恢复后的行为，而非宣称两种进程结构在所有 shell 状态下完全相同。

## 测试结果

定向 Rust 测试共 **13 项通过，0 项失败**：4 项新增回归和 9 项已有回归。完整输出见 [host-regression.log](host-regression.log)。

| 新增回归 | 验证结果 |
| --- | --- |
| 二次启动失败对照 | 临时测试 sh 第一次启动正常、第二次启动固定退出 127。旧分支真实复现失败；OHOS 同 Sh 分支执行原命令并返回 37。 |
| 环境与 argv | 快照变量、显式覆盖、运行时 PATH 前缀、代理及线程变量正确；空参数、空格、单引号、换行、`$0`、`$@` 保持；函数与别名可调用。 |
| shell 选项 | 快照 `set -e` 生效；原命令执行 `false` 后退出 1，后续命令未执行。 |
| 条件边界及凭据保护 | 不同路径/类型继续使用旧包装；没有快照、快照不存在、非 brokered `-c` 不改写。brokered Sh 的 `-lc` 与 `-c` 都保留 dummy、恢复 BASH_ENV、清除受保护 ENV 和私有副本；只读错误凭据导致执行关闭，原命令未运行。 |

已有 9 项覆盖 Bash/Zsh/Sh 包装、引用转义、尾部参数、brokered Zsh、显式环境优先级、快照 PATH 和显式 PATH 覆盖。新增测试位于 `codex-rs/core/src/tools/runtimes/mod_tests.rs`。

`git diff --check` 和工作区 `cargo fmt --all -- --check` 均通过。格式检查提示稳定版 rustfmt 不支持仓库的 `imports_granularity` 选项，但命令退出 0。

## 宿主测试方法与边界

此次没有运行完整 `cargo test -p codex-core`：已检查的外置盘宿主缓存中没有 codex-core 产物；完整依赖构建由主会话后续 OHOS 发布构建覆盖。

为直接验证修改代码，[snapshot_wrapper_harness.py](snapshot_wrapper_harness.py) 每次读取当前源码，原样提取生产包装函数、所有 shell 文本辅助函数、相关常量及这 13 项测试，再用 `rustc --test` 编译执行。没有另写包装算法。

该独立测试架具有以下依赖替代，不能混称为完整 crate 测试：

- `ShellType`、`Shell` 使用源码字段，省略 serde 派生。
- `AbsolutePathBuf` 以已经验证为绝对路径的 `PathBuf` 替代；测试文件由标准库建立在专用临时目录并清理。
- provider 注册表查询只用于本组不含 provider 凭据标记的样例：先断言标记不存在，再返回空集合。快照 dummy 的恢复、只读拒绝、ENV/BASH_ENV 清理仍运行真实生产函数。
- 断言使用 Rust 标准库，而非 `pretty_assertions`。

输入源码与生成测试架摘要见 [source_metadata.json](source_metadata.json)。所有测试产物和临时目录位于外置盘 `.harmony-build/snapshot-shell-reuse/`。
