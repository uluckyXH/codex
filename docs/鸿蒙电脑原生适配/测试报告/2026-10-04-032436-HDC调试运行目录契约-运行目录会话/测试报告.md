# HDC 调试运行目录契约测试报告

日期：2026 年 10 月 4 日。分支：`codex/harmony-native`。本次记录覆盖运行目录代理负责的修改；完整 CLI 集成和模型请求由主会话另行记录。

## 结论

显式 `hdc-debug` 调试契约已在运行中的鸿蒙 7 电脑模拟器通过运行目录测试。别名目录、控制目录、私有文件锁、目录身份重验、符号链接拒绝均已实际执行通过。

控制套接字的目录创建成功，但 **Unix pathname socket 的 bind 仍被系统以 EACCES（13）拒绝**。该项没有修复，也没有标为通过；代码保留拒绝。最小签名 C 探针进一步证明：`socketpair` 和 `socket(AF_UNIX)` 成功，失败发生于 `bind`。嵌入式 app-server 使用进程内 channel，因此这一独立传输能力失败不等同于 TUI 一定不能启动。TUI、模型请求、受限工具执行均须分别实测。

## 改动与信任边界

默认策略仍为 `strict`。只有构建时明确传入以下两个参数，才生成 HDC 调试包：

```sh
# 仅用于 HDC 的 UID 2000 调试部署，不能作为商业 PC 默认参数。
--runtime-profile hdc-debug --runtime-base /data/local/tmp/cdx
```

运行时不能用环境变量切换策略或改根。编译参数、签名记录和交付摘要都记录策略。调试策略仅接受 UID 2000 及固定目录链：

| 目录 | UID | GID | 权限要求 |
| --- | --- | --- | --- |
| `/data` | 1000 | 1000 | 精确 0771 |
| `/data/local` | 0 | 0 | 精确 0751 |
| `/data/local/tmp` | 2000 | 2000 | 精确 0771 |
| `/data/local/tmp/cdx` | 2000 | 无组访问权限 | 精确 0700，必须预先存在 |
| `c000007d0/a` 与 `c000007d0/s` | 2000 | 无组访问权限 | 精确 0700 |
| 私有锁文件 | 2000 | 无组访问权限 | 精确 0600、单硬链接 |

其余目录仍使用原校验。所有祖先以禁止跟随符号链接的 FD 打开并持有，操作前后核验 UID、GID、权限及对象身份；既有错误权限不会被自动修复。调试包信任系统的 `system` 身份及 `shell` 调试组中的系统服务，这些平台主体已能管理调试环境；它不宣称能够隔离其他拥有 HDC 调试能力的主体。

这项契约不授予任何系统权限，不改变模型命令的沙箱模式，不承诺受限执行能力，也不改变正式 PC 包的目录策略。

## 官方依据

OpenHarmony 初始化配置明确设置 `/data` 的 system 所有权和 0771 权限，同时建立 `/data/local` 和 `/data/local/tmp`。这与本模拟器的实测属性一致。[官方启动配置](https://github.com/openharmony/startup_init/blob/master/services/etc/init.cfg)

官方账户配置定义 system UID/GID 为 1000，shell 为 2000。[官方账户定义](https://github.com/openharmony/startup_init/blob/master/services/etc/passwd)

shell 组还包含平台诊断服务，因此不能把 shell 组可写解释成仅单个 CLI 进程可写；这也是仅提供显式调试契约的原因。[官方组定义](https://github.com/openharmony/startup_init/blob/master/services/etc/group)

## 测试结果

| 测试 | 结果 | 说明 |
| --- | --- | --- |
| Mac `codex-uds --lib` | 31/31 通过 | 包含原有目录替换、锁替换、符号链接、共享目录拒绝、并发、socket 生命周期回归 |
| Python 构建与打包测试 | 43/43 通过 | 显式策略传递、宿主环境变量不能覆盖、构建输入记录、默认策略保持 |
| Rustfmt 指定三个文件 | 通过 | 稳定 Rust 忽略 nightly 的 imports_granularity 配置并给出警告 |
| OHOS `codex-uds --lib --no-run` | 通过 | 初次发现测试监听器缺少 mut，修正后链接通过 |
| 模拟器运行目录测试 | 1/1 通过，remote_exit=0 | 完整目录链、a/s、锁、链接拒绝、FD 重验 |
| 模拟器控制 socket 生命周期 | 失败，remote_exit=101 | bind EACCES13，保留失败，不降级 |
| 最小签名 C 系统调用探针 | remote_exit=1 | socketpair 成功；socket 成功；bind EACCES13 |

宿主测试命令（工具输出摘要：31 passed，0 failed）：

```sh
# 在仓库根目录运行目录、锁及套接字宿主回归；使用已有 Rust 1.95.0。
rustup run 1.95.0 cargo test --manifest-path codex-rs/Cargo.toml --locked --offline -p codex-uds --lib

# 在 scripts 目录运行构建与打包回归；需要 Python 3.11 或更新版本。
python3 -m unittest test_build_harmony test_harmony_distribution
```

目标测试中的两个用例均默认 ignored，避免在未准备目录或非 HDC 进程中误执行；本次通过 `--ignored --exact` 单独执行，原始日志保存在本机报告目录但被 Git 忽略；[关键输出摘要](关键输出摘要.txt)随源码提交。目标签名程序的准确摘要以[测试程序签名记录](测试程序签名记录.json)中的“输出 / SHA-256”为准。
