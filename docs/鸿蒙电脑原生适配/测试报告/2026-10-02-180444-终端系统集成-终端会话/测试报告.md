## 测试选择

系统分支和更新行为发生改变，选择相关非认证宿主测试以及 OHOS 发布模式检查。updates.rs 使用 not(debug_assertions)，仅检查默认 debug 模式不能覆盖此入口。

完整 TUI 宿主测试的过滤器覆盖更新动作、剪贴板纯逻辑、粘贴路径和通知编码，但依赖准备失败。随后用隔离清单直接引用 update_action.rs 和 external_browser.rs，验证可独立检查的代码。没有复制或改写产品函数，没有伪造 OHOS 内置 cfg，没有模拟认证状态或启动 Codex CLI。

本批未新增系统外部符号。没有运行全仓测试、目标链接、目标测试程序、完整 CLI、签名或真机操作。

## 精确步骤与关键输出

逐项实际命令、开始/结束时间、退出码、错误与测试统计见[执行摘要](证据/执行摘要.txt)。每条命令由[执行用例脚本](证据/run_cases.py)设置上述工具链、并发、离线和独立临时目录后运行；日志不经会丢失原始退出码的管道。

主要完整包命令：

```sh
python3 scripts/build_harmony.py check --release \
  --sdk /Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native \
  --output-dir "<本批输出目录>/鸿蒙构建" --package codex-tui

rustup run 1.95.0 cargo test --manifest-path codex-rs/Cargo.toml \
  --locked --offline --target aarch64-apple-darwin --profile dev-small \
  -p codex-tui --lib -- \
  update_action::tests clipboard_copy::tests clipboard_paste::pasted_paths_tests \
  clipboard_paste::pasted_search_query_tests notifications::tests notifications::osc9::tests

rustup run 1.95.0 cargo tree --manifest-path codex-rs/Cargo.toml \
  --locked --offline --target aarch64-unknown-linux-ohos -p codex-tui -e normal,build
```

上面可读示例中的“本批输出目录”实际值已完整记录于执行摘要。隔离检查执行[isolation_policy_check.py](证据/isolation_policy_check.py)的 host 和 ohos 模式。脚本通过 Rust #[path] 引用产品文件，并使用真实 codex-install-context 和 codex-utils-absolute-path；OHOS 环境复用仓库 scripts/build_harmony.py。生成文件、独立锁文件的摘要见附件，均位于外置盘输出目录。
