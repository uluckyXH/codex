# 鸿蒙电脑原生适配测试报告目录

本目录专门保存测试报告和必要的脱敏证据，供不同 Codex 会话共同使用。执行前阅读[测试规范](../测试规范.md)，每批从[测试报告模板](测试报告模板.md)创建独立报告。成功、失败、阻塞和中断都要留档。

## 目录结构

```text
docs/鸿蒙电脑原生适配/
├── 测试规范.md
└── 测试报告/
    ├── 报告目录说明.md
    ├── 测试报告模板.md
    └── 年月日-时分秒-中文任务-会话短标识/
        ├── 测试报告.md
        └── 证据/
            ├── 环境摘要.txt
            ├── 执行摘要.txt
            └── 产物摘要.txt

.harmony-build/
├── current/target/               # 所有批次串行复用的一份编译缓存
└── 测试批次/同一批次名/
    ├── 日志/
    ├── 执行结果.tsv
    └── 临时目录/                # 测试结束后清理
```

目录树中的证据文件按需创建，不要求为没有产物的文档测试伪造“产物摘要”。批次名示意：`2026-10-02-173000-进程回归-会话甲`。时间统一使用 `Asia/Shanghai`（UTC+08:00）；报告同时注明开始和结束时刻。

## 保存与提交规则

- 报告使用中文文件名和正文；命令、代码标识和原始错误保留原文。
- 同一会话重测也要使用新批次目录，引用旧报告；不删除旧失败结果。
- 报告必须标明完整源码 SHA。若测试时有未提交改动，列出被测变更及摘要；只填写分支名不够。
- Markdown 报告与少量脱敏文本证据提交到 Git。`.harmony-build` 内的原始日志和产物不提交，也不使用 `git add -f` 绕过忽略规则上传它们。
- `.log` 已被仓库忽略。需要随报告共享的关键输出，整理为有来源说明的 `.txt` 摘要；不要只是改后缀把整份敏感日志提交。
- 摘要保留用例、命令、时间、退出码、数量和关键错误。删改内容标记为“已脱敏”或“已省略”，不得改变结论。
- 不提交 token、API Key、认证文件、签名私钥、完整环境转储或无关用户项目内容。
- 原始日志若需要长期共享，另行记录获准的附件位置、摘要及保留期限；本目录不自动对外上传附件。

多个会话各自新增报告和日志目录，集成时只追加自己的索引行，保留其他会话报告。构建统一排队，串行复用主仓库的一份缓存；不清理仍在使用的目录。已结束批次的编译缓存和重复解包可在报告留档后清理，规则见[构建缓存保留与清理](../构建缓存保留与清理.md)。历史报告中的本机构建路径仅记录当时位置，不代表二进制永久保留。
