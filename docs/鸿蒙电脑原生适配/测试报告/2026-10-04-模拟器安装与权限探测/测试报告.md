## 失败证据与判断

启动目录原始错误见 [启动目录错误](证据/启动目录错误.txt)，独立隔离原始错误见 [沙箱独立探测](证据/沙箱独立探测.txt)。证据摘录来自本轮实际工具返回，没有包含配置正文。

启动目录检查来自 `codex-rs/uds/src/ohos_runtime.rs` 的 `open_base` / `directory_mode_is_safe`，alias 入口在 `codex-rs/arg0/src/harmony_alias_dir.rs`。现有编译根为 `/data/storage/el2/base/files`。普通 hdc 视图不存在该路径，并在 `/data` 祖先校验处已经失败：其 owner 为 1000、mode 为 0771，与当前 UID 2000 的保护约定不符。

独立 bwrap 已绕过 Codex 的初始化流程测试，仍因系统拒绝读取 `/proc/sys/kernel/overflowuid` 而失败。源码位置为 `codex-rs/vendor/bubblewrap/bubblewrap.c` 的 `read_overflowids`。这是另一个阻塞点，不能用“新建可写目录”解释或修复，也不能据此推断 user namespace、seccomp 等后续步骤已得到验证。

本次没有删掉安全检查、放宽系统目录权限、关闭安全策略、切换 root 或自动设置完全权限。没有为暂不可用的目录重新编译候选包。

Context 探针原始 JSON 保存在 Git 忽略的 `.harmony-build/emulator-install/runtime-probe.json`。结果中的 `status=collected` 只表示成功采集观察，不表示内部 API 调用成功；三个目录接口在依赖库加载阶段失败，不能误记为已经得到有效应用目录或 API 明确返回了“上下文不存在”。
