## 尚不能宣称通过的能力

普通 HAP + private HNP 已证明原生 ELF 可以获得应用联网权限，但这不增加内核隔离能力。当前镜像的 bwrap 命名空间创建仍返回 `EINVAL`，Landlock 探测返回 `ENOSYS`；受限命令不能据此标为修复。默认模型调用和终端保持只读权限，未自动启用完全权限。

直接原生工具测试只证明程序在应用工作区内的功能，不等同于 Codex 受限执行后端通过。后续表格须保留这一差别。

用户配置、完整真实日志、安装二进制保留在忽略目录；Git 仅归档已脱敏证据、源码和文档。测试期间未修改系统 HOME、系统 SELinux 或其他应用权限。

事件流中仍有 V8 Code Mode 不可用、改用直接工具的已知提示。它没有阻止模型请求；本次问候并未调用文件或命令工具，因此不能用此结果证明受限工具已修复。

## 实际交互终端验收

通过 HDC `uitest` 操作模拟器内本应用，不操作 Mac 浏览器。第一次启动先出现上游的模型升级提示，明确选择 `Use existing model`，没有接受模型切换。随后实际 TUI 显示版本 `0.160.0-dev`，工作区为 `/data/storage/el2/base/files/workspace`。

输入 `/status` 后，界面报告 `GPT-5.6-Terra`、推理 `max`、供应商 `proxy`、权限 `Read Only (Ask for approval)`。本地状态查询的 token 计数为 0。应用的“停止终端”按钮结束子进程，前端显示会话结束、信号 `15`；信号退出时退出码为 `null`，没有误报为正常退出 0。

测试中有两项需要区分：

- 初始空白属于启动过渡，稍后真实 TUI 已正常绘制，没有为此放宽 PTY 权限。
- 模拟器中文输入法将 `/` 转成顿号，切到英文后 `/status` 正常。未将错误输入发送为模型请求。

截图保存在忽略目录 `.harmony-build/emulator-install/validation/`：`hnp-model-select.png`、`hnp-tui-status-final.png`、`hnp-tui-stopped.png`。交付时复制到发行目录，Git 只记录说明和摘要。
