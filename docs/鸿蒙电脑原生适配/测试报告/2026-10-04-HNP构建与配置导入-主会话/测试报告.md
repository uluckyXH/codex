构建入口新增显式 `hnp-debug`、固定短目录和绑定应用 UID。宿主环境变量不能偷偷选择 UID 或 HNP 工具入口摘要。HNP 入口先按 SDK 编译并自签名，再将摘要编入 CLI；四个小入口保留相同字节，打包核对与编译摘要一致。普通 `strict`、`hdc-debug` 构建不使用 HNP 入口。

配置导入先验证私有目录及输入的所有者、文件类型、大小和链接数；允许官方调试传输得到的 `0660` 文件仅位于 `0700` 接收目录内。输出使用独占临时文件、`0600`、`fsync` 和原子重命名，成功后删除接收文件。既有配置也必须通过所有者及 `0600` 检查。读取范围最多 64 KiB，不打印内容、地址或密钥。模型和 TOML 由可信 Mac 导入步骤验证，启动器再次固定 `gpt-5.6-terra`。

七项用例覆盖：无配置目录初始化、调试输入转私有配置并清理、更新的字节保持与原子替换、符号链接和硬链接拒绝、共享接收目录拒绝、公开可读/空/超长输入拒绝、危险权限的既有配置拒绝。只使用假值 `FAKE_TEST_KEY`。

## 执行方式

```sh
# 在仓库根目录运行构建及分发回归
PYTHONPATH=scripts python3 -m unittest scripts.test_build_harmony scripts.test_harmony_distribution

# 检查本批 Python 文件格式和静态规则
.harmony-build/工具/python/bin/ruff check scripts/build_harmony.py scripts/build_harmony_distribution.py scripts/test_build_harmony.py scripts/test_harmony_distribution.py

# 编译并运行假配置导入用例；该路径是本批实验工程
python3 .harmony-build/emulator-hnp/test_secure_config.py
```

## 失败与边界

一次测试命令把 Python 模块名末尾误加 `.py`，产生 unittest 加载错误；更正命令后 47 项通过。该加载错误不算运行了分发测试。

ELF 测试夹具只验证打包解析逻辑，不能替代真实 SDK 签名、HNP 安装与设备执行。`0700` 应用目录和联网权限也不能补齐 Codex 受限后端缺少的内核能力。没有自动改成完全权限。

## 模拟器私有导入

官方 HDC 调试传输与同一原生导入器的假配置设备测试通过后，主会话单独导入用户提供的配置。主机验证 TOML、HTTPS Responses、模型 `gpt-5.6-terra`、本地文件 `0600` 和 Git 忽略状态；地址及 Key 未打印。应用 UID/GID 为 `20020059`，导入器报告 `config_import_stage=complete result=2 errno=0`，并明确 `launch_complete=no_child config_status=2`。

最终位置为应用私有 `state/config.toml`；接收文件由导入器删除。实际值只保留在用户指定的本地私有配置和目标应用配置中。`private-import-result.json` 仅含脱敏的传输状态和原生阶段结果。本次没有启动 Codex，也没有发起付费模型请求。
