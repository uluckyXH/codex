## 已落地的改动

| 改动 | 原因与当前行为 | 对应工作 |
| --- | --- | --- |
| [交叉构建入口](../../scripts/build_harmony.py) | 从仓库读取 Rust 版本；校验 SDK；生成目标链接器与 C/C++ 包装器；配置 SDK CMake；隔离目标 pkg-config 搜索；将产物与临时文件放入外置盘仓库 | 适配04—05 |
| [最小 Rust 探针](../../scripts/harmony_probe.rs) | 只接受 ARM64 OHOS，验证标准库及 SDK 链接；未来真机输出启动信息、当前目录及自身路径 | 适配04、适配29 |
| [POSIX 创建分支](../../codex-rs/utils/pty/src/posix_child.rs) | 为 OHOS 补齐 `addchdir` 选择；动态查找工作目录扩展，缺少时保留原有兼容启动后端 | 适配06 |
| [凭据后端](../../codex-rs/keyring-store/src/unsupported.rs)及 [MCP 依赖](../../codex-rs/rmcp-client/Cargo.toml) | OHOS 不选 Linux Secret Service；没有已验证的原生安全存储时，读写删除明确返回 Unsupported，防止内存后端假报持久保存成功 | 适配15、适配20 |
| [HTTP 依赖](../../codex-rs/http-client/Cargo.toml) | 仅为 OHOS 启用 native-tls 的 vendored OpenSSL，使用锁定源码和目标 SDK，避免依赖构建机 OpenSSL | 适配05、适配16 |
| 中文设计与操作文档 | 覆盖源码清单、平台接口、沙箱、签名、安装配置、维护、验证和执行计划；补充外置盘环境配置 | 适配01、适配27—30 |

SDK 的 `spawn.h` 和 ARM64 `libc.so` 导出表均没有 `posix_spawn_file_actions_addchdir_np`。因此没有直接添加外部符号硬链接，也没有把 OHOS 伪装成 Rust 的 `musl` 目标。

所有平台差异均限定在目标条件或独立构建入口内。首批补丁没有关闭沙箱，也没有声称现有 Linux 权限后端能直接用于商业鸿蒙。

## 已复现的完整构建阻塞

当前依赖路径由目标 Cargo 依赖图确认：

```text
codex-cli → codex-execpolicy → starlark 0.14.2 → rustyline 14.0.0 → nix 0.28.0
```

`rustyline` 的 `src/tty/unix.rs:42` 使用 `nix::ioctl_read_bad!`。在当前 OHOS 目标与锁定 libc 组合中，宏传给 `libc::ioctl` 的 request 类型为 `u64`，接口需要 `i32`，编译报 `E0308`。

后续需比较已有上游修复和最小受控依赖补丁，保持窗口尺寸读取的 ABI。若使用 vendored 补丁，记录原版版本、完整来源、许可、改动和撤销条件；不能直接修改本机 Cargo 缓存，或通过关闭执行策略模块绕过问题。

前两次失败分别暴露了 SDK CMake 未进入构建环境，以及 OpenSSL 未选择目标源码构建的问题。这两项已修正，HTTP 模块的独立目标检查也已通过。

一次失败可能遮住更后面的错误。尚未完成 V8、bwrap/libcap、全部 TUI 系统集成、辅助程序和完整链接的验证，不能把 rustyline 写成唯一剩余工作。

## 复现命令

先完成[构建环境和外置盘配置](苹果电脑构建环境与外置盘配置.md)，在仓库根目录执行：

```sh
export OHOS_NDK_HOME="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native"
python3 -m unittest discover -s scripts -p test_build_harmony.py -v
python3 scripts/build_harmony.py probe
python3 scripts/build_harmony.py check \
  --package codex-keyring-store --package codex-utils-pty
python3 scripts/build_harmony.py check --package codex-http-client

# 完整检查目前预计在已登记的第三方依赖处失败。
python3 scripts/build_harmony.py check
```

本机诊断日志保存在被 Git 忽略的 `.harmony-build`，其中 `完整检查.log` 记录最后一轮完整目标检查，`网络模块检查.log` 和 `目标测试构建.log` 记录对应结果。日志不会代替本文的可复现步骤。

自测试规范建立后，各会话按[测试规范](测试规范.md)执行，并将每批结果写入[测试报告目录](测试报告/报告目录说明.md)。上面的首批结果属于历史汇总；新报告不会把它们算成本轮重新执行的测试。
