## 已解决的构建问题

1. SDK CMake 路径和 OpenSSL 目标源码构建已配置。
2. `codex-cli → codex-execpolicy → starlark → rustyline → nix 0.28` 的 ioctl 类型不匹配，通过最小 OHOS 补丁解决。
3. zbus 引入 nix 0.29 的目标套接字类型错误，通过排除不适用的 OHOS 桌面后端解决。
4. 完整链接暴露宿主 ranlib 把 OpenSSL 归档改成 96 字节空库；目标专用 llvm-ranlib 修复后，完整链接成功。
5. 发布模式检查暴露 core 异步类型布局查询深度达到 130；仅对 OHOS 提高编译上限为 256 后，完整 release 检查通过。前一失败见[集成报告](测试报告/2026-10-02-192224-最终源码集成验证-主会话/测试报告.md)。

这些实际失败各有报告。后一次通过只说明该次源码和环境，不抹去旧错误，也不证明未来 SDK 或上游版本一定兼容。

## 复现

使用[外置盘环境](苹果电脑构建环境与外置盘配置.md)，在仓库根目录配置 SDK 后执行：

```sh
export OHOS_NDK_HOME="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native"
python3 -m unittest discover -s scripts -p test_build_harmony.py -v
python3 scripts/build_harmony.py probe
python3 scripts/build_harmony.py check
python3 scripts/build_harmony.py build
```

正式留档时按[测试规范](测试规范.md)给本次执行设置独立 `--output-dir` 并记录日志；原始产物留在被忽略的 `.harmony-build`。这些命令不会签名或执行目标文件。完整工作范围以[源码清单](适配范围与源码清单.md)及[实施计划](实施计划与任务拆分.md)为准。
