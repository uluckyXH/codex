# 鸿蒙电脑七版故障修复计划

日期：2026-10-03（北京时间）。输入：[用户故障报告](../鸿蒙PC7_Codex安装与运行故障报告.md)。基线：`875b3a2d2d3b46ea062c960a66af68df8a70051a`，集成分支：`codex/harmony-native`。

目标：恢复商业鸿蒙 PC 7.0 原生受限执行、文件写入及完整编码流程，补齐默认 CA、临时目录与安装诊断，再交付新的签名候选包。三个会话并行实施；每项先定位、修复、测试，再回写进度和报告，最后由主会话集成验证。

## 现有证据与优先级

用户已确认包校验、安装、TUI 启动通过；指定 `/etc/ssl/certs/cacert.pem` 后第三方模型已实际回答。主要阻塞是工具退出 159、文件写入失败，以及独立沙箱构建的只读目录错误。CA 设置同时改变证书来源与 TLS 后端，不能只凭成功认定唯一原因；159 也尚未被原始信号状态证明为 SIGSYS。

固定 `/tmp` 的共享 daemon 目录与系统只读布局存在直接适配冲突。修复该目录之后，还要验证 helper 加载、namespace、mount、proc、seccomp 和策略允许的文件访问。legacy 模式明确拒绝不兼容策略，应保留保护并改为可解释错误，不能以关闭沙箱或自动授予全盘权限代替修复。

## 文件归属与协作方式

- 沙箱会话使用独立工作副本与 `codex/harmony-pc7-sandbox` 分支，负责 `codex-rs/uds`、`codex-rs/linux-sandbox`、必要的 `codex-rs/bwrap` 及 `sandboxing` 的 probe。不得改主会话的网络或打包文件。
- 工具会话使用独立工作副本与 `codex/harmony-pc7-tools` 分支，负责 `arg0`、`process-hardening`、`utils/pty`、工具执行诊断、`sandboxing/src/bwrap*`、CLI doctor/版本输出。涉及沙箱会话文件时先与主会话协调。
- 主会话负责 `http-client`、构建与安装打包脚本、`releases/`、速用文档和集成；不在其他会话的工作副本操作。不改用户 provider 或密钥，不执行登录或凭据读写测试。
- 两个工作副本从计划提交后的集成 HEAD 开始。各自产物、TMPDIR 和可变编译目录隔离在外置盘；下载缓存可共用，不共用可变 target。各会话提交自己的补丁，主会话检查后集成；仅主会话 push 集成分支。
- 每项测试记录精确提交或文件摘要、命令、环境、退出码与边界；失败与中断也保留。遵守[测试规范](测试规范.md)，测试报告统一保存在[测试报告目录](测试报告/报告目录说明.md)。

## 发布目录与关闭条件

仓库根目录的 `releases/` 已列入 `.gitignore`，只在本机保存二进制、归档、校验清单和随包文档；Git 继续管理源码、修复计划、报告及交付索引。Git 忽略不代表自动创建 GitHub Release，也不代表产物已上传。

本次新包位于 `releases/2026-10-03-鸿蒙PC七版修复候选/鸿蒙Codex安装`。使用独立版本身份和新目录，不覆盖旧包或用户配置。交付记录写明最终源码 SHA、SDK/target、helper 和 CLI 摘要、签名信息、检查结果及仍需用户验证的项。

关闭核心问题必须有同一新版在鸿蒙 PC 普通用户环境下的证据：独立受限执行、交互工具执行、文件写入与读取、最小编码闭环、禁止路径访问仍拒绝、daemon socket 仍隔离。当前开发机只有 Mac；可以完成宿主回归、目标检查、构建与签名，不能替代缺失的鸿蒙内核与系统权限验收。如平台拒绝必要内核能力，应明确报出，不静默改为无沙箱运行。
