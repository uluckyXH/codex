# 鸿蒙 PC 升级与专项日志速用

适用：已有账号/API 配置的鸿蒙 PC 7.0、ARM64、HiShell/zsh。新版显示 `0.160.0-dev`，不检查、不提醒、不安装官方更新；以后手动安装本项目的鸿蒙包。**文件写入失败和终端 159 尚未确认根因，本次需要采集新版的专项日志。**

## 1. 复制与升级

Mac 上把 `releases/2026-10-03-鸿蒙Codex-0.160.0开发候选/鸿蒙Codex安装` 整个文件夹复制到鸿蒙主目录，命名为 **`鸿蒙Codex更新-0.160.0`**。目录内应有一个完整压缩包、`安装包校验.sha256` 和本说明；不要混入旧压缩包。

先退出旧 Codex，再在终端复制：

```zsh
: '让 zsh 接受后续命令中的中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 在独立 Shell 中升级，任一步失败就停止；不会修改 API 或账号配置
(
set -eu
# 进入刚传来的新版资料目录
cd "$HOME/鸿蒙Codex更新-0.160.0"
# 校验压缩包，自动选择设备已有的校验工具
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 只接受一个候选包，避免误选旧包
set -- 鸿蒙Codex-*-未真机验证.tar.gz
[ "$#" -eq 1 ] && [ -f "$1" ]
# 建全新的解压目录，已有目录时停止，不覆盖旧内容
mkdir 更新解压
# 解压整个目录包，保留主程序、辅助程序与签名
tar -xzf "$1" -C 更新解压
# 安装到新版独立目录，保留旧安装及原账号/API 配置
sh 更新解压/鸿蒙Codex/安装.sh --prefix "$HOME/应用工具/鸿蒙Codex-0.160.0开发候选"
# 备份并更新 zsh 启动配置，让新终端使用新版
sh "$HOME/应用工具/鸿蒙Codex-0.160.0开发候选/启用终端.sh"
)
```

```sh
# 当前终端立即加载新版命令路径
. "$HOME/应用工具/鸿蒙Codex-0.160.0开发候选/环境.sh"
# 确认命令来自新版目录
command -v codex
# 确认显示 0.160.0-dev，以及 HarmonyOS 构建 SHA
codex --version
```

已有配置继续使用，不要重跑首次 API 配置或登录。若安装提示新版目标目录已存在，先停下核对；不要删除旧目录或覆盖它。

## 2. 先收集沙箱专项日志（不调用模型）

```sh
# 检查普通 pwd、受限 pwd、包内资源与真实退出状态；失败也会保留日志
sh "$HOME/应用工具/鸿蒙Codex-0.160.0开发候选/诊断.sh" --sandbox
```

最后一行会显示本次目录：`$HOME/Codex诊断/时间-进程号/`。提供这三份文件：

- `检查摘要.txt`：每项检查的退出码。
- `受限终端.txt`：新增的 `stage`、`raw_wait_status`、`signal`、`errno` 和沙箱错误。
- `构建与能力.txt`：确认实际使用的程序、版本及资源。

`159` 只是表面退出码；这些字段用来区分程序主动退出、信号终止、子进程加载及沙箱准备失败。无输出的字段不要自行补值。

## 3. 再收集文件写入与终端工具日志

下面的命令保留交互界面，只把 stderr 写到独立文件；按原来的服务配置调用模型。

```sh
# 创建只供本次排查使用的目录和日志路径
harmony_trace_dir="$HOME/Codex诊断/工具专项-$(date +%Y%m%d-%H%M%S)-$$"
# 日志目录只允许当前用户访问
mkdir -m 700 "$harmony_trace_dir" && \
    mkdir -m 700 "$harmony_trace_dir/空白项目" "$harmony_trace_dir/交互日志"
# 进入空白项目，不使用现有业务项目复现
cd "$harmony_trace_dir/空白项目"
# 开启本次进程的阶段诊断，将交互日志和 stderr 分开保存
CODEX_HARMONY_PROCESS_DIAGNOSTICS=1 \
RUST_LOG=warn,codex_exec_server::fs_sandbox=debug,codex_linux_sandbox=debug \
codex -c "log_dir=\"$harmony_trace_dir/交互日志\"" \
    2>"$harmony_trace_dir/进程专项.txt"
# 退出 Codex 后显示本次日志目录
printf '%s\n' "$harmony_trace_dir"
```

进入后依次发送：①“用终端工具执行 pwd”；②“用文件编辑工具创建 问候.txt，内容为 鸿蒙验证”。保留失败工具的**完整错误文字**，不要仅记录退出码。按正常受限权限运行，不开启全盘权限来绕过失败。

退出后，在同一个终端复制：

```sh
# 从进程与交互日志提取与当前故障相关的行；没有匹配时也保留空文件
grep -E 'codex-process|raw_wait_status|signal=|errno=|sandbox.*stage=|fs sandbox helper|bubblewrap|Permission denied|Read-only file system' \
    "$harmony_trace_dir/进程专项.txt" \
    "$harmony_trace_dir/交互日志/codex-tui.log" \
    > "$harmony_trace_dir/专项摘要.txt" || :
# 显示摘要，便于复制错误片段
cat "$harmony_trace_dir/专项摘要.txt"
```

发回第 2 步的三份文件、第 3 步的 `专项摘要.txt` 和失败工具的完整错误文字即可。分享前检查路径和内容；**不用发 API Key、`config.toml` 或 `auth.json`**。若摘要为空，请说明为空，不表示故障已经解决。
