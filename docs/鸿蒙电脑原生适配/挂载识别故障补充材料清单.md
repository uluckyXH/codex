在原来的 HiShell 复制执行下面整段。中文注释在独立 Shell 内执行，无需设置 zsh；只写入新的采集目录，不修改安装或账号配置。若安装位置不同，只改 `harmony_package` 一行。

```sh
: '采集当前环境的完整挂载表和版本；命令失败会写入文件，不依赖 id 或 Rust 工具链'
sh <<'HARMONY_COLLECT_EOF'
# 建目录失败时停止；新文件请求仅当前用户可读写
set -eu
umask 077
# 使用本轮实际安装位置，避免 PATH 命中旧 Codex

harmony_capture="$harmony_parent/挂载补充-$(date +%Y%m%d-%H%M%S)-$$"

harmony_pid=$$
printf '采集 Shell PID：%s\n安装目录：%s\n' "$harmony_pid" "$harmony_package" > "$harmony_capture/采集说明.txt"
# 每个命令分别保存 stdout、stderr 和退出码，缺少命令也留下原始错误
harmony_capture_one() {
    harmony_name=$1
    shift
    if "$@" > "$harmony_capture/$harmony_name.txt" 2> "$harmony_capture/$harmony_name-错误.txt"; then
        harmony_exit=0
    else
        harmony_exit=$?
    fi
    printf '%s：退出码 %s\n' "$harmony_name" "$harmony_exit" >> "$harmony_capture/采集摘要.txt"
}
# 记录采集时间、内核和架构；完整商业系统版本仍请在上表填写
```

## 3. 开发方需要补出的证据，旧包无法提供

测试方先完成前两节即可。仅设置 `RUST_LOG=debug`、重复运行旧包或读取其他进程的 `/proc`，不能补出旧代码没有记录的内部字段。开发方需准备带定向日志的签名诊断包；测试方收到后按随包命令执行一次即可。本轮尚未生成该诊断包。

| 诊断位置 | 新包必须记录什么 |
| --- | --- |
| 检查对象 | `aliases` 或 `control sockets`、实际路径、PID/EUID、挂载命名空间标识、构建 SHA |
| 同一个已打开目录 | Rust `metadata().dev()` 原值及十六进制、major/minor 结果、inode、UID/GID、权限；必要时对照 SDK C `fstat`，标明各数据来源 |
| 挂载身份来源 | 该 FD 的 `fdinfo.mnt_id`；`statx` 的请求字段、返回掩码、mount ID、设备主次编号；调用失败时保留 errno，不把不可用填成 0 |
| 文件系统和匹配条目 | `fstatfs` 类型及失败原因；Rust 进程完整 mountinfo；选中的 mount ID、parent ID、device、root、mount point、文件系统类型 |
| 具体拒绝分支 | 条目解析失败、ID 缺失／重复、设备号不一致、路径不属于该挂载、挂载覆盖关系、无法安全遮蔽的别名或嵌套挂载，逐类标记 |
| 探针退出流程 | 每个查询的 PID、API 返回码；卸载前后、结果收尾及退出前的细分阶段；父进程的 signal 和原始等待状态 |

必须记录同一目录 FD、同一 Rust 进程中的关联证据。挂载 ID 可能随重启、重新挂载或命名空间改变，不能把历史 `3996` 当作固定值。

我们需要确认的是：Rust 是否确实读到 `66699`，是否确实转成 `260:139`，以及是否正因与挂载表 `0:66699` 不同而拒绝。当前 SDK 的转换宏与 Rust 规则相同，不能预先认定替换转换函数就能解决。

探针方面要分清：`context_not_exist` 是 API 返回“无应用上下文”；SIGSEGV 是随后的异常终止。当前最后标记为 `native-dlclose`，尚不能精确断言崩溃就在 `dlclose` 内部。
