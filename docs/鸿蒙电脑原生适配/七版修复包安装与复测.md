# 七版修复包安装与复测

目标设备：商业鸿蒙 PC 7.0、ARM64、HiShell/zsh。修复源码和 Mac 测试已分别留档；新版的内核隔离与完整编码闭环仍待这台设备复测。[修复计划](鸿蒙电脑七版故障修复计划.md)记录各项状态，不能把“构建成功”当成“沙箱已通过”。

## 安装或升级

Mac 上将 `releases/2026-10-03-鸿蒙PC七版修复候选/鸿蒙Codex安装` 整个目录复制到鸿蒙的 `$HOME/鸿蒙Codex安装`，按[接口密钥安装速用](接口密钥安装速用.md)或[账号登录安装速用](账号登录安装速用.md)的第 1、2 步安装。不要只复制一个 codex 文件。

已有 `config.toml` 和账号/API 配置直接沿用，不必重跑首次配置。新安装目录是 `$HOME/应用工具/鸿蒙Codex-七版修复`；安装器不覆盖旧目录，终端配置器会备份 `.zshrc` 并更新自己管理的启动块。

## 先运行一次本机诊断

```zsh
: '允许在终端粘贴下面的中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 加载新版命令路径；不改变 HOME、TMPDIR 或账号配置
. "$HOME/应用工具/鸿蒙Codex-七版修复/环境.sh"
# 输出新包的源码身份，确认没有误用旧版本
codex --version
# 检查文件、资源、普通 pwd 和受限 pwd；不请求模型、不执行登录
sh "$HOME/应用工具/鸿蒙Codex-七版修复/诊断.sh" --sandbox
```

结果在终端最后输出的 `$HOME/Codex诊断/时间-进程号/` 中。失败时也会保留报告，重点提供 `检查摘要.txt`、`受限终端.txt`、`构建与能力.txt`。目录错误、签名/加载失败和信号状态会分别显示；不用发送 `config.toml`、`auth.json` 或 Key。

旧配置若启用了 `use_legacy_landlock`，受限模式会明确拒绝；在本机配置编辑器撤销这个实验开关，再用默认沙箱复测。不要把 `sandbox_mode` 改成全盘权限来掩盖故障。

## 再验证真实工具闭环

诊断中的受限终端通过后，在新建的空白测试项目中启动。模型会按现有服务配置处理测试请求，可能产生正常 API 费用。

```sh
# 新建独立测试目录，不触碰现有项目文件
mkdir -p "$HOME/Codex七版验证"
# 进入这个空白项目，后续只在这里验证文件操作
cd "$HOME/Codex七版验证"
# 启用阶段日志并启动；只对本次进程生效
CODEX_HARMONY_PROCESS_DIAGNOSTICS=1 codex
```

依次让 Codex 做下面三件事，并保存每步的工具结果：

1. 执行 `pwd`，应该得到当前测试目录，退出码为 0。
2. 用文件编辑工具创建 `问候.sh`，内容为 `printf '鸿蒙验证成功\n'`，再读取文件核对。
3. 执行 `sh 问候.sh`，应该输出“鸿蒙验证成功”，退出码为 0。

这三项通过只能证明允许操作的编码闭环；还需按[沙箱验收表](沙箱与权限适配.md)验证禁止访问的路径与 daemon socket 仍被隔离。若仍出现 159，请提供原始 `signal`、`raw_wait_status` 和最后一个 `stage`，不能仅凭 159 判定 SIGSYS 或 seccomp。

## 日志与回退

交互日志默认是 `${CODEX_HOME:-$HOME/.codex}/log/codex-tui.log`；自定义 `log_dir` 时以该设置为准。阶段输出也可能显示在终端 stderr。只摘录本次错误附近的内容，分享前检查路径、请求内容和服务地址，不附带认证文件。

```sh
# 撤销新版脚本管理的终端启动块；原配置备份与旧安装均保留
sh "$HOME/应用工具/鸿蒙Codex-七版修复/启用终端.sh" --remove
# 临时使用本次故障报告中的旧安装路径；有其他路径时按实际修改
. "$HOME/codex-hm/环境.sh"
```

回退仅用于对比；旧包的沙箱和 TLS 已知问题不会因此消失。`releases/` 是本机产物目录，源码、方案与测试报告仍由 Git 管理；本流程不会创建或上传 GitHub Release。
