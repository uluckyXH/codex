## 目录来源与安全约束

OHOS 首选编译期固定入口 `/storage/Users/currentUser`，其存在依据来自用户《鸿蒙PC7_Codex安装与运行故障报告.md》，注意 Users 大小写。先以 symlink_metadata 判断：入口存在时，规范化后的真实目录必须属于当前有效 UID，叶目录和原始/规范路径的祖先都接受权限检查；错误 UID、不安全权限、损坏链接直接失败，不能改走另一根目录。只有固定入口不存在时，才用 getpwuid_r(geteuid) 的账号 home，并执行同一完整校验。

原先只查账号数据库的方案经主会话复核后调整：公开 musl 的 [getpw_r.c](https://raw.githubusercontent.com/openharmony/third_party_musl/master/src/passwd/getpw_r.c) 与 [getpw_a.c](https://raw.githubusercontent.com/openharmony/third_party_musl/master/src/passwd/getpw_a.c) 可以证明接口及账号读取流程，不能证明商业 PC 的数据库一定存在或 home 一定有效。固定入口优先使已知 PC 路径不依赖 passwd 成功；入口安全失败仍明确拒绝，不从 HOME、TMPDIR、CODEX_HOME 或命令参数取回退路径。

最终选择规范路径下 `.codex-uds`。账号叶目录禁止组/其他用户写；祖先只允许 root 或当前 UID 所有，写权限例外仅限 root 所有的 sticky 目录。预留目录使用同一父描述符 mkdirat/openat，O_NOFOLLOW/O_DIRECTORY，核对 UID、严格 0700，以及路径与已开描述符的 dev/ino。已有不安全目录不自动 chmod，不删除已有 socket；并发及重复创建可复用。

保留完整 64 字符 SHA256 socket 名，按 sockaddr_un 的实际容量检查字节数和结尾 NUL；过长明确报错。监听器、shell snapshot 和沙箱都通过未改签名的 codex-uds 公共接口得到同一目录。Linux 的 mountinfo 别名枚举和每次 bind 后的重新屏蔽保留；新测试覆盖用户存储挂载别名及直接 socket bind 别名拒绝。

## 模式、helper 与阶段诊断

非法 legacy + 文件系统受限策略在启动 helper 或应用系统策略前退出 2，解释必须有 bubblewrap 隔离 app-server sockets。内层与 legacy 互斥参数也按同一受控错误处理。允许组合保持原行为，没有自动无沙箱回退。

包内 bwrap 仍校验已打开文件的 SHA256，再从同一描述符路径执行；没有商业 PC 签名拒绝 fd 路径的证据，故不把它改成重新按文件名打开。预检的实际 signal 字段和原始 wait status 来自 waitpid，不从退出值 159 猜测。PR_SET_NO_NEW_PRIVS/seccomp 的失败只增加上下文，seccomp 错误类型、过滤规则与拒绝策略不变。
