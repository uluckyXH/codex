## 实際验证与限制

具体命令、时间、退出码、源码摘要及隔离验证脚本见[本批测试报告](测试报告/2026-10-02-180444-终端系统集成-终端会话/测试报告.md)。

- 更新策略的 3 项宿主单元测试通过。隔离清单直接引用原始 `update_action.rs`，未复制或改写被测逻辑；测试检查安装方式映射、禁用平台下所有来源均不产生更新动作、其他平台安装命令保持原样。
- 直接引用 `update_action.rs` 和 `external_browser.rs` 的隔离 OHOS 发布模式 `cargo check --tests` 通过。它只证明这些模块及其目标测试的类型检查，不是完整 TUI 检查、目标链接或运行。
- 实际 OHOS TUI normal/build 依赖图不再包含 `arboard`、`zbus`、`nix 0.29.0`；仍保留 `rustyline 14.0.0 → nix 0.28.0` 的旧阻塞。
- 完整 TUI 发布模式目标检查失败于 `rustyline/src/tty/unix.rs:42`：OHOS `libc::ioctl` request 需要 `i32`，宏传入 `u64`。该依赖修复由主会话处理，本分支没有重复 vendor。
- 完整 TUI 宿主定向回归未进入测试执行：离线缓存缺少 `assert_matches 1.5.0`。因此剪贴板、通知和应用级 UI 回归没有被本次隔离策略测试替代。

## 上游同步注意

重新同步时复核 `target_os = "linux"` 与 `target_env = "ohos"` 的交集，尤其是新增 arboard、zbus、浏览器和更新调用。OHOS 在当前 Rust 目标中仍报告 `target_os="linux"`，只改变 UI 文案不能隔离依赖。若后来接入经验证的鸿蒙原生后端或发布渠道，应按对应模块替换当前降级，避免去掉一个提示后重新落入普通 Linux 安装路径。

公共实施进展和报告索引由主会话统一登记，本分支没有修改。
