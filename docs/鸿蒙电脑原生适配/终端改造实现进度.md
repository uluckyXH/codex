## 接口和目录约定

- 目录来源是本应用实际 ApplicationContext 的 `filesDir`；原生入口再次查询并比较来源，不由 UID 推导路径。应用专属数据在 `filesDir/codex/`。运行身份使用实际 EUID/EGID，不假设两者相等。
- 通用签名分发采用 `--runtime-profile platform`，不传 runtime-base/UID。宿主调用明确离线入口 `codex doctor --initialize-data-directories --json`，然后只创建 GUI 辅助目录；空白 Shell 不要求配置。初始化 stdout/stderr 各有16KiB上限，核对 JSON `paths.root` 与实际 Context 对应的 `filesDir/codex` 相等，失败保留退出状态及 stderr。尚未把独立 CLI 首次初始化列为通过。
- `prepare` 与终端启动严格拒绝可被 group/other 写入的应用祖先和非0700 files，不偷偷改权限。另提供显式 `secure-context` 宿主操作：再次查询本应用原生 Context，只允许收紧当前 files 及其直接、自有的 base；原始权限和每次改动须留在诊断记录。它不是独立 CLI 的权限能力，也不用于把新 UID 初始0777伪记为原生通过。此边界将由主会话审核并在模拟器实际验证。
- 主会话负责手工配置导入与导出脚本。宿主协议采用 `codex/host/control/action.txt`、`codex/host/handoff-private/incoming-config.toml`、`codex/host/launch-completion.txt`；诊断及 `codex-tui.log` 均放入 `codex/logs/`。
- 空白 Shell 不要求配置或 API Key。Shell/Codex 各自持有会话标识；输入、缩放、中断、退出及关闭必须匹配标识。
- 新增可切换 bundle 名构建参数，以同一份签名原生分发制作第二个宿主身份；签名 ELF 原样复用，不按 UID 重编。

主会话审查的 proc 边界已补修：`ReadIdentity`不再根据proc inode owner判断运行UID；改为O_PATH目录和实际status Uid元组，容纳dumpable=0使inode归root。`Observe`只排除status已证明其他身份且未被跟踪的不可读对象；已跟踪或身份不明的读取拒绝仍保留扫描未确认。每次增添成员前后重验直接子进程/session anchor，失去锚点时撤销本轮新句柄，避免数字SID重用后误收成员。设备若不允许必要status/stat读取，仍可能能力拒绝，须在真实Codex hardening后测试。
