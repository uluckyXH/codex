3. 目录来源不等于安全证明。所有祖先继续逐级 `openat`、`O_NOFOLLOW`、持有 FD 与 dev/ino 防替换验证；平台 files 叶要求当前 EUID 所有、0700，应用自有祖先不能 group/other writable。不会 chmod 已有 files、base、HOME 或项目；初始平台目录为 0777 时明确报能力缺口。宿主若有合法的自有目录收紧流程，应在交接中说明，该行为不由 CLI 暗中补做。

## 拟提供的 Rust API

`codex_uds::initialize_ohos_data_directories()`：在 OHOS 返回进程内共享的、持续持有验证 FD 的 `OhosDataDirectories`。提供 `files_dir()`、`root_dir()`、`state_dir()`、`runtime_dir()`、`temp_dir()`、`logs_dir()`、`identity()`、`source()` 和 `revalidate()`；启动失败不缓存，后续可在合法条件恢复后重试。正式签名、目录视图、MAC/ACL、独立 HiShell 和跨实际身份结果仍需设备验证。

`codex_utils_home_dir::default_log_dir(codex_home)`：通用默认日志选择；OHOS 默认 state 返回同根 logs，显式其他 CODEX_HOME 继续返回其 `log/`，非 OHOS 沿用原逻辑。

## 无认证初始化与实际路径接口

安装后若需主动初始化，使用精确命令 `codex doctor --initialize-data-directories --json`（可省略 `--json` 读人类输出）。不带 `-c`、`--capabilities`、远程参数或其他 doctor 检查项。OHOS arg0 先 hardening，再初始化；这条窄语法随后跳过 dotenv、config/auth、aliases，doctor 只输出初始化成功的真实目录。它不发模型请求、不读 config.toml/auth.json、不更改 cwd；显式 CODEX_HOME 不会改变内部根。安装器不能根据命令文字猜 root，必须先确认退出0，再解析 JSON。

成功 JSON 的稳定字段：`schemaVersion:1`、`status:"ok"`、`runtimeProfile:"platform"`、`source`（`native_application_context` / `validated_platform_namespace`）、`contextUnavailable`（可空）、`identity:{uid,euid,gid,egid}`、`paths:{files,root,state,runtime,aliases,controlSockets,tmp,logs}`。这些 paths 是默认目录；用户显式 CODEX_HOME/log_dir 的配置仍另行处理，命令不读取配置来推定覆盖结果。失败非零且 stderr 留下具体 stage/path/owner/mode；不会输出成功 JSON。该结果只确认目录初始化与保护检查，不能替代安装可执行性、alias、socket 或 HiShell 设备验收。

`--version`、`--help` 与 `doctor --capabilities` 继续只读、无需初始化。能力诊断会提示上述主动初始化命令，不能把它们的退出0作为 state 已创建的证明。

## 第二实际身份及全新目录边界

旧应用 base/files 已被 GUI 收紧到0700，所以旧 UID 的运行成功不能证明新安装可初始化。本轮 CLI 不推广旧 GUI 的 fchmod：新应用或 HiShell 的 files 为0777、祖先可被非可信身份写入、叶不属于当前EUID、链接跳转、链对象被替换或完整 socket 超长，均拒绝。即使 Context 返回路径和 UID 所有权正确，也不豁免共享写权限。第二真实 UID 必须使用同一 ELF、全新目录并记录调用前的祖先 mode/owner；若平台默认777导致拒绝，记录为安全拒绝及通用支持缺口，不能伪装通过。合法宿主自己的目录收紧必须由主会话独立确认来源与隔离证明，不能修改共享 HOME/HiShell 目录。
