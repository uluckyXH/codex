# 苹果电脑构建环境与外置盘配置

适用范围：在苹果电脑交叉编译，在商业鸿蒙 PC 上签名、运行并验收。运行已编译的 Codex 不需要在鸿蒙 PC 安装 Rust；开发用户自己的 Rust 项目时另行考虑。

本文记录当前构建机实际使用的外置盘路径 `/Volumes/MacSSD`。换电脑时替换为自己的挂载路径，不要照搬不存在的目录。编译期间保持磁盘挂载。

## 文件分别存在哪里

| 内容 | 环境变量或位置 | 本机路径 |
| --- | --- | --- |
| Rust 编译器、标准库、目标标准库 | `RUSTUP_HOME` | `/Volumes/MacSSD/dev/rust/rustup` |
| 下载的 crate、Git 依赖、Cargo 安装的工具 | `CARGO_HOME` | `/Volumes/MacSSD/dev/rust/cargo` |
| 普通 Cargo 编译产物 | `CARGO_TARGET_DIR` | `/Volumes/MacSSD/dev/rust/target` |
| Homebrew 下载缓存 | `HOMEBREW_CACHE` | `/Volumes/MacSSD/dev/cache/homebrew` |
| 本项目鸿蒙编译产物和临时文件 | 构建脚本 `--output-dir` | 仓库内 `.harmony-build`，仓库本身位于外置盘 |
| 当前原生 SDK | DevEco Studio 内置 SDK | `/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native` |

这些设置将主要的 Rust 文件放到外置盘，不会迁移 Homebrew 本身、Xcode 命令行工具或系统组件。少量 Homebrew 日志及 macOS 系统临时文件仍可能位于内置盘，不能承诺内置盘完全没有写入。

`CARGO_HOME` 也可能保存 Cargo 注册表凭据，不应把整个目录上传到仓库或共享给其他用户。[Cargo 目录说明](https://doc.rust-lang.org/cargo/guide/cargo-home.html)

## 第一次安装

Homebrew 的 `rustup` 包负责管理工具链；本仓库使用 [Rust 版本文件](../../codex-rs/rust-toolchain.toml)锁定的 **1.95.0**。使用 `brew install rustup`，后续由 rustup 选择版本。[Homebrew 官方说明](https://formulae.brew.sh/formula/rustup)

以下配置块只追加一次。先确认外置盘已挂载；若已有相同变量，修改已有配置，避免重复追加。

```sh
mkdir -p /Volumes/MacSSD/dev/rust/cargo \
  /Volumes/MacSSD/dev/rust/rustup \
  /Volumes/MacSSD/dev/rust/target \
  /Volumes/MacSSD/dev/rust/tmp \
  /Volumes/MacSSD/dev/cache/homebrew

cat >> ~/.zshrc <<'EOF'

# Rust 工具链、依赖和编译产物放在外置盘
export RUSTUP_HOME="/Volumes/MacSSD/dev/rust/rustup"
export CARGO_HOME="/Volumes/MacSSD/dev/rust/cargo"
export CARGO_TARGET_DIR="/Volumes/MacSSD/dev/rust/target"
export HOMEBREW_CACHE="/Volumes/MacSSD/dev/cache/homebrew"
export PATH="/opt/homebrew/opt/rustup/bin:$CARGO_HOME/bin:$PATH"
EOF

. ~/.zshrc
brew install rustup

TMPDIR="/Volumes/MacSSD/dev/rust/tmp" \
rustup toolchain install 1.95.0 --profile minimal \
  --component rustfmt --component clippy --component rust-src

rustup default 1.95.0
rustup target add --toolchain 1.95.0 aarch64-unknown-linux-ohos
```

上述 Homebrew 路径适用于当前 Apple Silicon 电脑。其他安装前缀用 `brew --prefix rustup` 确认，再把返回路径下的 `bin` 加入 PATH。新窗口加载 `.zshrc`；编辑器、后台任务或不读取 `.zshrc` 的 Shell 需要单独继承这些变量。

`RUSTUP_HOME` 控制工具链位置，`CARGO_HOME` 控制 Cargo 下载缓存。这两个变量必须在安装和后续使用时保持一致。[Rustup 环境变量](https://rust-lang.github.io/rustup/environment-variables.html)

## 确认安装位置

```sh
rustup show
rustup which rustc
rustc --version
cargo --version
rustup target list --installed
printf '%s\n' "$RUSTUP_HOME" "$CARGO_HOME" "$CARGO_TARGET_DIR"
```

本机已经实际确认：`rustup home` 位于外置盘，已安装 `1.95.0-aarch64-apple-darwin`，并具有 `aarch64-unknown-linux-ohos` 目标。

目标名包含 `linux`，但它是 Rust 的 OHOS 目标标识，不意味着使用 Linux 子系统。Rust 实际输出 `target_os="linux"`、`target_env="ohos"`；源码必须同时考虑这两个条件。

## 本仓库实际可用的构建入口

[构建脚本](../../scripts/build_harmony.py)只依赖 Python 3.11 以上的标准库，并从仓库版本文件读取 Rust 版本，避免上游升级时遗漏第二份版本号。它要求明确的 SDK，生成目标专用 C/C++ 包装器，复用 SDK 自带的 CMake，并把编译输出和临时目录放到 `.harmony-build`。此目录已由 Git 忽略。

```sh
cd /Volumes/MacSSD/Repositories/codex
export OHOS_NDK_HOME="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native"
# 后续构建统一复用这一份缓存，日志另按批次保存。
harmony_cache_root="$PWD/.harmony-build/current"

# 构建最小 Rust 探针，并输出 ELF 头、加载器及动态库信息。
python3 scripts/build_harmony.py probe --output-dir "$harmony_cache_root"

# 检查已开始适配的模块，不在 Mac 上运行鸿蒙程序。
python3 scripts/build_harmony.py check --output-dir "$harmony_cache_root" \
  --package codex-keyring-store --package codex-utils-pty

# 检查完整 CLI；本轮已通过，后续源码和 SDK 变化仍需复核。
python3 scripts/build_harmony.py check --output-dir "$harmony_cache_root"

# 开发构建，用于先验证完整链接；不能在 Mac 上执行目标文件。
python3 scripts/build_harmony.py build --output-dir "$harmony_cache_root"

# 发布配置另行构建和验证，不把开发构建当成发布结果。
python3 scripts/build_harmony.py build --release --output-dir "$harmony_cache_root"
```

可用 `--sdk` 替代环境变量，传入 `native`、`openharmony` 或包含 `openharmony/native` 的 SDK 版本目录。SDK 路径有空格时必须加引号。

需要把构建目录移到另一个外置盘目录时，给每次命令添加 `--output-dir /外置盘路径/鸿蒙构建`。该选项覆盖本次进程的 `CARGO_TARGET_DIR` 和 `TMPDIR`，不会修改全局 Shell 配置；下载依赖仍跟随 `CARGO_HOME`。

按上例指定 `--output-dir` 后，探针位于 `.harmony-build/current/harmony-rust-probe`，`build` 成功后的完整 CLI 位于 `.harmony-build/current/target/aarch64-unknown-linux-ohos/debug/codex`；`build --release` 成功后对应 `release/codex`。脚本省略该选项的默认输出仍是 `.harmony-build`，新批次统一使用上例固定目录。`check` 成功不会生成可分发的 CLI；任何 ELF 都还需要资源、签名及真机验收。

脚本不会安装工具链、签名、上传或尝试运行目标程序。商业鸿蒙 PC 的最低版本、加载器、签名接受条件和运行权限仍需真机确认。

## 编译缓存与清理

`CARGO_HOME` 是多个项目可共享的依赖缓存；`CARGO_TARGET_DIR` 是可重建的编译缓存。本项目只保留一份当前编译缓存，所有会话排队复用，不再给每批测试复制一套。报告、日志和交付包独立留档，具体见[构建缓存保留与清理](构建缓存保留与清理.md)。

空间不足时，先查看 `.harmony-build` 和 Cargo 编译目录大小，再决定清理哪个项目的产物。不要把删除整个 `CARGO_HOME` 当成清理编译产物：那里可能有安装的工具、配置和注册表凭据。

后续上游更新若修改 Rust 版本，先审查版本文件，再在同一个外置盘工具链目录安装对应版本；不通过跟随 Homebrew 的最新 `rust` 版本来替代仓库的固定版本。
