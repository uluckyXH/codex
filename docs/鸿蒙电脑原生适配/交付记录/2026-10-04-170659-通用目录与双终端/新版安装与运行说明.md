# 鸿蒙 PC 新版安装与运行说明

适用：ARM64 鸿蒙 PC 原生 HiShell。无需安装 Rust、SDK、Java 或测试 GUI。真机由用户验收；模拟器应用的成功不替代 HiShell 结果。

版本：`0.160.0-dev.harmony.g50046bef671c`。源码 SHA：`50046bef671cb6ca9312306f8c63aea4cfee172b`。目录策略：`platform`。这些字段由打包程序替换，release 中是实际构建值；仓库中的命令通过唯一压缩包选择本次版本。

## 1. 把这些文件带到鸿蒙 PC

从本次 `releases/日期-时间-说明/` 中取安装资料，将其中**一个** `鸿蒙Codex-*-未真机验证.tar.gz`、`安装包校验.sha256` 和三份安装文档放入鸿蒙的 `$HOME/鸿蒙Codex安装`。该目录不能混放多个旧压缩包。

压缩包已含签名后的 `codex`、`rg`、`bwrap`、独立探针及英文脚本。保留完整包，不只复制 `bin/codex`。配置文件和 Key 不在包内；按下面两种认证文档之一配置。

鸿蒙需有 `sh`、`zsh`、`tar`、基础文件命令及 `sha256sum` 或 `shasum`。按[华为说明](https://consumer.huawei.com/cn/support/content/zh-cn16079826/)开启外部来源扩展程序运行。安装前退出旧 Codex 会话；新版不自动搬运旧数据。

## 2. 安装并让终端找到 codex

```zsh
: '允许 zsh 粘贴执行下列中文注释'
setopt INTERACTIVE_COMMENTS
```

```sh
# 校验、解压、安装；任何一步失败就停止
(
set -eu
# 进入从 Mac 带来的本次安装资料
cd "$HOME/鸿蒙Codex安装"
# 先验证压缩包完整性
if command -v sha256sum >/dev/null 2>&1; then
    sha256sum -c 安装包校验.sha256
else
    shasum -a 256 -c 安装包校验.sha256
fi
# 只允许恰好一个候选包，避免误装旧版本
set -- 鸿蒙Codex-*-未真机验证.tar.gz
test "$#" -eq 1 && test -f "$1"
# 使用新目录，重复执行不会覆盖已有解压或安装文件
harmony_stamp=$(date +%Y%m%d-%H%M%S)
harmony_unpack="$PWD/unpack-$harmony_stamp"
harmony_install="$HOME/应用工具/codex-harmony-$harmony_stamp"
mkdir "$harmony_unpack"
# 保留完整签名程序与辅助工具的相对位置
tar -xzf "$1" -C "$harmony_unpack"
# 安装到程序目录；安装器不运行 Codex，不读写认证配置
sh "$harmony_unpack/鸿蒙Codex/install.sh" --prefix "$harmony_install"
# 备份并更新 zsh 的 Codex 启动块，后续新终端自动使用这一版
sh "$harmony_install/enable-terminal.sh"
)
```

**安装结束后新开一个 HiShell 标签页**，继续执行：

```sh
# 检查实际程序路径、主程序版本和包内 rg
command -v codex
codex --version
rg --version
# 由 CLI 自己创建并验证 codex/state、r、tmp、logs，不需要先开 GUI
codex doctor --initialize-data-directories
```

初始化输出 `state=…`、`runtime=…`、`tmp=…`、`logs=…`。正常应用命名空间的默认根是 `/data/storage/el2/base/files/codex`，实际以成功输出为准。**初始化报错时先执行第 5 步诊断**；不要手工改整个 HOME、`files` 或 `base` 的权限。

## 3. 配置认证（二选一）

- 接口 URL + Key：按[接口密钥安装速用](接口密钥安装速用.md)操作，无需账号登录。
- ChatGPT 账号：按[账号登录安装速用](账号登录安装速用.md)操作。

两种方式都保留 `gpt-5.6-terra`。需要沿用现有 `config.toml` 时，只手动复制到上一步 `state` 目录；显式设置了 `CODEX_HOME` 的用户继续使用该目录。没有旧数据迁移代码，不自动搬会话或数据库。

## 4. 在项目目录启动

```zsh
# 输入当前终端已经有权读写的项目绝对路径，包括桌面项目
read -r 'harmony_project?请输入项目的绝对路径：'
# 指定项目启动；不把项目搬入应用数据目录
codex --cd "$harmony_project" --model gpt-5.6-terra
```

`codex/workspace` 只是 GUI 的默认测试项目。原生 Git、Node.js、Python 等按项目需要另行准备。完全访问也受鸿蒙系统权限限制；受限执行还需设备提供相应隔离能力，不会静默降级。

## 5. 查看日志与排障

```sh
# 找到当前完整安装目录，用包内独立探针观察身份和目录；不读取 Key
harmony_program=$(command -v codex)
harmony_package=$(dirname "$(dirname "$harmony_program")")
sh "$harmony_package/diagnose.sh" --paths-only
```

```sh
# 采集版本、目录、文件校验及一次受限 pwd，结果目录由脚本打印
sh "$harmony_package/diagnose.sh" --sandbox
```

```sh
# 初始化成功时定位默认日志，读取最后 120 行；不输出配置正文
(
set -eu
harmony_paths=$(codex doctor --initialize-data-directories)
harmony_logs=$(printf '%s\n' "$harmony_paths" | sed -n 's/^logs=//p')
test -n "$harmony_logs"
tail -n 120 "$harmony_logs/codex-tui.log"
)
```

日志在实际启动 TUI 后产生。显式 `log_dir` 或其他 `CODEX_HOME` 的日志位置按对应配置处理。发送诊断目录和错误文本即可，不发送 `config.toml`、`auth.json` 或 Key。若尚未初始化成功，终端标准错误和独立探针结果就是本次证据。

## 6. 以后更新

退出旧版后，把新包放入新的安装资料目录，按第 2 步安装到新程序目录并更新终端启动块。新程序复用同一合法数据根；安装不会重签名二进制或覆盖已有配置。暂不使用上游普通 Linux/npm 更新包。
