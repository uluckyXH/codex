# 独立原生身份与目录探针

`codex-resources/harmony-runtime-probe` 是不依赖 Codex 启动的离线诊断程序，用于记录实际进程身份、目录和挂载证据。它不初始化 arg0、不读取 `.env`、配置正文或认证数据，不调用模型或外部网络，也不依赖系统提供 `id`、`stat`、`readlink` 等命令。

探针输出不能批准生产运行根。JSON 中 `runtime_root_approved` 始终为 `false`；Native API 返回路径、叶目录为 0700、文件读写或 socket 绑定成功，都不能单独证明商业鸿蒙 PC 的沙箱隔离成立。

## 命令接口

在解压后的包目录执行：

```sh
./codex-resources/harmony-runtime-probe --help
./codex-resources/harmony-runtime-probe --json
./codex-resources/harmony-runtime-probe --path /data/storage/el2/base/files
```

默认只读，输出单个 JSON 到标准输出，不先创建日志目录。`--json` 可以省略。可重复提供最多 12 个 `--path ABSOLUTE`，它们替代默认路径候选，但保留身份和 Native API 查询。路径必须为绝对路径、小于 1024 字节且不含 `.`、`..` 分量。

没有 `--path` 时收集有效的 `HOME`、`CODEX_HOME`、`TMPDIR` 路径；未设置 `CODEX_HOME` 时补充 `HOME/.codex`；另观察 `/storage/Users/currentUser`、`/data/storage/el2/base/{files,cache,temp}` 和 `/dev/shm`。这些只是诊断候选，不是回退顺序或受信任目录名单。只读取这三个环境变量的路径值，不转储环境。

明确需要验证新建对象时，可以在一个已有父目录下执行：

```sh
./codex-resources/harmony-runtime-probe --path /data/storage/el2/base/files \
  --create-test /data/storage/el2/base/files
```

`--create-test` 最多一次。先用持有的目录 FD 检查整条祖先链，拒绝符号链接、不受信任的所有者、可被组或其他用户写入的非 root sticky 祖先，以及根目录本身。满足该探针的 POSIX 前置检查后，才独占创建随机目录、0600 文件和本地 Unix socket，验证实际所有者、模式及文件读写。只有刚创建、dev/ino 与类型仍一致的对象才被清理；不递归清理未知内容，不修复、chmod 或 chown 任何已有目录。0700 叶目录不会掩盖不安全祖先。

超时、进程被信号终止或创建后无法确认对象身份时，可能留下测试对象；报告保留名称、已获得的输出和清理状态，不声称清理成功。

| 退出码 | 含义 |
| --- | --- |
| 0 | 已完成观察。路径不存在、被只读策略拒绝、Native 库/符号/上下文不可用仍可作为完整观察返回。不是安全运行根批准。 |
| 1 | 收集不完整、预算耗尽、子进程异常，或创建、验证、清理测试失败。 |
| 2 | 命令行无效，尚未开始探测。 |

## 证据与边界

身份包括真实/有效 UID、GID、附加组及 `/proc/self/status` 中限定的身份、NoNewPrivs、Seccomp 字段。路径证据包括每级不跟随链接的元数据、链接目标、规范化路径、文件系统信息、覆盖该路径的挂载记录和可获得的挂载 ID，不读取目录中文件正文。

Native 查询限定为 `OH_AbilityRuntime_ApplicationContextGetFilesDir`、`GetCacheDir`、`GetTempDir`。区分库不存在、符号缺失、`16000011` 上下文不存在、其他 API 错误和无效返回路径。查询在同一探针重新执行出的工作子进程中运行；即使系统声明了 API，该独立进程也可能没有 ApplicationContext，不能据此推断某个宿主应用的上下文状态。

身份、每个 Native API、每条候选路径和显式创建测试分别运行。父进程记录阶段、PID、超时、原始 wait 状态、退出码、信号和截断状态；一个失败不会阻止剩余预算内的其他检查。每项预算 1500 ms，整体调度预算 15 秒；每项 JSON 捕获最多 16 KiB、阶段/错误输出最多 2 KiB，全部工作结果最多 64 KiB。路径祖先最多 32 级，附加组最多 256 个，挂载表最多读取 1 MiB、匹配最多 8 条。不可中断的内核调用可能在 SIGKILL 后仍暂时存在；父进程只做有界回收并如实输出未知 wait 状态。

采集和试写通过不代表签名被设备接受、工具看不到控制 socket、模型调用成功或所有鸿蒙版本兼容。生产根由 `CODEX_OHOS_RUNTIME_BASE` 编译契约与统一运行目录模块决定，本探针不修改该契约。

## 构建与验证

生产入口为 `scripts/harmony_runtime_probe.c`，同时需要相邻的 `harmony_runtime_probe_context.h`。使用 OHOS SDK 的 C11 编译器、`-D__MUSL__` 和 `-ldl`，传入字符串宏 `CODEX_HARMONY_BUILD_ID`、`CODEX_HARMONY_VERSION`；未传入时记录 `unknown`。打包、签名和资源清单由主构建流程负责。原 `scripts/harmony_probe.rs` 启动 smoke probe 保持独立。

SDK 6.1.1.125 的 `application_context.h` 间接包含 C++ 引用参数，直接按 C11 引入会报错。探针使用 SDK `ability_runtime_common.h` 的返回枚举及三个目录查询共有的函数类型；`harmony_runtime_probe_sdk_check.cpp` 用 C++ 编译期断言核对所有三个 SDK 声明，不进入运行时产物。`stat`、`statfs`、socket 等结构均来自实际平台头文件，没有复制平台结构布局。

宿主固定夹具回归：

```sh
python3 -B scripts/test_harmony_runtime_probe.py
```

测试会编译宿主探针和模拟 Native 库，使用独立临时目录，并需要本地 AF_UNIX bind 权限。不会启动 Codex、执行认证测试或读取个人凭据。目标 C11 链接和 C++ 签名检查的完整命令保存在[最终验证报告](测试报告/2026-10-03-161126-独立原生目录探针最终验证-工具会话/测试报告.md)中；该报告同时保留前两类失败及复测关系。
