# 应用目录验证记录

日期：2026-10-04。对象：当前 DevEco 26.0.0 的鸿蒙 7 PC ARM64 模拟器。目的：验证普通应用的目录获取方式，并区分应用身份与 hdc 调试身份。

## 实际操作与结果

使用本机 DevEco 自带模板和 hvigor 构建最小 Stage 应用 `com.codex.emulatorhost`，安装后通过 `aa start` 启动 `EntryAbility`。应用只取得 Context 的三个目录，并在自己的文件目录写入路径观察；没有网络权限、模型请求或扩大执行权限的配置。

| 项目 | 观察 |
| --- | --- |
| 应用启动 | 成功；本机 hvigor assembleHap 成功，hdc install 和 aa start 成功 |
| 应用 UID | 20020058 |
| UIAbility Context.filesDir | `/data/storage/el2/base/haps/entry/files` |
| UIAbility Context.cacheDir | `/data/storage/el2/base/haps/entry/cache` |
| UIAbility Context.tempDir | `/data/storage/el2/base/haps/entry/temp` |
| 应用文件写入 | `context.json` 写入成功，内容为上面三个目录 |
| hdc shell -b | 切换到应用调试目录，仍为 UID 2000；没有切换成应用身份 |
| 调试视图下的文件目录 | `./data/storage/el2/base/haps/entry/files`，应用 UID 所有，模式 0770 |

这是 UIAbility 的 HAP 级 Context；不要把它误记为应用级 `/data/storage/el2/base/files`。`hdc shell -b` 下的路径要按其调试视图解释，普通 hdc Shell 不能直接用同一个应用绝对路径访问数据。

本轮原型位于 Git 忽略的 `.harmony-build/emulator-host/`，构建缓存位于 `.harmony-build/emulator-host-cache/`，未作为正式应用交付。没有修改系统挂载、SELinux、HOME 权限或应用权限清单以提升执行能力。

## 对 CLI 适配的结论

应用自身可以通过 Context 取得可写的私有存储，不能据此推断独立 CLI 从 hdc 或 HiShell 启动时也具有同一视图、身份和目录权限。把二进制放进一个路径，不会自动获得应用上下文。

本轮继续使用显式 `hdc-debug` 构建验证 CLI。真正的应用宿主仍需要单独设计执行身份、文件授权、原生进程及 IPC。最小应用没有证明它能执行完整 Codex，也不能弥补模拟器内核未提供的用户命名空间能力。
