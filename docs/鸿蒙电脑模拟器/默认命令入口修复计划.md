# 默认命令入口修复计划

日期：2026-10-04。问题：应用内 Codex 执行默认命令时报 `sh: sh: inaccessible or not found`，模型改用 `login=false` 后可以运行 `pwd` 和 `rg`。

## 已确认的事实

- 被测设备：HarmonyOS 7.0.0.105、2in1、aarch64 模拟器；应用 UID 为 `20020059`。
- 被测旧版本：`0.160.0-dev.harmony.g8c4b3a6f48ef`。
- 当前用户会话已选择 Full Access；同一身份可以创建 HTML 文件并使用包内 `rg` 搜索。提升为管理员不是本次修复方案。
- 同一会话的四组 `pwd` 对照结果：默认 Shell / `login=true` 返回 127；默认 Shell / `login=false` 返回 0；指定 `/bin/bash` 的结果也分别为 127 和 0。
- 有效配置未覆盖 `features`；启动日志记录旧版 Shell 快照创建成功，快照文件存在。
- 源码对模型提供的 `/bin/bash` 先提取 Shell 类型、重新探测，失败可回退到 `sh`。因此不能从工具请求字段断言设备安装了 Bash。
- 同一会话的只读身份检查返回 `argv0=sh`、`BASH_VERSION` 未设置、`KSH_VERSION=@(#)MIRBSD KSH R59 2020/10/31`；`/proc/$$/exe` 指向 `/system/bin/sh`。跟随链接的 `stat -L /system/bin/sh` 返回 `Permission denied`。

## 定位与修复方向

旧版快照包装在恢复环境后再次执行 `exec 'sh' -c ...`。鸿蒙应用身份下，直接原生启动 Shell 与 Shell 内部先检查文件再启动程序的行为存在差异。[OpenHarmony mksh 源码](https://github.com/openharmony/third_party_mksh/blob/master/exec.c) 中，`search_access` 会把 `stat` 失败映射为找不到程序；错误 127 不能单独证明程序不存在。

修复候选：仅在 OHOS、会话 Shell 为 `Sh`、目标路径与会话路径完全相同时，在已启动的 Shell 中恢复快照并执行原命令，去掉不必要的第二次 Shell 启动。保持登录参数、快照、环境覆盖、位置参数和退出码语义。其他平台、不同 Shell 路径、V2 快照以及权限和沙箱策略保持原有规则。

以实际源码回归和设备复测为验收依据；若差分测试不支持该原因，停止这一候选并重新定位，不将规避失败写成修复成功。
