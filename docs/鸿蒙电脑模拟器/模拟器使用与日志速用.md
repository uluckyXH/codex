# HDC 独立包使用与日志速用（历史入口）

当前可联网的原生版本使用 [HNP 应用宿主入口](HNP应用宿主调试速用.md)，已收到真实模型回复。本文保留 HDC 独立部署的日志路径与失败复现方法，不能用于新应用的数据目录。

适用：已部署的鸿蒙 7 ARM64 PC 模拟器，HDC shell UID 2000。这是独立 `hdc-debug` 构建，不能用它覆盖真机 HiShell 版本。最终结果见本次发布目录的测试报告；本说明不代表受限执行已经通过。

**当前限制：HDC 身份下的实际模型请求在 TCP 连接阶段返回 `PermissionDenied (13)`；本包尚未通过正常对话和受限工具验收。** 运行目录已打通，终端入口已加入 HDC 输入与窗口尺寸适配。此调试包用于复现和继续适配。

## 打开 Codex

保持模拟器运行，在 Mac 终端执行：

```bash
# 连接正在运行的模拟器，并打开设备内的 Codex 交互界面。
bash "/Volumes/MacSSD/Repositories/codex/docs/鸿蒙电脑模拟器/run-harmony-codex.sh"
```

也可以双击同目录的 `run-harmony-codex.command`。发布包中的 `emulator-tools` 含相同入口，四个脚本一起保留。它们只连接模拟器；首次安装和配置另行完成。

入口固定模型 `gpt-5.6-terra`。HDC 终端若只报告 `0×0`，鸿蒙 TUI 使用入口传入的合法窗口行列数；没有合法提示时使用 `80×24`。这台模拟器无法写入内核终端尺寸，调整 Mac 窗口后请退出并重新运行入口，以重新获取尺寸。配置文件、项目和日志均在模拟器内，关闭 Mac 终端不会将它们复制回 Mac。退出 Codex 后会返回 Mac 终端。

## 查看日志

```bash
# 为当前 Mac 终端添加 DevEco 自带 hdc 的位置。
export PATH="/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains:$PATH"
# 查看设备内 Codex 最后 100 行界面日志。
hdc -t 127.0.0.1:5555 shell 'tail -n 100 /data/local/tmp/codex-emulator/logs/codex-tui.log'
# 将界面日志复制到当前 Mac 目录；分享前检查并去除接口地址和其他敏感信息。
hdc -t 127.0.0.1:5555 file recv /data/local/tmp/codex-emulator/logs/codex-tui.log ./harmony-codex-tui.log
```

`codex exec` 的错误和 JSON 事件输出到当前终端；没有启动 TUI 时可能还没有 `codex-tui.log`。由单条 `hdc shell COMMAND` 运行无需输入的 `codex exec` 时，应在远端命令末尾加 `</dev/null`，以免等候标准输入结束。

不要发送 `state/config.toml`、认证文件或完整会话目录；它们可能包含密钥或任务内容。

## 目录对应

| 用途 | 模拟器内位置 |
| --- | --- |
| 完整版本包 | `/data/local/tmp/codex-emulator/packages/` |
| 当前版本目录名 | `/data/local/tmp/codex-emulator/active-package` |
| 用户配置 | `/data/local/tmp/codex-emulator/state/config.toml` |
| 项目工作区 | `/data/local/tmp/codex-emulator/workspace` |
| 日志 | `/data/local/tmp/codex-emulator/logs` |
| 受保护的别名与控制目录 | `/data/local/tmp/cdx` |

`start-codex.sh` 是设备端脚本，复制到 `/data/local/tmp/codex-emulator/start-codex.sh` 后由 Mac 入口调用。`HOME`、`CODEX_HOME`、`TMPDIR` 分别使用专用的 `home`、`state`、`tmp`；不会修改整个系统 HOME 的权限。

受限模式与完全权限是不同的运行方式。当前模拟器独立探针已确认用户命名空间不可用，bwrap 不能建立所需隔离；创建可写目录不会改变这一结果。入口不自动更改沙箱模式。完全权限也仍受鸿蒙当前进程的系统权限约束。
