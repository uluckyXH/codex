# 鸿蒙 7 模拟器调试包交付说明

本包已在当前 `HarmonyOS 7.0.0.105 / 2in1 / aarch64` 模拟器验证。Codex 版本 `0.160.0-dev.harmony.g8c4b3a6f48ef`，Rust 源码 `8c4b3a6f48efa9eb4642d75929de8ba5ebdc6e84`。

## 现在可以做什么

- 在“Codex 鸿蒙原生终端”应用里启动 CLI，输入任务并收到 `gpt-5.6-terra` 回复。
- 查看 `/status`、正常 `/quit`、停止和重新启动会话。
- 导出本地脱敏日志。真实 Key 和接口地址没有打进安装包。

直接原生测试中的文件创建、修改、读取、搜索、删除共 8 项已通过。**Codex 受限命令仍不可用**：当前内核缺少 bubblewrap 所需的用户命名空间，Landlock 也不可用。应用不会自动切到完全权限，因此不能宣称模型操作文件和命令的受限闭环已经完成。

## 当前这台模拟器怎么安装或更新

已经替你安装并导入现有配置；平时只需打开应用。以下命令均在 Mac 执行：

```bash
# 进入已交付的目录；若移动或解压到其他位置，请改为那个目录。
cd "/Volumes/MacSSD/Repositories/codex/releases/2026-10-04-063742-鸿蒙Codex-HNP应用调试"
# 校验 HAP，只有成功才覆盖安装；不要先卸载已有应用。
shasum -a 256 -c codex-harmony-terminal-debug.hap.sha256 && \
"/Volumes/MacSSD/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc" -t 127.0.0.1:5555 install codex-harmony-terminal-debug.hap
# 打开应用，不打断已运行的交互会话。
python3 ./manage-harmony-app.py open
```

应用内点“启动 Codex”。模型固定 `gpt-5.6-terra`，初始权限只读。模型升级提示选择 `Use existing model`；输入斜杠命令前使用英文输入法。应用上方“停止终端”结束会话，终端内 `/quit` 正常退出。

## 修改配置与取日志

保留 Mac 上原有 `docs/鸿蒙电脑模拟器/config.toml`。只有修改过配置才需要重新导入；导入会重启本调试应用：

```bash
# 确保本地密钥配置文件仅自己可读写。
chmod 600 "/Volumes/MacSSD/Repositories/codex/docs/鸿蒙电脑模拟器/config.toml"
# 独立导入配置，不打印 URL 或 Key，不更换模型。
python3 ./manage-harmony-app.py import-config --config "/Volumes/MacSSD/Repositories/codex/docs/鸿蒙电脑模拟器/config.toml"
# 收集启动后的 TUI 日志，自动遮蔽当前配置中的 Key、URL 和域名。
python3 ./manage-harmony-app.py collect-logs --config "/Volumes/MacSSD/Repositories/codex/docs/鸿蒙电脑模拟器/config.toml" --output "./终端日志-$(date +%Y%m%d-%H%M%S)"
```

应用配置位于 `/data/storage/el2/base/files/state/config.toml`，TUI 日志位于该 `state` 下的 `log/codex-tui.log`，均已验证为 0600。日志可能包含任务文本，分享前需再检查。

| 文件 | 用途 |

| `codex-harmony-terminal-debug.hap` 及 `.sha256` | 当前模拟器的完整应用安装包，含原生 Codex 和终端界面 |
| `manage-harmony-app.py` | Mac 端打开、配置导入、状态和脱敏日志工具 |

| 原生文件 `.tar.gz` 及 `安装包校验.sha256` | 已自签名 ELF 的原始构建交付；不能代替上述 HAP 安装步骤 |

HAP SHA256：`bad4428c9931df803f2bfeb73b885e12a125c41747357f5850d876c7e39f263b`。HAP 外壳版本 `0.1.0`，与原生 Codex 版本分别记录。

包内 ELF 保留 SDK 二进制自签名；HAP 是当前模拟器接受的**未签名调试包**，尚非商业 PC 的正式证书签名包。它绑定当前专用应用 UID `20020059`；新模拟器、卸载重装或实体 PC 均需重新核验部署身份，不能直接当作通用安装包。测试未修改系统 HOME、SELinux 或其他应用权限。

源代码、中文文档及脱敏测试证据纳入 Git；`releases/`、构建目录、密钥配置和安装二进制不纳入 Git。
