## 实施约束

- 不关闭系统安全策略，不用全局改权限或 root 冒充普通用户适配。
- 不静默把受限模式改成完全权限。如果设备缺少必要隔离能力，报告事实并评估经过验证的替代后端；未验证的能力不标记通过。
- 应用系统沙箱、Codex 的命令沙箱、普通文件权限分别验证。
- 模拟器调试身份与真实 PC HiShell 分别记录，不把模拟器成功写成真机全部兼容。
- 代码文件用英文名；文档用中文名。配置、密钥、二进制和临时构建文件不提交。
- 每项修复后执行对应测试并回写本表；失败记录保留。

## 目录方案与隔离边界

`hdc-debug` 是编译时显式选择的调试部署策略，默认 `strict` 不变。它只接受已核对的 `/data`、`/data/local`、`/data/local/tmp` 的固定身份和权限，以及当前 UID 2000 所有的 `0700` 私有运行根。该部署信任系统身份和 shell 调试组内的系统服务；不把任意组可写目录都认定为安全，不把路径配置交给环境变量覆盖。

独立签名探针确认当前模拟器的用户命名空间调用返回 `EINVAL`，对应 `/proc/self/ns/user`、UID/GID 映射接口不存在；Landlock ABI 查询返回 `ENOSYS`。seccomp 过滤可用，但它单独不能替代文件路径隔离。修复后的 bwrap 在建立隔离阶段安全退出，测试命令未被执行。

因此，运行目录修复可以解除 CLI 初始化阻塞，但不能承诺恢复这个内核上缺失的隔离能力。完全权限执行需要用户明确选择；不能自动作为受限执行失败的回退。报告会分别记录对话、普通原生进程与 Codex 受限工具的结果。
